# 第 7 章　共議

> *築基初期・第七重「共議」*

第二百天，西北送來一個案子：涼州軍糧霉變，三千石軍糧在入倉三個月後發黑，邊軍差點斷糧。

案子同樣跨司。這次尹知行輕車熟路：謀篇官拆案、畫圖、並行 ── 三個探子，二十天全部查完。

然後他在合卷的時候，傻了。

三份回報，**三個結論**：

```
兵部探子：糧入倉時已有黴根。是「糧的問題」── 採買收了陳糧。
戶部探子：採買憑證齊全，糧是新糧。是「倉的問題」── 涼州倉防潮失修。
工部探子：倉體去年才修過，防潮層完好。是「糧的問題」或「管倉的問題」。
```

三個探子，每個人的推步紀錄都乾淨，證據都紮實。

但結論**互相打架**。

---

尹知行第一反應是把三份回報都送上去，讓首輔自己看。

寫呈文寫到一半，他停筆了。

這不就是把「**仲裁**」這個最難的活，丟給最沒時間細看的人嗎？

首輔每天看幾十份呈文。三份互相矛盾的報告丟上去，結果只有兩種：要嘛首輔隨手挑一份信（**等於擲骰子**），要嘛發回重查（**等於白查**）。

**諸探合議，議而不決，等於沒議。**

他得在驛盟司這層，把矛盾收掉。

---

他先試了最直覺的辦法：**多數決**。

三個結論裡，「糧的問題」有兩票（兵部、工部），「倉的問題」一票（戶部）。

少數服從多數 ── 結論：糧的問題，採買有弊。

他把這個結論放了一晚，越想越不對。

工部那票「糧的問題」，仔細讀原文，其實是「**倉沒問題，所以大概是糧或管倉的問題**」── 這是**排除法**，不是**證據**。兵部那票才是真的驗了糧樣。

兩票看似同向，**含金量完全不同**。

**數人頭不數證據，多數決就是多數暴力。**

---

第二百一十天，尹知行設計了第一個合議機制：「**對質（debate）**」。

三個探子，當面坐下，規則三條：

```
一、各陳其證
    每人先講自己的結論 + 三條最硬的證據。只講證據，不講推測。

二、互攻其弱
    每人必須對另外兩人的證據提出至少一條質疑。
    質疑要具體：「你的糧樣取自倉的哪一層？」
    不准空泛：「我覺得你不對。」

三、改口有賞
    對質中被說服而改結論的，記功不記過。
    死守錯誤結論到底的，才記過。
```

第三條是他特地加的 ── 他在商會學過：**人不肯改口，多半不是因為證據，是因為面子**。把「改口」從丟臉變成有功，對質才會真的對質。

---

對質當天，第一輪就出了火花。

戶部探子質疑兵部探子：「你驗的糧樣，取自倉的哪一層？」

兵部探子：「上層。」

戶部探子：「**霉變是從下層開始的**。上層的黴，可能是下層傳上去的 ── 你驗上層樣，驗不出『入倉時就有黴根』還是『倉內受潮後長黴』。」

兵部探子愣住，翻自己的卷 ── 他確實只取了上層樣。

第二輪，工部探子被兵部探子問：「你說防潮層完好 ── 你驗的是哪一段？」

工部探子：「隨機抽了三段。」

兵部探子：「涼州倉沿山而建，**北牆貼山體** ── 山體滲水只會滲北牆。你抽的三段有北牆嗎？」

工部探子翻卷。沒有。

---

對質結束，三個探子帶著新問題回涼州，七天後回報：

下層糧樣 ── 黴根從**外皮向內**長（受潮特徵，不是陳糧特徵）。
北牆防潮層 ── **裂了一道三尺長的縫**，山體滲水浸了最靠牆的一垛糧。

真相：糧是新糧、倉整體完好，**北牆一道裂縫**。三個探子各自只看到了自己那一角。

結論改寫，三人聯名。首輔批：「修牆、換糧、立涼州倉巡檢例。」

---

複盤時，尹知行在本子上寫下這個案子教他的事：

> 三個探子都沒說謊、都沒偷懶 ── 但**每個人都只站在自己的角度取證**。

> 對質的價值不是「吵出誰對」，是**逼每個人去戳別人取證的盲區** ── 盲區戳出來，再去補查，真相自己浮現。

但他也記下了對質的成本：

> 對質一場，三個探子停工三天，加七天補查。

> **不是每個案子都值得對質。**

他定了一個分流規則，貼在驛盟司合議堂門口：

```
合議分流

結論一致 → 直接合卷。不要為了「程序完整」硬開對質。

結論衝突、案輕 → 總按察裁決（supervisor）：
    驛盟司設「總按察」一職，讀三方證據，按證據強度裁定。
    快，但依賴總按察一人的眼力。

結論衝突、案重 → 對質（debate）：
    各陳其證、互攻其弱、改口有賞。
    慢，但能戳出所有人的盲區。

對質後仍不決 → 補查再對質，最多兩輪。
    兩輪不決 = 證據不足以下結論 ── 「**不決**」本身就是結論，照實上報。
```

最後一條是他想得最久的。

**議到天荒地老不是嚴謹，是失職** ── 上報「現有證據不足以裁定」，讓上面決定要不要加派人力，比拖著像樣。

---

那晚他在牆上貼紙條：

> 多數決數的是人頭，對質數的是證據。

> 對質的真正產出不是勝負，是**盲區**。

> 議而不決要有期限 ──「不決」照實上報，也是一種決。

---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **築基初期・第七重「共議」**。

## 雜役筆記

*尹知行《諸探之約》第七章。*

**▍Multi-agent 結論衝突的三種處理**

| 機制 | 涼州案對應 | 適用 | 成本 |
|---|---|---|---|
| **Voting（多數決）** | 被否掉的第一版 | 答案空間小、各 agent 獨立同質 | 低 |
| **Supervisor（總按察）** | 案輕走這條 | 需要快、有一個夠強的裁決 agent | 中 |
| **Debate（對質）** | 案重走這條 | 高價值決策、要挖出盲區 | 高 |

**▍Voting 的陷阱**

「兩票糧的問題」看似同向，含金量不同 ── 一票是實證、一票是排除法推測。

多數決假設每票等權且獨立。實務上 agent 的「票」經常：
- 證據強度不同（驗過糧樣 vs 排除法）
- 不獨立（如果兩個 agent 用同一個資料源，它們的「兩票」其實是一票）

改良：**加權投票**（按證據強度/信心分數加權）、或 voting 只用來篩「需不需要進一步合議」。

**▍Supervisor 模式**

一個更高層的 agent 讀取各 worker 的產出，裁決或重新分派。

- 優點：決策快、結構簡單、責任清楚
- 缺點：supervisor 本身是單點 ── 它的偏誤就是系統的偏誤；它的 context 要裝下所有 worker 的產出
- 工程對應：LangGraph 的 supervisor pattern、AutoGen 的 GroupChatManager

**▍Debate 模式**

多個 agent 互相攻擊對方的推理，再下結論。研究顯示 debate 能顯著提升事實性任務的正確率 ── 核心機制正是「逼出盲區」：

```
Round 1: 各 agent 獨立給出結論 + 證據
Round 2: 每個 agent 必須針對其他 agent 的證據提出具體質疑
Round 3: 各 agent 看到質疑後，修正或堅持自己的結論
裁決:    aggregator 根據對質後的結論收斂
```

實作要點（對應對質三規）：
1. **質疑要具體**：prompt 裡明確要求「指出對方證據的具體弱點」，不是「你同不同意」
2. **改口無罰**：prompt 明確允許 agent 修正立場（「如果對方的質疑成立，請修正你的結論」）── 否則模型傾向死守第一版答案
3. **輪數封頂**：debate 不收斂就停，輸出「未決＋分歧點」

**▍「不決」是合法輸出**

兩輪對質不決 = 現有證據不足。此時最誠實的輸出是：

```json
{
  "verdict": "undecided",
  "positions": [...各方立場...],
  "disagreement": "分歧的具體點",
  "evidence_needed": "要裁決還缺什麼證據"
}
```

強迫收斂只會產生過度自信的錯誤結論 ── 書 1 的拷問章教過：**「我不知道」是合法答案**。多 agent 版本：「我們沒共識」是合法結論。

**▍成本分流**

合議機制是有價的：debate 的 token 成本是單 agent 的好幾倍。分流規則（一致→直接過；衝突＋輕→supervisor；衝突＋重→debate）就是在「準確率」和「成本」之間做的顯式取捨 ── 下下章「計餉」會正面處理成本。

## 這一章你只要記得這三件事

1. **多數決數人頭不數證據。** 實證一票和排除法一票不等值；同資料源的兩票其實是一票。Voting 只適合答案空間小、各方獨立同質的場景。
2. **Debate 的真正產出是盲區，不是勝負。** 規則三件套：質疑要具體、改口無罰、輪數封頂。
3. **「不決」是合法結論。** 兩輪不收斂就照實上報「證據不足＋分歧點＋還缺什麼」── 強迫收斂只會產生過度自信的錯誤。
