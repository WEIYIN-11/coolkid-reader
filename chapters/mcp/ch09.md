# 第 9 章　計餉

> *築基初期・第九重「計餉」*

第三百天，戶部尚書親自到驛盟司，把一本帳摔在溫止案上。

「驛盟司開銷，**上月四萬二千兩**。」尚書說，「驛站書吏的工錢、謄抄的紙墨、驛馬驛夫、各司加派的人手 ── 照這個燒法，**一年五十萬兩，夠修一段黃河大堤**。」

「朝廷立驛盟司是為了省「探子互毀」的浪費 ── 不是為了開一個更大的浪費。」

溫止把帳轉給尹知行，只說了四個字：

「**算清楚它。**」

---

尹知行把上月所有起居注的紀錄倒出來，逐條算。

起居注幫了大忙 ── 每一條 span 都記了「文牒（token）數」：一來一回的牒文，按字計量。驛站的工本，幾乎跟文牒數成正比 ── 牒越長、回文越厚，書吏抄得越久、紙墨越多。

他把帳拆開，看到的東西讓他自己都吃了一驚：

```
上月驛務總帳

按司分：
  刑部探子用驛     一萬八千兩（43%）
  鹽鐵司          九千兩
  兵部            七千兩
  其餘十司合計     八千兩

按事分：
  刑部的一萬八千兩裡 ──
    「取卷」類      一萬五千兩（83%）
    其中「整卷全取」 一萬二千兩
```

再往下挖，「整卷全取」的大頭，是刑部探子的一個習慣：

查案時不管用不用得上，**先把相關卷宗整卷取回來再說** ── 一卷屍格三千字，探子真正要看的是其中「死因」一欄，**八十個字**。

三千字的工本，用八十個字。

**九成七的驛資，花在沒人看的字上。**

---

尹知行又發現第二個漏洞：**同一卷被重複取**。

滄州去年有一件大案，卷宗熱門。上月「滄州-刑名-卷四十一」這一卷，被**十一個不同的探子各取了一次**。

十一次全額工本 ── 抄了十一遍同一卷。

第三個漏洞最隱蔽：**牒文越寫越長**。

通文式只規定了「必含七欄」，沒規定上限。各司的驛使為了「保險」，把探子的整段原話、前因後果、甚至客套話全塞進牒裡。平均一張牒，從推行初期的兩百字，膨脹到了**九百字**。

回文也跟著膨脹 ── 書吏看牒裡寫得鄭重，回文也不敢簡短。

---

第三百一十天，尹知行頒《計餉例》，四條：

```
一、按牒計餉，帳隨牒走
    每張牒、每份回文，按文牒數計工本，記在「案號」名下。
    每司每案，月底一張帳單 ── 誰用的、用在哪案、花多少，一目了然。

二、節流四法
    取要不取全：取卷窗口加「取欄」之法 ── 可只取一卷中的指定欄目。
      （屍格只取「死因」欄：三千字變八十字。）
    熱卷置抄：被取超過三次的卷，驛站抄一份置於外架，
      再有人取，給抄本、收半價工本。（同卷十一取，十一份全價變一份全價＋十份半價。）
    牒文限長：牒正文以三百字為限。超長者，驛站照收，但超出部分**雙倍計餉**。
      （不禁止，但讓囉嗦變貴。）
    急務分等：尋常牒走慢驛（次日回），半價；急牒走快驛（即時回），全價。
      （多數查詢根本不急 ── 給便宜的慢路，人自然分流。）

三、司設餉額（budget）
    每司每月驛餉有額。八成時驛使示警，滿額後新牒入慢隊。
    要超 ── 司丞具名申請，說明用在哪案。

四、月帳公示
    十三司的驛餉月帳，驛盟司公示。
    誰省誰費，同儕看得見。
```

---

推行第一個月，反彈最大的是「牒文限長」。

刑部的驛使抗議：「案情複雜，三百字寫不清。」

尹知行調出刑部上月最長的一張牒 ── 一千四百字 ── 當著驛使的面刪。

客套開頭，刪。前因後果的鋪陳（驛站書吏根本不需要知道），刪。「若有不便還望海涵」，刪。

剩下的有效內容：

```
尋格：滄州／溺死／去年六至九月
要欄：死因、屍身特徵
急否：否
```

**三十一個字。**

「你那一千四百字裡，書吏真正用來查卷的，就這三十一個字。」尹知行說，「其餘一千三百多字，**書吏要先讀完、再扔掉** ── 你付錢讓他讀你的客套話。」

驛使啞口。

---

第二個月，帳出來了：

```
驛務總帳：四萬二千兩 → 一萬九千兩（-55%）

其中：
  取欄之法省      九千兩
  熱卷置抄省      四千兩
  牒文瘦身省      五千兩
  慢驛分流省      三千兩
  （查案量：不減反增 7% ── 因為便宜了，原本捨不得查的也查了）
```

最後一行是尹知行特地算給戶部尚書看的。

「省錢的目的不是少辦事。」他在呈文裡寫，「**是讓同一筆銀子，辦更多的事。**」

戶部尚書批回來兩個字：「**可。續。**」

---

那晚他在牆上貼紙條：

> 算帳要算到「案」── 總數嚇人，明細才能治病。

> 九成七的驛資花在沒人看的字上：**取全卷的習慣、重複的熱卷、膨脹的牒文**。

> 不禁止浪費，**讓浪費變貴** ── 人自己會省。

---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **築基初期・第九重「計餉」**。

## 雜役筆記

*尹知行《諸探之約》第九章。*

**▍Token-based Pricing（按文牒計餉）**

LLM 的計費單位是 token（輸入 + 輸出分開計價，輸出通常貴數倍）。Multi-agent 系統的成本 = 所有 agent、所有輪次、所有工具回傳的 token 總和 ── **跨 agent 的訊息每轉一手就再算一次**，膨脹比單 agent 快得多。

**▍成本可見性：按 trace 歸帳**

「帳隨牒走」= 把 token 用量記在 trace/span 上（上一章埋的料），就能按「案件、agent、操作類型」聚合：

```
總帳嚇人 → 按 agent 分 → 按操作分 → 找到熱點
刑部 43% → 取卷類 83% → 整卷全取 → 對症下藥
```

**沒有按案歸帳的成本管理 = 只知道帳單總數的節食** ── Langfuse / Helicone / LangSmith 都內建 per-trace token 統計。

**▍四個最常見的 token 黑洞（對應節流四法）**

1. **整卷全取 → 取你要的欄**：工具回傳要支援欄位選擇/分頁/摘要層級。一份 API 回應全文塞進 context，模型只用其中一欄 ── 97% 的 token 餵了空氣。Tool 設計時就要給 `fields` / `limit` 參數。
2. **熱資料重複取 → 快取（prompt caching / result caching）**：同一份卷宗被十一個探子取十一次 = 同樣的 context 重複計費。Anthropic 的 prompt caching：重複的前綴段落以~1/10 價格計；應用層的查詢結果快取同理。
3. **訊息膨脹 → 上下文紀律**：agent 間傳遞的訊息要傳「結論與必要證據」，不是完整對話史。「付錢讓書吏讀你的客套話」= 把整段 conversation history 轉發給下一個 agent。
4. **不分急緩 → 模型分級（model routing）**：不是每個任務都需要旗艦模型。簡單分類/抽取 → 小模型（快驛慢驛差價可達 10-60 倍）；複雜推理 → 大模型。Batch API（慢驛）通常半價。

**▍Budget（餉額）**

每個 agent / 每個任務設 token 預算：

```
- 軟限（八成示警）：記錄並告警，不中斷
- 硬限（滿額處置）：降級（換小模型）、入隊（batch）、或中止並上報
- 超額要顯式申請 ── 不是悄悄燒
```

Agent 迴圈尤其需要硬限 ── 失控的 ReAct 迴圈一晚上能燒掉一個月的預算（書 3 的空轉死法，這裡有了價格標籤）。

**▍成本與價值一起報**

「查案量不減反增 7%」── 成本優化的正確指標不是「花得少」，是**單位產出成本**。只報帳單會導向「少用」；報「每案成本」才導向「用得聰明」。降本後使用量上升是健康訊號（Jevons 效應的良性面）。

## 這一章你只要記得這三件事

1. **成本要按 trace 歸帳才能治病。** 總數只會嚇人；按案 → 按 agent → 按操作層層下鑽，熱點自己浮現。
2. **四大 token 黑洞：整卷全取、熱卷重複取、訊息膨脹、不分急緩。** 對症：欄位選擇、快取、上下文紀律、模型分級。
3. **不禁止浪費，讓浪費變貴。** 軟限示警、硬限處置、超長雙倍計價、慢驛半價 ── 經濟槓桿比禁令有效，且指標要看單位產出成本，不是總帳。

下一章：驛路通了、帳也算清了 ── 然後出了開盟以來最嚴重的一次事故：**有人偽造驛牒，借別司探子的手，從驛站套走了密卷**。驛道上有了奸細。**防諜**。
