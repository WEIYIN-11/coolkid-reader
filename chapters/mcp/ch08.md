# 第 8 章　留痕

> *築基初期・第八重「留痕」*

涼州案結案一個月後，兵部來函，措辭很硬：

> 「貴司對質紀錄載明：本部探子『取樣只取上層、取證有疏』。
>
> 本部覆核探子，探子稱：**取上層是涼州倉管的建議**，倉管說下層糧垛壓實、開垛費工。
>
> 若此言屬實，疏失在倉管誤導，不全在探子。**請貴司查證**。」

尹知行去翻案卷。

卷裡有探子的每旬回報、有對質紀錄、有最後的聯名結論。

但「**取樣那天倉管說了什麼**」── 沒有。

回報寫的是「三月初七，取糧樣三份，驗得上層有黴」。**做了什�麼，有**。**為什麼這樣做、誰影響了這個決定** ── 沒人記。

探子自己也說不清了 ── 那是兩個月前的事，他跑了四個案子，記憶早糊了。

兵部的函，最後只能回「**查無實據，無法查證**」。

兵部不滿意。探子覺得冤。驛盟司被夾在中間。

---

尹知行在合議堂坐了一晚。

他想起自己在雲書司管九百二十個探子的時候，每個探子都有推步小冊 ── 觀察、思考、行動，一輪一條。

那時候是**單司**：冊子是雲書司的內規，探子寫給自己司丞看。

現在是**跨司**：兵部探子用了漕運司的驛站、聽了戶部倉管的話、在驛盟司對質 ── 一條查案路徑橫穿四個衙門。

**每個衙門只看得到自己門裡那一段。**

兵部知道探子哪天出發、哪天回。
漕運驛站知道有人來牒查過水文。
倉管知道自己說過什麼（但不會主動講）。
驛盟司知道對質結果。

**沒有任何一個人，看得到完整的那條線。**

---

第二百四十天，尹知行向溫止提《起居注案》。

「皇帝有起居注 ── 言行起居，逐條記錄，史官執筆，皇帝本人不得改。」

「跨司辦案的探子，也要有**起居注（observability）**。」

規制三層：

```
一案一卷（trace）
    凡跨司案件，開案即立一卷起居注，案號即卷號。
    這條案子上所有人的所有動作，都記進同一卷。

一步一條（span）
    探子每做一個動作，記一條：
      何時、何人、做什麼、為什麼做（聽了誰的建議）、
      用了哪座驛站、耗時多久、結果如何。
    條與條之間記「先後」：這一步是因為上一步的什麼結果。

隨做隨記（structured logging）
    不是結案後補記 ── 是做一步記一步。
    補記的起居注必然美化、必然遺漏。
    記錄的格式照《通文式》：欄位寫死，不准散文。
```

溫止看完問：「探子會嫌煩。」

「會。」尹知行說，「所以記錄的活，**儘量不讓探子做**。」

「探子過驛站 ── 驛站自動記（誰、何時、查了什麼、回了什麼）。
探子用驛使 ── 驛使自動記。
只有『**為什麼**』這一項，必須探子自己寫一句 ── 因為只有他自己知道。」

「一步一句話，比涼州案之後被兵部追問兩個月便宜。」

溫止用印。

---

起居注推行第一個月，就破了一個誰都沒料到的案。

不是貪腐案 ── 是**效率案**。

尹知行月底翻各案起居注，發現一個怪事：凡是用過刑部驛站「尋格」問事的案子，**那一步的耗時都特別長** ── 別的問事一個時辰回文，「尋格」平均要一天半。

他調出刑部驛站自己的紀錄，逐條對 ──「尋格」的書吏只有一個，而且這個書吏同時兼管屍格庫的日常整理。牒一多，他就積壓。

**沒有起居注之前，每個探子只覺得「刑部回得慢」，忍了。**
**起居注把「慢」變成了數字，數字指向了同一個瓶頸。**

刑部加派一個書吏，「尋格」回文時間降到半天。

尹知行把這件事記進《諸探之約》：

> 起居注的第一個用處是「出事後問責」。

> 但更大的用處是「**沒出事時找瓶頸**」── 慢、貴、繞路，全都藏在紀錄裡，等人去翻。

---

第二百七十天，涼州案式的爭議又來了一次 ── 工部探子被指「漏查一個料場」。

這次不一樣了。

調起居注，三條紀錄攤開：

```
四月初二　工部探子　問事「查料場〔涼州〕」於工部驛站
          回文：在冊料場二處（東場、西場）
四月初三　探子赴東場查驗　〔為何：在冊僅二處，先查近者〕
四月初五　探子赴西場查驗　〔為何：續查第二處〕
```

被「漏查」的那個料場，**不在工部驛站的在冊清單裡** ── 是個私設黑料場。

探子按紀錄辦事，一步沒漏。**漏的是工部自己的料場名冊**。

問責從探子身上移開，落到名冊維護的主事頭上。

探子後來跟尹知行說了一句話：

「以前辦案，最怕的不是案子難，是**事後說不清**。現在起居注一條條在那 ── **它記我的每一步，也保我的每一步**。」

---

那晚尹知行在牆上貼紙條：

> 起居注三層：一案一卷、一步一條、隨做隨記。

> 「做了什麼」驛站代記，「為什麼做」只能自己寫。

> 它記你的每一步，也**保**你的每一步。

---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **築基初期・第八重「留痕」**。

## 雜役筆記

*尹知行《諸探之約》第八章。*

**▍Observability（可觀測性 / 起居注）**

系統運行時的內部狀態，能從外部紀錄完整重建。Multi-agent 系統的 observability 比單 agent 重要一個量級 ── 因為**一條執行路徑橫穿多個 agent、多個 server，沒有任何單點看得到全貌**。

**▍Trace / Span（一案一卷 / 一步一條）**

分散式追蹤的核心模型：

- **Trace（卷）**：一次端到端的執行，唯一 trace_id 貫穿全程 ── 跨 agent、跨 server 都帶著同一個 id
- **Span（條）**：trace 裡的一個動作單位，記：開始/結束時間、操作名、輸入輸出摘要、父 span（因果鏈）

```
trace: 案盟-元-0017（涼州軍糧案）
 ├─ span: 兵部探子.取樣     (3h)  ← 為何：倉管建議取上層
 │   └─ span: 驛站.查倉圖   (0.5h)
 ├─ span: 戶部探子.驗憑證   (2d)
 │   ├─ span: 驛站.調撥銀底冊 (1h)
 │   └─ span: 驛站.尋格      (1.5d)  ← 瓶頸在這裡被看見
 └─ span: 對質              (3d)
```

**▍LLM 應用的 span 該記什麼**

```
- model / agent 名、版本
- prompt（或其摘要/hash）、completion（或其摘要）
- token 數（input / output）── 下一章計餉的原料
- 工具呼叫：tool 名、參數、結果、耗時
- 錯誤與重試
- 「為什麼」：推理摘要（ReAct 的 thought 就是現成的 why）
```

「做了什麼自動記、為什麼只能自己寫」── 框架能自動埋的是動作層（tool call、token、延遲），**決策依據**（為什麼取上層）必須來自模型的推理輸出，要顯式保留。

**▍Structured Logging（隨做隨記、欄位寫死）**

- 即時記，不要事後補（補記必美化、必遺漏）
- 結構化欄位（JSON），不要自由散文 ── 散文不可查詢、不可聚合
- 對應工具：**Langfuse**（開源 LLM tracing）、**LangSmith**（LangChain 生態）、**Helicone**（proxy 式接入）、**OpenLLMetry**（OpenTelemetry 標準的 LLM 擴充）

**▍Observability 的兩個用途**

1. **事後歸因（涼州案）**：哪一步、誰的輸入、什麼依據 ── 問責和免責都靠它。「它記我的每一步，也保我的每一步」── 完整的紀錄對被審查者是保護，不只是監控。
2. **日常找瓶頸（尋格案）**：聚合 span 統計 → 慢的、貴的、常失敗的操作自動浮現。**沒有 tracing 的系統，每個人只感覺得到「慢」，沒有人知道慢在哪**。

**▍跨 agent 的 trace 傳遞**

關鍵工程細節：agent A 呼叫 agent B（或 server）時，**trace_id 要跟著請求傳過去**（案號寫進牒），B 的紀錄才能掛回同一卷。MCP 場景：client 發起的請求帶 metadata，server 的執行紀錄回掛同一個 trace ── 否則十三司各記各的，又回到「沒有人看得到全貌」。

## 這一章你只要記得這三件事

1. **Multi-agent 的執行路徑橫穿多個系統，沒有單點看得到全貌 ── 所以 trace_id 必須跟著請求跨系統傳遞。** 一案一卷、一步一條。
2. **動作自動記（tool call、token、耗時），「為什麼」顯式留（推理摘要）。** 出事後要還原的不是做了什麼，是憑什麼這樣做。
3. **Observability 的價值一半在問責，一半在找瓶頸。** 聚合統計讓「慢、貴、常失敗」自動浮現 ── 刑部尋格的積壓，是被數字抓出來的，不是被抱怨抓出來的。
