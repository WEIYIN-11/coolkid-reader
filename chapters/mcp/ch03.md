# 第 3 章　立驛

> *築基初期・第三重「立驛」*

第五十天，通文式推到了第五個司。

然後尹知行收到一封來自鹽鐵司的抱怨信，寫信的就是演習案那位探子：

> 「封皮通了，是好事。但上月我查私鹽案，需調雲書司三年前在滄州的一份卷宗。
>
> 我司發函 → 雲書司收函 → 核我司密級 → 謄抄卷宗 → 回函 ── **前後十三天**。
>
> 私鹽販子三天就出海了。
>
> 文書通了，**門還是鎖的**。」

尹知行拿著信坐了半天。

通文解決的是「**看得懂**」。

沒解決「**拿得到**」。

---

他先想到的辦法，是他在商會學的：**把卷宗抄一份過去**。

商會當年各分舵資料對不上，他建了「總櫃主檔」，各分舵抄錄同步。

那就讓雲書司把卷宗抄一份放驛盟司，各司來驛盟司查？

他寫了個草案，拿去找溫止。

溫止看完，只問了一句：

「雲書司的卷宗，**一年添多少**？」

「⋯⋯大約八千卷。」

「你抄一份放驛盟司。那刑部呢？戶部呢？十三司都抄來，驛盟司一年進十萬卷。」溫止說，「然後雲書司今天補了一筆卷宗，你驛盟司的抄本**什麼時候跟上**？跟不上的那幾天，別司查到的是**舊的還是新的**？」

尹知行答不出來。

「再說。」溫止放下草案，「鹽鐵司願意把鹽引底冊抄給你放著嗎？」

「⋯⋯不願意。」

「**資料留在主人家裡，才是各司肯通的前提**。」溫止說，「你商會那套，是一家之內的事。十三司，是十三家。」

---

尹知行回去把草案燒了。

他重新想這個問題。

卷宗不能搬。那能搬的是什麼？

**是「查」這個動作。**

別司探子不需要「擁有」雲書司的卷宗 ── 他需要的是「**問一聲，得一答**」。

像什麼？

像驛站。

旅人不需要擁有驛站的馬廄、糧倉、馬伕 ── 他騎到驛站，遞上驛牒，換馬、吃飯、問路，然後走人。

**馬還是驛站的馬。但路人人能走。**

---

第六十天，尹知行向溫止提《立驛案》：

「在雲書司門口，立一座『**驛站（server）**』。」

「卷宗庫還是雲書司的，一卷都不搬。但驛站對外開三個窗口：

```
一、取卷（resources）
    遞卷宗號，得卷宗內容。
    例：「取 滄州-巡鹽-三年前-卷七」→ 得該卷全文。

二、問事（tools）
    遞一個明確的問題，驛站裡的書吏代查代答。
    例：「滄州近三年私鹽案，主犯名單？」→ 書吏翻卷彙整 → 回名單。

三、領訣（prompts）
    遞案件類型，得雲書司積累的「查案套路」。
    例：「我要查私鹽案」→ 得《私鹽案查辦十二步》模板。
```

「窗口的格式，全部依《通文式》：什麼窗口、收什麼牒、回什麼文，**寫死、公示**。」

溫止看完，問了一個問題：

「為什麼是三個窗口？取卷和問事，不都是『查』嗎？」

「不一樣。」尹知行說，「**取卷**是『我知道我要哪一卷』── 給原料，探子自己消化。**問事**是『我有問題但不知道答案在哪幾卷』── 驛站代工，給成品。」

「一個給料、一個給菜。」溫止說。

「對。**領訣**則是給食譜 ── 連怎麼查都教你。」

溫止用印。

---

第七十天，雲書司驛站開張。

掛牌那天，尹知行在驛站門口立了一塊公示碑，碑上刻的就是驛站的「**所能（capabilities）**」：

```
雲書司驛站・所能公示

【取卷】
  牒式：取卷〔卷宗號〕
  回式：卷宗全文，或「查無此卷」，或「密級不符」
  範圍：丙級以下卷宗、三年內

【問事】
  問事一：查人〔姓名／籍貫〕→ 回該人在卷案件列表
  問事二：查案〔州府／案類／年份〕→ 回案件摘要列表
  問事三：查贓〔贓物描述〕→ 回相似贓物在卷紀錄
  （只此三問。問别的，回「此驛無此事」。）

【領訣】
  訣一：私鹽案查辦套路
  訣二：糧倉虧空案查辦套路

【牒驗】
  凡來牒，必附：司名、探子號、案號（盟字號）、密級憑印
  缺一不接。
```

第一個來用的，就是鹽鐵司那位寫抱怨信的探子。

他遞牒「查人〔王五／滄州〕」，驛站書吏翻卷，**一個時辰**回了文：王五在卷三案，案號、摘要、卷宗號列齊。

探子拿著回文愣了一下，說了一句：

「⋯⋯上次這件事，我等了十三天。」

---

第八十天，問題來了。

驛站太好用，各司的牒像雪片一樣飛來。書吏從兩個加到六個，還是消化不完。

更麻煩的是，各司開始提要求：

刑部：「能不能加一問：查屍格（驗屍紀錄）？」
戶部：「能不能讓我們直接進庫自己翻？」
兵部：「牒式太繁瑣，我們急務能不能免牒？」

尹知行一條一條回：

刑部的「加一問」── **可**。驛站公示碑加刻「問事四：查屍格」。**所能可以擴充，擴充必公示**。

戶部的「直接進庫」── **不可**。「驛站之所以能開，是因為雲書司知道你**只能從窗口拿、拿什麼有紀錄**。你進庫自由翻，明天雲書司就關驛。」

兵部的「免牒」── **不可**。「免牒一開，誰來查過什麼就沒了紀錄。**揚州案的根，就是互相不知道誰在做什麼** ── 驛站不能自己再種一次這個根。」

---

那晚他在牆上貼紙條：

> 驛站三律：

> 一、**料不出門**。卷宗留在主人家，出門的是「答」。

> 二、**窗口寫死**。能做什麼，公示碑上刻什麼。要加，先改碑。

> 三、**無牒不接**。每一次取用，留一條紀錄。

---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **築基初期・第三重「立驛」**。

## 雜役筆記

*尹知行《諸探之約》第三章。*

**▍MCP Server（驛站）**

把一個資料源/工具系統，包裝成「對外提供標準化能力」的服務。

關鍵設計（驛站三律的對應）：

1. **資料不搬家**：server 是資料源前面的一層門面（facade），不是資料的副本。沒有同步延遲問題、沒有所有權轉移問題 ──「資料留在主人家裡，才是各司肯通的前提」。
2. **能力顯式宣告**：server 啟動時公示自己提供哪些 tools/resources/prompts。Client 只能用公示的，沒公示的不存在。
3. **每次取用有紀錄**：誰、什麼時候、拿了什麼。

**▍MCP 的三類能力（三個窗口）**

| MCP 概念 | 驛站窗口 | 給什麼 | 控制權在誰 |
|---|---|---|---|
| **Resources** | 取卷 | 原料（文件、資料內容） | 應用端決定讀哪個 |
| **Tools** | 問事 | 成品（執行一個動作、回結果） | **模型自己決定**何時呼叫 |
| **Prompts** | 領訣 | 食譜（預寫好的提示模板） | 使用者選用 |

「一個給料、一個給菜、一個給食譜」。

設計分界：
- 探子需要**自己消化原文**（找上下文、交叉比對）→ resource
- 探子需要**一個動作的結果**（查詢、計算、變更）→ tool
- 使用者要套用**標準作業流程** → prompt

**▍為什麼不用「資料同步」解互通**

尹知行被溫止打掉的「商會式抄錄方案」，是真實世界常見的反模式（把所有資料 ETL 進中央倉庫再開放）。問題：

1. **時效**：同步有延遲，讀到舊資料
2. **規模**：13 個源頭 × 持續增量，中央倉庫爆炸
3. **所有權**：資料擁有者失去控制 → 拒絕參加
4. **密級**：搬出來的那一刻，原本的權限體系失效

MCP 式的「query 過去、資料不動」（federation）解掉這四個問題。代價：每次查詢都是即時請求，比讀本地副本慢 ── 但「正確而慢」勝過「快而舊」。

**▍Capability 公示（所能公示碑）**

MCP server 在連線初始化時回報自己支援的能力清單。Client 據此知道「這個 server 能做什麼」── 不用讀文件、不用猜。

對應 MCP 協議的 `tools/list`、`resources/list`、`prompts/list` 方法。

**▍Server 的擴充紀律**

- 加能力（刑部加「查屍格」）：**可以**，公示後生效 ── 向後相容
- 繞過介面（戶部要直接進庫）：**不行**，破壞封裝
- 移除驗證（兵部要免牒）：**不行**，破壞審計

「所能可以擴充，擴充必公示」= API 的向後相容原則：加欄位可以，改語義、刪欄位、繞驗證不行。

## 這一章你只要記得這三件事

1. **MCP server = 資料源前的標準化門面。** 料不出門 ── 卷宗留在主人家，出門的是答。用 query federation，不用資料同步。
2. **三類能力分工明確：resources 給料、tools 給菜、prompts 給食譜。** Tools 是模型自己決定呼叫的，description 要寫到模型知道何時該用。
3. **窗口寫死、無牒不接。** 能力顯式公示、每次取用留紀錄 ── 這是資料擁有者肯開門的前提。

下一章：驛站立好了，但漕運司的探子到了驛站門口，**不知道怎麼遞牒** ── 牒怎麼寫、回文怎麼讀、斷了怎麼重連。立驛是一半，**接驛**是另一半。
