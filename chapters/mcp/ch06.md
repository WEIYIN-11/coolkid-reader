# 第 6 章　分工

> *築基初期・第六重「分工」*

第一百六十天，黃河在開封段決堤。

淹了三個縣。

朝廷震動。賑災的同時，首輔下令徹查：**這段堤去年才大修過，耗銀四十萬兩，為什麼一年就決？**

案子發到驛盟司 ── 因為它**橫跨三司**：

- 工部：堤是工部修的。施工有沒有偷工減料？
- 戶部：銀是戶部撥的。四十萬兩有沒有走到工地？
- 漕運司：決堤前後的水情調度是漕運司管的。有沒有調度失誤？

溫止把案卷丟給尹知行：「驛站都通了。**讓三司合查**。」

---

尹知行的第一個念頭，是把三司的探子叫到一起，開個會，然後各查各的。

會開了。三司各派兩個探子，加上尹知行，七個人。

他說：「工部查施工、戶部查銀流、漕運查調度。一個月後合卷。」

眾人散去。

第一旬的回報送上來，尹知行就知道**壞了**。

工部探子報：「施工紀錄完整，用料憑證齊全 ── **但用料憑證的採買價，需對戶部的撥銀底冊才能驗真偽**。我沒有，等戶部。」

戶部探子報：「撥銀紀錄完整，四十萬兩確實撥出 ── **但撥出之後流到哪些商號，需對工部的採買清單**。我沒有，等工部。」

漕運探子報：「調度紀錄查完，決堤前三天上游連暴雨，我司已按例洩洪 ── **但洩洪量是否超出堤體承受，需要工部的堤體規格**。我沒有，等工部。」

**三個探子，三個「等」。**

每個人都卡在「我的下一步需要別人的產出」。

而且沒有人知道別人卡在等自己 ── 工部探子不知道戶部在等他的採買清單，他把採買清單壓在自己的卷底，打算最後一起交。

第一個月就這樣空轉掉了。

---

尹知行複盤的時候，想起他在雲書司寫過的「謀篇」── 大任務拆小、小任務排序。

但那是**一個探子**的謀篇 ── 拆完的小任務，還是同一個探子按順序做。

這次是**三個司、六個探子** ── 拆完的任務分給不同人，而任務之間**有依賴**：

```
戶部「驗銀流」 ←需要← 工部「採買清單」
工部「驗用料價」 ←需要← 戶部「撥銀底冊」
漕運「算堤體承受」 ←需要← 工部「堤體規格」
```

他把這張依賴圖畫在牆上，看了半天，發現兩件事：

第一，工部的「採買清單」和「堤體規格」是**兩件不相干的事** ── 可以同時做，不用等彼此。

第二，戶部和工部**互相等對方** ── 但仔細看，戶部要的「採買清單」是工部查案的**第一步產出**，工部要的「撥銀底冊」是戶部的**第一步產出**。兩個「第一步」都不依賴別人 ── **先交換第一步，僵局就解了**。

問題不在任務，在**沒有人看全局**。

---

第一百七十五天，尹知行重組這個案子。

他設了一個新角色：「**謀篇官（planner）**」── 這次他自己當。

謀篇官做四件事：

```
一、拆案
    把大案拆成「一個探子兩旬內能查完」的小任務。
    每個小任務寫清：要查什麼、產出什麼、誰來查。

二、畫圖（依賴圖）
    每個任務標清楚：它需要誰的產出、誰在等它的產出。
    不依賴別人的任務 → 全部同時開工。
    互相依賴的 → 先交換「第一步產出」解鎖。

三、盯狀態
    每旬收一次各任務狀態：未動／在查／已完／卡住。
    「卡住」必須寫卡在等誰 ── 謀篇官去催那個「誰」。

四、改圖（re-plan）
    查案中發現新線索 → 加任務、改依賴。
    圖是活的，不是立案那天畫完就死了。
```

黃河案重新拆完是九個任務，畫成圖：

```
【可立即開工・並行】
  任務一（工部）：調堤體規格與施工紀錄
  任務二（工部）：調採買清單          ──→ 交戶部
  任務三（戶部）：調撥銀底冊          ──→ 交工部
  任務四（漕運）：調決堤前後水情調度紀錄

【等上游產出】
  任務五（戶部）：對採買清單驗銀流向     ←任務二
  任務六（工部）：對撥銀底冊驗用料真偽   ←任務三
  任務七（漕運）：對堤體規格算洩洪承受   ←任務一

【收口】
  任務八（戶部）：追查流向異常的商號     ←任務五
  任務九（謀篇官）：三線合卷、交叉驗證    ←五、六、七、八
```

每個探子拿到的任務令上，多了兩行字：

> 你的產出，╳╳在等。完成即送，**不要壓卷底**。
>
> 你若卡住，當日報謀篇官，**不要自己等**。

---

第二個月，九個任務全部走完。

合卷的結果：

施工沒有偷工減料（任務六：用料價與撥銀對得上）。
調度沒有失誤（任務七：洩洪量在堤體設計承受之內）。

問題在**任務八**揪出來的 ── 採買清單裡有一家石料商號，收了八萬兩，**石料卻是從一個廢棄料場拉的舊料**。新料的錢、舊料的貨，差價進了三個人的口袋：石料商、工部一個主事、和**驗收的監工**。

堤體用料以舊充新，扛不過一場大汛。

三人下獄。案結。

---

複盤會上，漕運司的探子頭領問尹知行：

「這案子六個探子，跟以前比，多了一個**不查案的人** ── 你這個謀篇官。一個人不查案，光畫圖盯狀態，**值嗎**？」

尹知行把第一個月和第二個月的進度擺在一起：

```
第一個月（無謀篇官）：三線全卡，產出零。
第二個月（有謀篇官）：九任務完成，案結。
```

「六個探子空轉一個月，**浪費的是六個人月**。」尹知行說，「謀篇官的成本是一個人月。」

「而且 ──」他指著依賴圖，「**探子越多，這個角色越值**。三司六探子，依賴有五條。十司二十探子，依賴幾十條 ── 沒人看全局的話，**空轉的不是一個月**。」

---

那晚他在牆上貼紙條：

> 多探子合查，死法不是「查不動」，是「**互相等**」。

> 每個人都在等，每個人都不知道別人在等自己。

> 解法：一個看全局的謀篇官 + 一張活的依賴圖。

> **不依賴別人的，全部同時開工。互相依賴的，先交換第一步。**

---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **築基初期・第六重「分工」**。

## 雜役筆記

*尹知行《諸探之約》第六章。*

**▍Planner-Executor 模式**

把「規劃」和「執行」拆成不同角色：

- **Planner（謀篇官）**：拆解任務、畫依賴、分派、盯進度、re-plan。**自己不執行**。
- **Executor（探子）**：領一個界定清楚的子任務，執行、回報產出。**不需要知道全局**。

對比書 3 的 ReAct（單 agent 邊想邊做）：planner-executor 適合**步驟可拆、可並行、多 agent** 的場景。ReAct 適合探索性、走一步看一步的場景。

**▍DAG Agents（依賴圖驅動）**

把任務組織成 **DAG（Directed Acyclic Graph，有向無環圖）**：

- 節點 = 子任務
- 邊 = 依賴（A → B 表示 B 需要 A 的產出）

執行規則：
1. 入度為零（不等任何人）的節點 → **全部並行開工**
2. 節點完成 → 下游節點的依賴減一 → 歸零即開工
3. 循環依賴（戶部等工部、工部等戶部）→ 拆出「第一步產出」解鎖，或合併節點

黃河案第一個月的空轉 = 沒有顯式 DAG 時的典型死法：**隱式依賴 + 沒人看全局 = 全員互等（deadlock）**。

**▍依賴圖的工程對應**

```python
tasks = {
  "採買清單": {"deps": [], "owner": "工部"},
  "撥銀底冊": {"deps": [], "owner": "戶部"},
  "驗銀流向": {"deps": ["採買清單"], "owner": "戶部"},
  "驗用料真偽": {"deps": ["撥銀底冊"], "owner": "工部"},
  ...
}
# 排程器：每輪把 deps 全部完成的任務丟給對應 agent 並行執行
```

LangGraph 的 graph、Airflow 的 DAG、make 的 target 依賴 ── 同一個模型。

**▍Re-plan（改圖）**

「圖是活的」：執行中發現新線索（流向異常的商號）→ planner 動態加節點（任務八）。

Plan-and-Execute 的最大弱點是「計畫趕不上變化」── 解法不是放棄計畫，是**把 re-plan 做成例行動作**：每輪執行完，planner 重看一次圖。

**▍兩條反空轉鐵律**

1. **產出即推送**：你的產出有人在等 ── 完成即交付，不要攢到最後一起交（工部把採買清單壓卷底 = 阻塞下游一個月）
2. **卡住即上報**：等待不是探子的工作 ── 卡住當日報 planner，由看得到全局的人去解

對應工程實務：任務狀態要顯式（pending / running / done / **blocked-on-X**），blocked 狀態必須帶「等誰」。

**▍Planner 的成本論證**

「一個不幹活的 agent 值嗎」── 用空轉成本算：

- 無 planner：N 個 executor 隱式互等，最壞全員空轉
- 有 planner：多付一個 agent 的成本，換取依賴顯式化

**N 越大、依賴越密，planner 的投資報酬越高**。N=2 且無依賴時，不需要 planner ── 別過度設計。

## 這一章你只要記得這三件事

1. **多 agent 合作的頭號死法是互等（deadlock），不是查不動。** 每個人都卡在等別人，且不知道別人在等自己。依賴必須顯式畫出來。
2. **DAG 執行兩規則：入度為零全部並行、完成即解鎖下游。** 循環依賴用「先交換第一步產出」打破。
3. **產出即推送、卡住即上報。** blocked 狀態必須帶「等誰」── 讓看得到全局的 planner 去解，不要讓 executor 自己等。
