# 第 1 章　失約

> *築基初期・第一重「失約」*

> *尹知行從雲書司南下，走了十六天，入京畿。*
>
> *離開北望城那天，嚴司丞送他到城門口，只說了一句：*
>
> ***「你會造探子了。但你的探子，出了雲書司就是個啞巴。」***
>
> *尹知行那時候不服。*
>
> *他的探子完成率七成、有圈籠、有試煉、有手冊 ── 天下探子司都在學雲書司之法。*
>
> *入京第三天，他就明白嚴司丞在說什麼了。*

---

尹知行抵達京畿那一天，先看到的不是驛盟司。

是刑部大牢門口，兩個披枷的探子。

一個是漕運司的，一個是鹽鐵司的。

兩個都是好探子 ── 他後來看了卷宗，兩個人的推步紀錄都乾淨漂亮，每一輪「觀察、思考、行動」都站得住。

但他們在揚州，互相把對方**當成奸細**上報了。

---

事情是這樣的。

揚州知府貪。漕運司接到的線報是「**漕糧虧空**」，派了探子去查。鹽鐵司接到的線報是「**鹽稅短收**」，也派了探子去查。

**同一個貪官。兩條線報。兩司各派各的探子。**

漕運司的探子偽裝成糧商，蹲了一個月，快摸到帳冊了。

鹽鐵司的探子偽裝成鹽販，也蹲了一個月，也快摸到帳冊了。

然後兩個人在知府的後巷撞上了。

漕運司探子觀察：此人深夜出入知府後宅、行蹤詭祕、不是本地口音 ── **推斷：知府的外地同黨**。上報。

鹽鐵司探子觀察：此人深夜跟蹤我、身上有兵刃、問話閃爍 ── **推斷：知府雇的殺手**。上報，並先動了手。

兩個人在巷子裡打了一架，雙雙掛彩，被巡夜的官兵當成盜匪抓了。

身分核實花了十一天 ── 因為**漕運司的探子名冊，鹽鐵司看不到；鹽鐵司的，漕運司也看不到**。

十一天裡，揚州知府燒光了所有帳冊。

案子死了。

---

朝廷震怒。

首輔在朝會上拍了桌子，原話傳出來是：

> 「天下十三司，司司有探子。**探子與探子互不相識、文書互不相通、卷宗互不可查**。」
>
> 「一案兩查、兩查互毀。這不是探子無能 ── **是朝廷沒有立約**。」

七天後，朝廷設「**驛盟司**」，位在京畿，掌天下驛傳、立諸司互通之約。

尹知行的舉薦信，就是往這裡投的。

---

驛盟司衙門很新，匾上的漆還沒乾透。

司丞叫**溫止**，五十歲上下，瘦，說話極慢，每個字都像算過成本。

「雲書司？」溫止看了一眼舉薦信，「**尹氏雲書司之法**的那個尹？」

「⋯⋯是。」

「你的手冊我讀過。」溫止說，「寫得好。**但解不了揚州的案子**。」

尹知行一愣。

「你的手冊教的是 ── **一個探子怎麼強**。」溫止把舉薦信放下，「目標怎麼立、工具怎麼給、推步怎麼走、圈籠怎麼設。十二章，章章都對。」

「但揚州那兩個探子，**單看哪一個都沒錯**。」溫止說，「漕運司那個，推步乾淨。鹽鐵司那個，圈籠齊全。**兩個都是好探子，加在一起是一場災難**。」

「⋯⋯」

「為什麼？」

尹知行想了很久。

「⋯⋯因為他們**互相看不見**。」他說，「不知道對方是誰、不知道對方在查什麼、查到了什麼。」

「再往下想。」溫止說，「為什麼互相看不見？」

「⋯⋯因為兩司的名冊、文書、卷宗 ── **格式不通、權限不通、語言不通**。」

溫止點頭。

「**諸探（multi-agent）之亂，不在探子，在無約**。」他說，「驛盟司要立的就是這個約。」

「從雜役做起。」溫止說，「**三個月。讓漕運司和鹽鐵司的探子，能合查一案**。做不到，回雲書司。」

---

尹知行領了憑牌，進了驛盟司的文書房。

房裡堆著十三司送來的「樣本」── 每司一箱，裡面是該司的探子文書範例、卷宗格式、任務令樣式。

他抽了漕運司和鹽鐵司的各一份任務令，並排放在案上。

漕運司的任務令：

```
漕字第卅七號
查辦：揚州漕糧虧空事
期：兩月　密級：丙
回報：每旬一報、報總督漕運衙門
```

鹽鐵司的任務令：

```
【鹽鐵密令】
事由＝揚州鹽稅短收
窗口＝60日
等級＝三等密
通聯＝鹽鐵轉運使、五日一聯
```

尹知行盯著這兩張紙。

同樣是任務令。

一個寫「期：兩月」、一個寫「窗口＝60日」。
一個寫「密級：丙」、一個寫「等級＝三等密」── 丙等於三等嗎？**沒人知道**。
一個「每旬一報」、一個「五日一聯」── 頻率不同就算了，「報」跟「聯」是同一件事嗎？

這還只是任務令。後面還有回報格式、卷宗格式、線人登記格式、證據鏈格式⋯⋯

十三司，**十三套互不相認的文書體系**。

---

他想起穿越前的事。

他做過一個專案：讓公司的 AI 探子接上外部工具。每接一個工具，他要寫一套「轉接」── 把工具的介面翻譯成探子看得懂的格式。

三個探子、四個工具，他寫了**十二套轉接**。

三乘四。

後來探子加到五個、工具加到八個 ── 四十套轉接。每改一個工具，五套轉接全要改。

他當時把這個叫 **M×N 問題**：M 個探子、N 個工具（或 N 個司），不立標準的話，要寫 M×N 套轉接。

立了標準，只要 M+N 套 ── 每個探子接一次標準、每個工具接一次標準，**中間全通**。

他那時候沒解掉這個問題，公司就沒了。

兩百年前的這個世界，十三司探子互不相通 ── **同一個問題，連數字都像**。

---

那晚，尹知行在文書房的牆上貼了第一張紙條：

> 揚州的案子，**不是探子之罪，是無約之罪**。

> 十三司互通，不能靠十三司互寫轉接 ── 那是 13×12 條路。

> 要立**一個約**，十三司各接一次 ── 那是 13 條路。

> **約**，比探子重要。

外面遠處傳來打更的聲音。三更。

跟他在藏經閣貼第一張紙條、在商會貼第一張紙條、在雲書司貼第一張紙條的時辰，一樣。

他翻開新的本子，封面寫四個字：

**諸探之約**

---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

丹田裡，練氣三世的根基穩穩托住這道新光 ── 跟練氣時不一樣了，光沉下去的時候，**有東西接住它**。

築基，是在根上起樓。

自此尹知行修為 ── **築基初期・第一重「失約」**。

## 雜役筆記

*尹知行《諸探之約》第一張紙條。*

**▍Multi-agent System（多代理系統 / 諸探）**

多個 agent 各自獨立決策、但要在同一個環境裡協作（或至少不互相破壞）的系統。

單一 agent 的問題（書 3 的主題）：目標、工具、循環、圈籠。
多 agent 的問題（本書的主題）：**互通、協調、仲裁、信任**。

揚州案 = 兩個「單體都正確」的 agent，因為互相不可見而互毀。**Multi-agent 的失敗模式跟單 agent 完全不同**。

**▍M×N Integration Problem**

M 個 AI 應用（探子）要接 N 個工具/資料源（司），逐對寫整合 = M×N 套客製轉接。

- 每個轉接都要維護
- 工具改版 → M 套轉接全要改
- 新工具上線 → 再寫 M 套

解法：**立一個標準協議**。每個應用接一次協議、每個工具接一次協議 → M+N。

這正是 **MCP（Model Context Protocol）** 要解的問題。

**▍MCP（Model Context Protocol，模型上下文協議）**

Anthropic 2024 年 11 月開源的開放協議，定義「AI 應用」跟「資料源/工具」之間的標準介面。

類比：**USB-C**。任何裝置接任何充電器 ── 因為兩邊都實作同一個接口標準。

```
沒有 MCP：
  Claude ↔ 客製轉接 ↔ GitHub
  Claude ↔ 客製轉接 ↔ Slack
  Cursor ↔ 客製轉接 ↔ GitHub   ← 跟上面那套不能共用
  Cursor ↔ 客製轉接 ↔ Slack    ← 又一套

有了 MCP：
  Claude ─┐                ┌─ GitHub MCP server
  Cursor ─┼── MCP 協議 ────┼─ Slack MCP server
  其他 app ─┘               └─ 任何 MCP server
```

寫一次 server，所有支援 MCP 的應用都能用。

**▍Interoperability（互通性）**

兩個獨立系統能交換資訊**且正確理解**對方資訊的能力。

注意「正確理解」：漕運司的「密級：丙」跟鹽鐵司的「三等密」都能被對方**讀到**（交換成功），但**對不上**（理解失敗）。互通 = 傳輸 + 語義兩層都通。

## 這一章你只要記得這三件事

1. **Multi-agent 的失敗跟單 agent 完全不同。** 兩個單體都正確的 agent，互相不可見就會互毀。揚州案的兩個探子都沒錯 ── 錯的是沒有約。
2. **M×N 問題用協議解。** M 個應用 × N 個工具，逐對整合是 M×N 套轉接；立一個標準，變 M+N。
3. **MCP = AI 世界的 USB-C。** 定義 AI 應用與資料源/工具之間的標準介面，寫一次、處處通。

下一章：尹知行要讓漕運司和鹽鐵司的文書互通。第一步不是建驛站 ── 是先讓兩司對「一份任務令該長什麼樣」達成共識。**通文**。
