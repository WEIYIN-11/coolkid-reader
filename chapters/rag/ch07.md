# 第 7 章　譯問

> *練氣初期・第七重「譯問」*

第三十六天，老閣主說的小弟子來了。

他大概十二三歲，個子矮，鼻尖紅。看到尹知行就低頭，看到萬卷盤就更低。

「⋯⋯我師父叫我來。」他說，「他說我學不好。」

尹知行等他繼續說。

他沒繼續說。

尹知行問：「你想學什麼？」

「我想學火。」

「⋯⋯火什麼？」

「就⋯⋯火。」小弟子說，「我不知道。」

尹知行盯著他。

他第一次遇到一個自己用了「氣味、字面、篩選、重判」全套都救不了的問題。

不是書找不到。是問題本身不成立。

「想學火」三個字，可以對應到上千片書。築基的、金丹的、招式的、藥草的、爐火的、心法的，每一個都跟「火」相關。

如果他照常跑流程：

- 氣味查找：抓出 50 片，從築基到結丹什麼都有。
- 胡判：圈不出來，因為沒有一片是這個問題的「真答案」。

問題就是 ── 這個問題沒有「真答案」。

尹知行讓小弟子先回去。

---

那晚尹知行回到桌前，把「想學火」三個字寫在紙上，盯著它。

他想起前世第一次處理這種「弱問題」的時候。

那是某個客服 chatbot 案子。客戶問「我帳戶有問題」、「我登不進去」、「我想退費」。這種問題模糊到 retrieval 全爆。

當時他用了兩招。

第一招，把問題拆開。

「想學火」太大，他可以拆成三個小問題：
- 火屬性的入門是什麼？
- 火屬性常見的起手式有哪些？
- 初學者學火會遇到什麼問題？

每一個小問題分別跑 retrieval，撈出來的答案合在一起，給弟子一份「火屬性入門包」。

第二招，更狡猾。

「想學火」這個問題太短，氣味抓不準。但如果他自己**先寫一段「假設這就是答案」的文字**，再用這段假文字去萬卷盤查 ──

假文字的氣味會比原問題清楚得多。

他在紙上試寫：

> 「初學者欲學火屬性，應先從養氣開始，每日內視火脈，待氣感穩定後方可入起手式。常見起手式為『離火三抱』，其要訣在於⋯⋯」

這段是他編的。他不知道是不是對的。

但這段文字的氣味，**遠比「想學火」三個字精準**。

他拿這段去萬卷盤查。

亮的那一塊區域裡，10 片書，前 3 片就是火屬性入門的標準答案。

---

「⋯⋯」

尹知行盯著萬卷盤亮的區域，半天沒動。

他想起前世讀那篇 paper 的時候 ── HyDE。Hypothetical Document 意向（embeddings）。先讓 LLM 寫一段假答案，用假答案的 意向 去查向量資料庫。論文一頁紙，當時他覺得「這也太狡猾」。

現在他在用木頭和毛筆做一模一樣的事。

---

第三十七天，小弟子又來了。

尹知行讓他坐下。

「你師父叫你來，是因為你『不知道自己想學什麼』。」尹知行說，「不是因為你蠢。是因為你還不會問。」

小弟子點頭。

「我幫你問。」尹知行說，「我把你的問題拆成三個小問題：『火屬性入門』、『火屬性起手式』、『火屬性常見毛病』。三個分別查。」

他跑三遍流程。萬卷盤亮三次，胡判圈三次，最後從九片書裡挑出五片給小弟子。

「五片，每天讀一片。一週後，你來告訴我你想學什麼。」

小弟子緊緊抱著五片書，跑了。

---

第三十八天，沈青又出現。

「我師妹說她想試試你那個『假答案查找法』。」沈青說，「她想問『鳳鳴離火決第五節到底在練什麼』。她讀了三遍都不懂。」

尹知行先寫了一段「假答案」：

> 「鳳鳴離火決第五節，承接前面四節的氣海築底，開始將內氣由氣海引向丹田，過程中需注意⋯⋯」

他用這段去萬卷盤查。

萬卷盤亮的區域裡有一片，是《鳳鳴離火決》第五節的「註本」 ── 鄭子衿之前讀的原本沒有註，這本註本是後來補的，氣味偏「註釋」風格，氣味查找從來沒抓到過。

註本一遞給鄭子衿，她讀完。

「⋯⋯哦。」

跟第二章那個沈青的「哦」一模一樣。

那種「終於懂了」的「哦」。

---

尹知行那天在紙上寫了第八張紙條：

> 問題不好，先翻譯一次再問。

翻譯有兩種：
1. 把大問題拆成幾個小問題，分別查。
2. 把短問題寫成一段「假答案」，用假答案查。

兩種，他都用。

---

第四十天，老閣主出現的時間比平常早。

「藏經閣下個月有個年會。」老人說。

「⋯⋯年會？」

「大長老會來。」老人說，「他每年來一次。每次會問一個問題。沒人答得出來。」

尹知行抬頭。

「您要我答？」

老人看著他。

「不是答。」老人說，「是讓藏經閣答。」

尹知行明白了。

老人要他在大長老面前，不靠自己的記憶、不靠自己的反應，**讓他這套系統自己跑出答案**。

也就是說，他這套東西要能「自己決定下一步」。

自己拆問題。
自己改氣味。
自己挑書。
自己組答案。

不是工具。是一個能動的、能想的東西。

尹知行苦笑。

「⋯⋯閣主，這個事情，我得帶徒弟。」他說，「我自己一個人，搭不出來。」

老人點頭。

「明天，」他說，「我給你一個徒弟。」

---

那晚尹知行在意位圖旁邊空著的第九張紙條位置，畫了一個小人。

那個小人手裡拿著一張紙，紙上寫著「問題」。

小人會走路。會自己跑到萬卷盤、跑到目錄櫃、跑到胡判那裡、再回來。

下面寫了三個字：

> 會動的。

他知道這個方向了。

但在那之前，他得先測試自己現有的東西到底有多準。

如果他連自己的命中率都不知道，他怎麼敢讓「會動的小人」自己跑？



---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **練氣初期・第七重「譯問」**。

## 雜役筆記

*尹知行第八張紙條，旁邊畫了一個小人。*

**▍Query 處理的兩個關鍵動作**

弱問題救不了 retrieval。在 retrieval 之前，先處理 query 本身。

**▍Query Decomposition（拆問題）**

把一個複雜或模糊的問題，拆成幾個具體的子問題，分別查，結果合在一起。例如：

- 「我想學火」→ 「火屬性入門」/「火屬性起手式」/「火屬性常見問題」
- 「比較 A 和 B 的差別」→ 「A 是什麼」/「B 是什麼」/「A 和 B 的差別」

**▍HyDE（Hypothetical Document Embeddings）**

先讓 LLM 寫一段「假答案」（hypothetical document），用這段假答案的 embedding 去做向量檢索。

為什麼有用？短問題的 embedding 跟長答案的 embedding 在語意空間裡常常**離很遠**（一個簡短、一個展開）。假答案在篇幅和風格上**和真答案接近**，embedding 距離更近，命中率提升。

論文：Gao et al., "Precise Zero-Shot Dense Retrieval without Relevance Labels"（2022）。

**▍Query Rewriting（重寫問題）**

另一個流派：用 LLM 把使用者的口語問題改寫成更精準的查詢字串。例如：

- 「我登不進去怎麼辦」→ 「使用者登入失敗的常見原因和處理步驟」

實務上常配合 multi-query：一次生成 3-5 個改寫版本，每個都跑一次 retrieval，結果合併。

**▍什麼時候用哪個？**

| 問題類型 | 用 |
|---|---|
| 太大、太模糊 | Query Decomposition |
| 太短、口語化 | HyDE 或 Query Rewriting |
| 多語言、術語不一致 | Query Rewriting |
| 跨多文件、有比較性質 | Query Decomposition |

通常**先試 query rewriting，再試 HyDE**，最後才考慮 decomposition（最貴）。

## 這一章你只要記得這三件事

1. **弱問題救不了 retrieval。要在 retrieval 之前先處理 query 本身。**
2. **HyDE：先寫一段假答案，用假答案去查真答案。** 短問題突然變得很好查。
3. **Decomposition：把大問題拆成小問題分別查，結果合併。** 模糊的需求變成幾個具體的撈取動作。
