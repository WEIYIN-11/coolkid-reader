# 第 11 章　制法

> *練氣初期・第十一重「制法」*

第一卷結束半年。

藏經閣已經有四個全職判官、八個雜役、兩個專門寫《問答錄》新卷的書記。尹知行不用每天親自報氣味了。

但他發現一件事，比他想像中更頭痛。

四個判官，命中率分別是 89%、84%、81%、73%。

明明做同一份工作，差距怎麼會這麼大。

---

那一週他蹲在後門，看每個判官怎麼工作。

他發現一個現象。

阿土每次拿到問題＋候選片，會先在紙上寫：

> 弟子要問的是 X，候選書 A 講的是 Y，跟 X 的關係是 Z，所以判斷⋯⋯

中間有「想」的過程。

第四個判官 ── 一個叫趙巖的年輕人 ── 直接看完就圈，中間沒寫任何東西。

尹知行問趙巖：「你判斷的時候腦子裡在想什麼？」

「就⋯⋯感覺哪片最像。」

「感覺？」

「感覺。」

尹知行回桌前坐下。

問題不在這四個人的聰明程度。

問題在他**沒有寫一份「判官守則」**。

每個人靠自己的直覺判，直覺好的命中率高，直覺差的低。

---

那晚尹知行寫了第一份《判官守則》。

```
判官守則（草稿）

一、收到問題＋候選書若干片之後，先做三件事：
   1. 用一句話複述「弟子真正想知道什麼」。
   2. 對每一片候選書，標註它「跟弟子要的事」有什麼關係：直接回答／背景知識／不相關。
   3. 排序。理由寫下來。

二、若所有候選都不相關，**不要硬選**。直接回「無命中」。

三、若有兩片候選都直接回答，挑「先講」「概括」的那片排首。
```

他抄了三份，給三個判官（阿土那份省略 ── 他本來就在做了）。

第二天，趙巖的命中率從 73% 升到 84%。

只是因為他在判之前，**先想了一下**。

---

尹知行又發現第二件事。

新判官最常問他：「這種問題我從沒看過，怎麼判？」

每次他都得舉例。「就像當初鄭子衿問鳳鳴離火決第五節那次⋯⋯」

舉例之後對方就懂。

於是他在《判官守則》後面加了三個「範例」：

```
範例一：弟子問「火屬性築基怎麼起手」
        候選五片：
        A. 《離火九轉訣》LH-001（火屬性築基起手式總論）
        B. 《丹陽引氣訣》第三節（火屬性氣口）
        C. 《雷霆斬》第一式（雷屬性招式）
        D. 《離火九轉訣》LH-008（火屬性築基末期）
        E. 《離火九轉訣》LH-001 的註本

        正確排序：A > E > B（D 是末期不對、C 無關）
        理由：A 是直接回答，E 補充說明，B 是相關但側重氣口。

範例二：⋯⋯
範例三：⋯⋯
```

新判官入職第一天，先讀守則加三個範例，再上工。

從此命中率不再忽高忽低。

---

尹知行那晚在《問答錄》新卷的扉頁寫：

> 給每一個會「答」的人，先寫一份指令。

> 指令裡放範例。

> 答案出口前，先要對方「說理由」。

他想起前世做 LLM 應用最早寫的那一堆 訣（prompt）。

最初他的 訣 是「你是一個專業的法律顧問，請回答以下問題」。

效果差。

後來他學會在 訣 裡放 system instruction、few-shot examples、output format、chain-of-thought 指示。

效果天差地遠。

但他當時從來沒對團隊**標準化**這套 訣。每個工程師寫自己的版本，bug 一堆。

現在他在這個世界，**第一次把它制度化了**。

---

第七天，尹知行又發現一個新問題。

某個判官圈出來的「最佳那片」格式不一致。有時候是 LH-005、有時候是「離火九轉訣第五節」、有時候是「左邊第三疊第二片」。

下游的雜役要把判官結果拿去調書，每個格式都得花時間轉換。

他在守則裡加了第四條：

```
四、輸出格式：
   首片：[書名] [章節編號] [尹知行編號]
   次片：同上
   理由：一句話，不超過二十字
```

統一格式之後，下游處理快了三倍。

他想：這就是 structured output 的價值。

---

第十天，趙巖開始反過來幫尹知行修守則。

「尹師兄，」趙巖說，「第二條『不要硬選』寫得太絕對了。有時候候選裡有一片『沾邊』的，比『完全沒命中』更有幫助。」

尹知行想了一下。

「你的意思是 ── 不確定的時候，給弟子一個『相關但不完全是答案』的提示？」

「對。」

「⋯⋯有道理。」

他改：

```
二、若所有候選都不直接回答：
   2a. 有沾邊的，回「未命中，但 X 可能相關」。
   2b. 完全無關，回「無命中」，並標註「建議去 Y 閣求證」。
```

兩天後趙巖的命中率升到 88%。

尹知行看著守則第二條的修訂，覺得這套東西也會自己進化。

---

第十四天，老閣主來桌前坐下。

「四個判官，現在都九成。」老人說。

「守則 + 範例 + 結構化輸出。」尹知行說，「沒什麼神奇的。」

「不神奇。」老人說，「但全宗門有八個閣，七個閣沒寫守則。」

「⋯⋯」

「下個月，」老人說，「我帶你去拜訪劍閣。」

尹知行愣了一下。

劍閣是去年大典禮上那個「劍意問題」的閣 ── 當時藏經閣的把握不到四成、建議去劍閣求證、那位弟子去了之後沒回來告訴尹知行答案、劍閣自己也沒能答出來。

整個門派裡，劍譜整理度最低、判官命中率最差、《問答錄》三年沒更新的，是劍閣。

尹知行明白老人要他做什麼。

「⋯⋯」

「不是去『救』劍閣。」老人說，「是去把你這套東西交給他們。」

尹知行點頭。

那晚他重新整理《判官守則》。

他知道，**寫得清楚的守則，是這個世界第一份「可以複製給別人」的資產**。

書可以借、人可以教、但能讓人**照做就有效**的，是守則。

他在守則的最後一頁寫下一句話：

> 凡寫得清楚的指令，皆是傳承。



---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **練氣初期・第十一重「制法」**。

## 雜役筆記

*尹知行《判官守則》最後一頁的批註。*

**▍Prompt Engineering（提示工程）**

寫好給 LLM 的「指令」。一份好的 prompt 通常包含：

1. **System role**：告訴模型「你是誰、你的任務」
2. **Instructions**：具體要做什麼、不做什麼
3. **Few-shot examples**：給 3-5 個範例
4. **Output format**：規定輸出格式（JSON、Markdown、欄位順序）
5. **Stop conditions**：什麼情況下回「我不知道」
6. **Chain-of-Thought 指示**：要求「先說理由再給答案」

**▍Few-shot Examples（範例）**

給模型 3-5 個「輸入 → 輸出」的範例，模型會模仿格式和邏輯。**對複雜任務效果遠勝純文字描述**。尹知行寫給判官的三個範例，就是 few-shot 的本質。

**▍Chain-of-Thought（思維鏈）**

要求模型「先想再答」。最簡單的版本：在 prompt 結尾加一句 `Let's think step by step.` 或 `先說明你的判斷理由，再給最終答案。` 命中率能提升 10-30%。

**▍Structured Output（結構化輸出）**

規定輸出格式（JSON Schema、固定欄位）。下游程式好處理、判官之間結果一致。OpenAI、Anthropic、Google 都支援「強制結構化輸出」，模型不會亂寫。

**▍Anti-pattern（常見錯誤）**

- *Prompt 太長*：超過 2000 字模型開始忽略中間段落
- *指令矛盾*：「請簡短回答 ⋯⋯ 並詳細解釋每一步」
- *沒給範例*：複雜任務只用文字描述，模型抓不到要點
- *沒設停損*：沒寫「不知道時回 IDK」，模型會硬編

**▍Prompt vs Fine-tuning vs RAG 的選擇**

| 你想做的 | 用 |
|---|---|
| 改變模型「怎麼回答」（風格、格式、語氣） | Prompt Engineering |
| 改變模型「知道什麼」（最新資料、私有資料） | RAG |
| 改變模型「本質的能力」（專業判斷、特殊任務） | Fine-tuning |

## 這一章你只要記得這三件事

1. **沒有寫下來的指令，靠的是直覺；靠直覺的系統，命中率永遠不穩定。**
2. **Prompt 的四件套：role + instructions + few-shot examples + output format。** 缺一個都會掉分。
3. **要求 LLM「先想再答」**（chain-of-thought）。命中率輕鬆 +10%。
