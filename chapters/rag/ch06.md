# 第 6 章　配劑

第二十九天清晨，老閣主說的「複雜問題」來了。

來的人不是弟子，是一個瘦高的青年，腰間掛著一柄半舊的劍。他自報家門：

「我是雷霆殿外門，姓秦，名嶼。」

林知行愣了一下。雷霆殿是門派裡專修雷屬性的，跟藏經閣不熟。

「我師父讓我來借書。」秦嶼說，「題目是 ── 跟雷屬性連用的、火屬性、築基期的引氣訣。」

林知行抄下這句話。

他的工作流現在已經很順：報氣味 → 萬卷盤抓 50 片 → 胡判圈 3 片 → 弟子拿走。

他依樣畫葫蘆。

「火屬性、築基期、引氣訣、跟雷屬性連用。」他在萬卷盤中心報。

木盤亮。

亮的格子裡，他抽出 10 片，掃了一眼。

全是火屬性的引氣訣。

雷屬性，一個字都沒帶到。

---

「⋯⋯」

林知行又報了一次氣味，這次強調「雷屬性」。

木盤亮的區域偏向另一邊，10 片全是雷屬性的招式，沒有引氣訣。

他試了第三次，把所有條件擠在一個氣味裡：「火雷雙屬性、築基期、引氣訣」。

木盤亮的區域非常小，只有 3 片。

抽出來看。一片是《雙屬性入門概論》（太基礎），一片是《雷火合鳴》（談的是金丹期、不是築基期），一片是《引氣三法》（火屬性、但沒提雷）。

三片都不對。

---

林知行盯著萬卷盤。

問題出在「雷屬性連用」這個概念上。

藏經閣裡幾乎沒有專門寫「火屬性 + 雷屬性連用」的書 ── 這是個冷門題目。氣味相近的書都是「單一屬性」的，雙屬性的書非常少。

而那些少數真正寫過「雷火連用」的書，書名可能完全不出現「火屬性」「雷屬性」這幾個字 ── 它們可能叫《祖師雜記》《合鳴小錄》《老兵手札》。氣味會偏向「雜記」「手札」這種風格，不會精準聚到「雙屬性」上。

換句話說：

> 氣味，會被「文體」帶偏。

如果他能直接搜「『雷』和『火』和『引氣』這幾個字同時出現的書」，他就能找到那些字面命中、但氣味偏的書。

可萬卷盤不會搜字。萬卷盤只會搜氣味。

---

林知行走到藏經閣的一樓總目錄。

總目錄是一個老式的索引櫃，裡面是按「書名首字」「屬性」「年代」分類的卡片。三十年沒人翻過，灰塵厚得像氈。

他翻了「雷」字頭、「火」字頭、「引氣」字頭。

三個目錄交集處，有七片書。

七片，全部都是「氣味查不到、但字面命中」的書。

他抽出來，遞給胡判。

胡判看了一眼，圈出一片。

「這片真正回答你問題。」

書叫《雜屬連用札》。

完全是個冷門書名。萬卷盤永遠找不到它。

---

第二十九天下午，秦嶼拿到答案，鞠了個躬走了。

林知行回桌前，貼第七張紙條：

> 氣味找得到「意思像的」，字面找得到「用詞像的」。兩個一起用。

他想起前世第一次學 hybrid search 那一晚。

那天是某個資深 ML 工程師當著全團隊吐槽：「你們以為向量化就能取代 BM25 嗎？BM25 對冷門名詞、人名、產品型號、錯字、code snippet，比 embedding 強百倍。別整天 vector vector vector，加個 BM25 進去 ── 」

當時林知行沒當一回事。

他現在當一回事了。

---

第三十天，鄭子衿又來了。

「我要練『鳳鳴離火決』，從第三節到第七節。」她說，「我需要那本書的『築基期、第三節到第七節』的片。」

林知行報氣味。木盤亮的區域裡有 40 片，胡判圈出來的前 3 片，2 片是「鳳鳴離火決」，但都不是第三到第七節。

「⋯⋯」

林知行盯著萬卷盤。

「鳳鳴離火決」是書名，「築基期」是境界，「第三節到第七節」是位置。

三個都是條件。但萬卷盤只會比「氣味」，它不會「篩」。

他需要在報氣味之前先**篩**：只看「鳳鳴離火決」這本書的、「築基期」的、「第三到第七節」的範圍。

這在他前世叫 metadata filter。

---

林知行那天晚上重新拆每一片書。

不是重拆內容，是重貼標籤。每一片的紙條右上角，加三個欄位：

```
書名：鳳鳴離火決
境界：築基期
章節：第五節
```

然後他改萬卷盤的查詢方式。

下次鄭子衿來，他先在櫃子最上層拉一個橫桿，設定「書名 = 鳳鳴離火決」「境界 = 築基期」「章節 = 第三節 ~ 第七節」。

橫桿一動，萬卷盤上只有符合條件的那一塊區域被照亮。氣味查找只在那塊區域裡跑。

抽出 5 片，全是對的。

胡判圈出前 3，鄭子衿讀完，沒挑出毛病。

---

第三十一天，林知行在意位圖旁邊又貼一張紙：

> 先篩、再查、再排。

三道工序。

先用條件（屬性、境界、章節、年代）篩出候選範圍。
再用氣味在範圍內查 Top-K。
再用胡判判前 3。

那一週，林知行解決的問題數量翻倍。

---

第三十二天的晚上，老閣主再次出現。

他這次坐了下來，跟林知行隔一張桌子。

「你的紙條，」老人說，「已經七張了。」

「七張。」林知行答。

「再過多少天，你會貼第八張？」

林知行愣了一下。

「不知道。」

「會有的。」老人說，「明天會有一個小弟子來，問一個你絕對找不到的問題。不是因為書不在，是因為他不會問。」

說完，老人留下半盞茶，走了。

林知行盯著意位圖。

第八張紙條的位置，他先空出來。

## 雜役筆記

*林知行的第七張紙條，畫了三個箭頭。*

**▍Hybrid Search（混合檢索）**

向量檢索（氣味）+ 關鍵字檢索（字面），兩個都跑、結果合在一起。**冷門名詞、人名、產品代號、罕見書名、錯別字、code snippet** 是向量檢索的死角，關鍵字檢索剛好補上。

**▍BM25**

關鍵字檢索的經典演算法。把文件按「查詢字出現的頻率 + 在整個語料庫的稀有度」打分。**對人名、代號、特殊詞極強，部署簡單**，沒模型沒嵌入。Elasticsearch、Lucene、Tantivy 都內建。

**▍合併方式**

抓 Top-50（向量）+ Top-50（BM25），合起來去重，再丟給 reranker。常用合併打分法叫 **Reciprocal Rank Fusion（RRF）**，把兩個排名各自取倒數加起來，公式簡單、效果好。

**▍Metadata Filter（中介資料篩選）**

每片 chunk 上加結構化標籤（書名、章節、屬性、年代、作者、文件類型）。查詢之前**先用標籤篩出候選範圍**，再在範圍裡跑向量查找。

實務上每個向量資料庫都支援，例如：

```python
# pgvector / Qdrant 風格
collection.search(
  query_embedding,
  filter={"book": "鳳鳴離火決", "stage": "築基期"},
  top_k=10,
)
```

**▍三道工序**

```
Query
  │
  ▼
Metadata filter（先篩範圍）
  │
  ▼
Vector + BM25 hybrid（再查 Top-K）
  │
  ▼
Reranker（再排前 3）
  │
  ▼
LLM Generation
```

林知行第六章建好的，就是這套。

## 這一章你只要記得這三件事

1. **氣味（向量）會被文體帶偏。** 冷門名詞、人名、代號用「字面（BM25）」更穩。兩個一起用叫 hybrid search。
2. **先篩、再查、再排。** Metadata filter 把候選範圍縮小，後面所有計算都更準更快。
3. **這套組合是大部分上線 RAG 系統的標配。** 缺一不可。
