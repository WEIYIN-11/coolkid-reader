# 第 10 章　開壇

第九十二天。

大典禮這天，藏經閣前的大廳裡擠了三百多個弟子。

最前排坐著評議長老 ── 一個瘦瘦的中年人，眼神冷得像冬天的鐵。林知行記得閣主跟他說過，這個人「每年砍掉一個閣」。

林知行站在中央。

他面前是一張案，案上一塊木牌，木牌上是他自己刻的四個字：

> **未知亦答**

「未知」是說明，「亦答」是承諾。

問題答不出來的時候，也要給出一個答覆 ── 那個答覆叫「我不知道」。

---

評議長老開口。

「規則很簡單。」他說，「任何弟子，任何問題，六個時辰。我隨機抽查二十題。準確率低於八成，藏經閣關門。」

林知行行禮。

「請開始。」

---

問題一個一個進來。

「火屬性築基期起手式是哪一招？」
萬卷盤亮、胡判圈、答案出。**對。**

「我師兄叫我練雷霆斬第三式，但我才剛入門，可以嗎？」
拆成兩跳（「雷霆斬第三式適合什麼境界？」+「剛入門能不能練？」），問道童子跑兩圈，答案出。**對。**

「鳳鳴離火決第五節到底在練什麼？」
HyDE 跑一次，註本撈出來，答案出。**對。**

「跟雷屬性連用的火屬性築基期引氣訣？」
Hybrid + metadata filter，《雜屬連用札》撈出來。**對。**

「想學火。」
Query decomposition，三個子問題分別查，回一份「火屬性入門包」。**對。**

連續一個半時辰，林知行答了三十一題。

評議長老沒說話。

---

第三十二題，東西進來了。

「請問藏經閣。」一個比較年長的弟子說，「我師父最近在研究『劍意』的入門，他要我問問藏經閣裡有沒有相關的書。」

「劍意」。

林知行愣了一下。

藏經閣裡的劍譜整理度不到一成。他這三個月主要在處理「心法」「引氣訣」「築基功法」這些主流大類，劍道是另一個閣（劍閣）的事。

但弟子問了。

他照流程跑：報氣味 ──

萬卷盤亮的區域非常小，只有四片，氣味勉強相關。

胡判看了四片，搖頭：「都不對。」

「沒有？」林知行問。

「沒有。」胡判說。

林知行頓了一拍。

---

他抬頭，看著三百個弟子，看著評議長老。

評議長老的眼神比剛才更冷了一點。

林知行對著弟子說：

「**這個問題的答案，藏經閣的把握不到四成。**」

「⋯⋯什麼？」

「我們有四片書勉強相關，但沒有一片真的回答你師父的問題。我不會用四成的把握給你看似肯定的答案。」林知行說，「請去劍閣求證。如果劍閣那邊有確切答案，麻煩您回來告訴我，我把它加進藏經閣的書目，下一個問同樣問題的弟子就不用再走一遭。」

弟子愣了愣。

「⋯⋯謝謝。」他說，「我去。」

弟子退下。

大廳靜了三秒。

然後評議長老笑了。

---

那個笑非常薄、非常短，但林知行看見了。

評議長老站起來。

「藏經閣的『未知亦答』。」他說，「**老子等這四個字，等了二十年。**」

林知行行禮。

「謝長老。」

「準確率不用測了。」評議長老說，「能說『我不確定』的系統，比準確率九成五的系統更可靠。」

說完，評議長老向閣主行禮 ── 是的，這個冷得像鐵的人，向閣主行了禮。

「我這就回去稟報門主。」他說，「藏經閣，續。」

---

那天剩下的四個時辰，問題還是一個一個進來。

林知行答了一百二十八題。

對的，他答。

不確定的，他**老實說不確定**，並且附上「目前撈到最相關的書」當參考、「建議去哪裡求證」當提示。

下午結束，他統計：

- 完整正確：**89%**
- 老實說不確定：**8%**
- 漏掉或答錯：**3%**

89% 比他預期的高。8% 的「老實說不確定」是他預期的，那是他系統有意識保留的緩衝區。3% 的漏掉，是他下個月要修的清單。

評議長老沒等下午結束就走了。走之前留了一句話：

「年輕人，**你這套東西最值錢的，不是答得多準，是你知道你不確定什麼**。」

林知行覺得這句話可以裱起來。

---

夜裡，林知行回到藏經閣最底層的萬卷盤大廳。

老閣主已經在那裡了，坐在木盤旁邊一張椅子上。

「林知行。」老人說，「過來。」

林知行走過去。

「九十二天前，」老人說，「你問我『會的話』，我說會。然後我把《問答錄》塞給你。」

「⋯⋯記得。」

「你知道為什麼我那天塞給你？」

林知行搖頭。

老人看著木盤。

「我七十二歲那年，」老人說，「上一任閣主死了。沒留下完整的繼承人。藏經閣的書幾百年來只有兩個人能管 ── 一個是閣主，一個是閣主的徒弟。我沒徒弟。」

「⋯⋯」

「我以為這就完了。」老人說，「直到那天你出現在書架後面，眼睛亮得不像個雜役。我聽你跟自己說話，你說『chief retrieval officer』。」

林知行笑了一下。

「我那時候連這個世界的字都不確定能看懂。」他說。

「但你已經在想『系統』。」老人說，「我認識七代閣主。沒有一個人在第一天就想系統。他們想的都是『要背多少書才能當上閣主』。」

老人停了一下。

「林知行，」他說，「從明天起，你是藏經閣首席檢索官。閣主之位，你準備好的時候，自然會接過去。」

林知行愣住。

「我⋯⋯」

「不用回答今天。」老人說，「你還有時間。藏經閣也還有時間。」

---

老人起身慢慢走。

走到大廳門口的時候，他停了一下。

「對了。」他說，「萬卷盤最深處有一格，從我接手到現在，從沒打開過。你哪天有空，去看看。」

說完，老人走了。

林知行站在中心，看著木盤。

他走過去，找老人說的那一格。

那一格在木盤最內圈最角落，有一塊薄薄的木板蓋著。

他掀開。

裡面是一片書，紙已經舊到一碰就碎。

紙上是這個世界的字，林知行能讀。

紙上寫著：

> 凡欲問道者，先問自己問題對不對。
>
> 凡欲答道者，先答自己「我不知道」這四個字。
>
> 此兩者，藏經之根。

林知行盯著這幾行字，盯了很久。

他笑出聲。

「⋯⋯七代之前的閣主，」他自言自語，「您也是被人 demo 翻車過嗎？」

---

那天晚上，林知行最後一次走過藏經閣。

從一樓的總目錄，二樓三樓四樓的書架，五樓的孤本，六樓的閣主居所，到地下的萬卷盤。

他每一層都停了一下。

意位圖的牆上，現在貼了二十七張紙條。他自己加的還有：

> 十一、漏掉答案的時候，要老實說漏掉。
>
> 十二、別把使用者當笨蛋，但也別把系統當聖人。
>
> 十三、能說「我不知道」的東西，比聲稱「我什麼都知道」的東西，可靠十倍。
>
> ⋯⋯

他走到桌前坐下。

打開新的一卷《問答錄》 ── 這次是他自己整理的，按主題分卷、按頻率排序、每一條後面附上「對應書目」「對應 chunk」「確信度」「最後核對日」。

第一條他自己寫：

> 問：藏經閣最厲害的法門是什麼？
>
> 答：「先問自己問題對不對。」這比任何一本書都重要。

他放下毛筆。

阿土跑進來：「林師兄！黃金到了！還有 ──」

林知行抬頭笑。

「阿土，明天起，**你是副閣主了**。」

阿土愣住，「啊？」

「你今天早上跑的測試集，我看了。」林知行說，「Recall 已經跟我一樣。明天起，你負責白天問答。我做下一步。」

「⋯⋯下一步是什麼？」

林知行看著意位圖上空著的最後一張紙條的位置。

「**讓藏經閣自己進化**。」他說，「我們現在是『回答』，下一步要『學習』。每一次有人問問題、每一次胡判圈錯一片、每一次我們老實說『我不確定』，都要回流到萬卷盤裡，**讓系統自己變聰明**。」

阿土沒聽懂。

林知行笑了。

「以後你會懂的。」

---

那晚他做了一個夢。

夢裡他回到前世那間會議室。

凌晨兩點。電腦螢幕亮著「Retrieval failed: 0 documents found.」。

但這一次，他不再覺得這行字像喪鐘。

他打開新的視窗，開始寫測試集、寫評估腳本、寫 hybrid search、寫 reranker、寫 query rewriting、寫 agent、寫 monitoring、寫「我不知道」的判斷邏輯。

寫到天亮。

醒來的時候，他在藏經閣的草蓆上。

外面有第一聲鳥叫。

新的一天，三百個弟子又要進來問問題。

林知行翻身坐起。

他笑了一下，伸手摸了摸枕邊那本厚得能砸死人的《問答錄》。

「⋯⋯今天，繼續迭代。」

---

**（林知行的 RAG 修行錄．第一卷完）**

## 雜役筆記

*林知行最後一張紙條，貼在意位圖最上方。*

**▍上線之後才是真正的開始**

實驗室裡 87% 的 Recall，上線之後可能變 70%。原因：

- *分布外問題*（OOD）：使用者問的問題類型跟測試集不一樣
- *資料漂移*：新文件進來、舊文件改了
- *模型漂移*：LLM 版本更新，行為變了
- *Adversarial queries*：使用者刻意試探系統邊界

**▍上線後一定要做的事**

1. **Observability（觀測）**：每一次 retrieval 都記下來，誰問的、撈了什麼、回了什麼、使用者滿意嗎。工具：Langfuse、Phoenix、Helicone。

2. **回饋迴圈（Feedback Loop）**：使用者點「沒幫到我」的問題，收集起來，補進測試集。每週重跑一次評估。

3. **A/B testing**：任何 pipeline 改動（新 embedding 模型、新 reranker、新 chunk 策略）都跟舊版同時跑、比指標、再決定切換。

4. **Cost monitoring**：每一個 query 多少錢？哪些 query 花得不值？OpenAI 帳單炸掉的故事每週都在發生。

**▍最重要：「我不知道」的能力（Abstention）**

讓系統在不確定的時候**老實說不確定**，而不是用流暢的語氣編一段假答案。實作方式：

- **Retrieval-based abstention**：撈出來的 Top-K 全部跟問題的相似度低於某個閾值 → 直接回「找不到」。
- **LLM-based abstention**：在 prompt 裡明確告訴 LLM「如果 context 裡沒有答案，回 `INSUFFICIENT_CONTEXT`」。
- **Confidence calibration**：訓練模型自己評估「這個答案有幾成把握」，低於閾值就 abstain。

**▍為什麼這比準確率還重要**

一個準確率 95% 的系統，每 20 個答案有 1 個錯。**使用者不知道是哪 1 個。** 整個系統的信任度被那 1 個錯的答案拖垮。

一個準確率 89% 的系統，但能對 8% 的不確定老實說「我不確定」 → 使用者每一次拿到肯定答案都可以信。**信任度遠高於前者**。

第 1 章林知行掛掉的那個 demo，95% 準確率。掛在那 5%。
第 10 章林知行通過的這個大典禮，89% 準確率 + 8% 老實說不知道。通過了。

**▍持續學習（Continuous Learning）**

每一次「不確定」的問題，就是下一輪改善的素材：

```
使用者問題（系統說不確定）
   │
   ▼
人工標註正確答案 / 補進新文件
   │
   ▼
更新知識庫、重算 embedding
   │
   ▼
跑回歸測試（舊題目不要掉）
   │
   ▼
上線新版
```

這個迴圈跑得越快，系統進化越快。林知行最後說「讓藏經閣自己進化」，就是這件事。

## 這一章你只要記得這三件事

1. **準確率不是 RAG 的終點，「能說我不知道」才是。** 一個會 abstain 的系統，比一個總是給肯定答案的系統可靠十倍。
2. **上線之後才是真正的開始。** Observability、回饋迴圈、A/B test、cost monitoring，缺一不可。
3. **持續學習是 RAG 的長期複利。** 每一個「不確定」的問題都是改善素材；每一次回饋都餵回知識庫。系統會越用越聰明。

---

**第一卷完。**

林知行從一個會議室的喪鐘，走到藏經閣的首席檢索官。十章下來，你跟著他建好了一個完整的 RAG 系統：

```
拆書（Chunking）
   │
識意（Embedding）
   │
萬卷盤（Vector DB）
   │
重判（Reranker）
   │
配劑（Hybrid Search + Metadata Filter）
   │
譯問（Query Rewriting + HyDE）
   │
拷問（Evaluation）
   │
連環問（Agentic RAG）
   │
未知亦答（Abstention + Continuous Learning）
```

從今天起，每次有人跟你說「我們做個 AI 幫我答這些」，你心裡都會浮現林知行的那十張紙條。
