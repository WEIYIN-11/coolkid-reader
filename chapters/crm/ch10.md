# 第 10 章　析數

第二百六十天，屠東家把陸瀚叫到正廳。

正廳很大、很冷。

屠東家坐在主位，旁邊是兩個分舵主（裴遠、北郡分舵主**沈兆**）、後面是錄事司丞和財房使。

「**陸瀚**。」屠東家說，「**你的五本書（人錄、商號錄、事錄、拍錄、通籙）已經跑了快九個月**。」

「⋯⋯是。」

「**今天我有四個問題**。」屠東家說，「**你給我答案。每個問題的答案，我要從你的書裡能算出來**。」

陸瀚點頭。

「**第一**：今年下半年，全商會能收多少錢？」

「**第二**：南郡和北郡，哪邊成交率高？高多少？為什麼？」

「**第三**：鄭三郎這個客戶，我跟還是不跟？」

「**第四**：我們失去的單，**最常死在什麼地方**？」

屠東家停了。

「**這四個問題，是我每個月都要知道的**。」屠東家說，「**你寫了五本書，這四個問題如果答不出來，那五本書就是擺設**。」

---

陸瀚回到錄事司。

他坐在桌前，把四個問題抄到牆上。

他想：

> 五本書是「**原料**」。

> 屠東家的四個問題是「**菜**」。

> 中間缺一個「**廚房**」 ── 從原料變菜的地方。

他翻開《記事手冊》第十章空白頁。

封面五個字：

**算盤台**

---

陸瀚先處理**第一題：下半年能收多少**。

這題第五章他已經做過。

```
weighted forecast = Σ (deal.amount × deal.stage_probability)
```

但這次屠東家要的是「下半年」 ── 預計成交日在七月到十二月之間的 deal。

陸瀚加上時間篩選：

```
SELECT SUM(amount × stage_probability)
FROM deals
WHERE expected_close BETWEEN '宣化二年七月' AND '宣化二年十二月'
  AND stage NOT IN ('完結', '流失')
```

跑出來：**約 23,500 兩**。

但陸瀚知道這個數有偏誤。

「**stage_probability**」是他**個人推測的**。實務上：

```
真實的 stage probability 應該從「過去成交歷史」反推：

  過去 12 個月在「議價」階段的 deal 共有多少筆？
  其中多少筆最後變成「完結」？
  → 議價 → 完結的歷史比率
```

陸瀚跑了過去 12 個月：

```
歷史 stage probability：
  探詢 → 完結   18%  （原本他猜 20%）
  報價 → 完結   38%  （原本猜 40%）
  議價 → 完結   62%  （原本猜 60%）
  立契 → 完結   88%  （原本猜 85%）
  履約 → 完結   96%  （原本猜 95%）
```

差不多，但**有些階段他猜得偏樂觀**。

用真實數字重算下半年預測：**21,800 兩**。

比他原本猜得少 1700 兩。

「**這 1700 兩**」 = 他過去三個月做的決策**多花的、不該花的成本**。

---

陸瀚處理**第二題：哪邊成交率高、為什麼**。

這題涉及「**漏斗轉化分析**」。

他把南郡、北郡各自過去半年的 deal 漏斗畫出來：

```
南郡：
  探詢 100 → 報價 80 → 議價 45 → 立契 22 → 完結 18
  轉化率（步進）：80%、56%、49%、82%

北郡：
  探詢 100 → 報價 85 → 議價 60 → 立契 50 → 完結 42
  轉化率（步進）：85%、71%、83%、84%

整體成交率：
  南郡：18%（探詢 → 完結）
  北郡：42%
```

差距巨大。

陸瀚看哪個階段差最多：

```
探詢 → 報價：南 80% vs 北 85%   ── 差 5%
報價 → 議價：南 56% vs 北 71%   ── 差 15%   ← 關鍵
議價 → 立契：南 49% vs 北 83%   ── 差 34%   ← 最關鍵
立契 → 完結：南 82% vs 北 84%   ── 差 2%
```

南郡死在「**議價 → 立契**」這一步。北郡同期 83%，南郡只有 49%。

陸瀚翻南郡所有「**議價→流失**」的 deal，看流失原因。

```
南郡 議價階段流失 23 筆：
  價格太高：17 筆
  對手便宜：4 筆
  時機不對：2 筆
```

17 筆「**價格太高**」。

陸瀚看南郡 deal 平均報價，比北郡高 18%。

「**南郡報價偏高 → 客戶議價不成 → 流失**」。

陸瀚把分析寫成一頁：

```
分析報告：南郡 vs 北郡成交率

主因：南郡死在「議價」階段（49% vs 北郡 83%）
根因：南郡報價平均比北郡高 18%
建議：
  1. 南郡報價策略檢討
  2. 南郡分舵主跟北郡分舵主交流定價邏輯
  3. 南郡 17 筆「價格太高」失單的客戶，回訪詢問
```

陸瀚交給屠東家。

---

第三題：**鄭三郎這個客戶，跟還是不跟**？

陸瀚翻鄭三郎的紀錄。

```
Contact #312 鄭三郎
所屬商號（通籙）：
  中州藥材行
  鄭家布行（已暫停營業）
  三和仲介
  
與他相關的 deal：
  D-013 中州藥材 800 兩 → 完結
  D-026 三和仲介 200 兩 → 完結
  D-041 鄭家布行 1200 兩 → 流失（時機不對）
  D-068 中州藥材 1500 兩 → 議價中
  D-072 三和仲介 300 兩 → 探詢中

完結金額：1000 兩
進行中加權預期：1500 × 0.62 + 300 × 0.18 = 984 兩
未來預期年成交：~2500 兩

維護成本：
  過去 12 個月 activity 共 47 條
  涉及內部時間：估算 18 工作時
  
ROI（粗算）：
  收益（年化）2500 兩
  成本 18 時 × 標準計時 5 兩 = 90 兩
  毛利率：(2500 - 90) / 2500 = 96%
```

陸瀚總結：

```
鄭三郎結論：
  收益佳（年化 2500 兩）
  維護成本低（96% 毛利）
  關係穩定（連續成交多筆，未流失原因不是「不爽我們」）
  → 建議：繼續跟、列為「重點客戶」
  → 加標籤「VIP」、未來 deal 自動指派給高階分舵主
```

---

第四題：**失去的單，最常死在什麼地方**？

陸瀚跑全商會過去 12 個月**流失的 deal**：

```
過去 12 個月流失 deal 共 187 筆
總金額（如果成交）約 95,000 兩

流失階段分布：
  探詢階段流失：62 筆 (33%)
  報價階段流失：48 筆 (26%)
  議價階段流失：54 筆 (29%)
  立契階段流失：18 筆 (10%)
  履約階段流失：5 筆 (3%)

流失原因分布：
  價格太高：63 筆 (34%)
  對手便宜：41 筆 (22%)
  時機不對：35 筆 (19%)
  找錯人：18 筆 (10%)
  我方反應太慢：14 筆 (7%)
  其他：16 筆 (9%)
```

陸瀚把 deal value × loss rate 做加權：

```
按「失去金額」排序的流失原因：
  價格太高：失去 32,000 兩
  對手便宜：失去 21,000 兩
  時機不對：失去 18,000 兩
  ...
```

「**價格**」相關的兩項加起來，**失去 53,000 兩 = 全商會流失總金額的 56%**。

陸瀚寫結論：

```
第四題答案：

過去 12 個月，全商會失去最多金額的根因是「定價問題」。
其中：
  - 我方報價過高（32,000 兩）：南郡尤其嚴重
  - 對手便宜（21,000 兩）：競品研究不足

建議：
  1. 全商會建立統一定價基準
  2. 設立競品價格追蹤機制
  3. 議價階段拉長一週（給雜役更多空間調價）
```

---

陸瀚把四題答案併成一份《析數冊》，呈給屠東家。

屠東家看了大概一個時辰。

「⋯⋯**陸瀚**。」屠東家說，「**我做這個商會三十年，第一次有人能告訴我「失去了多少錢」和「為什麼失去」**。」

「⋯⋯」

「**這個算盤台，每個月一份**。」屠東家說，「**全分舵主必看**。」

「是。」

屠東家走的時候停了一下。

「⋯⋯**這套東西**。」他說，「**讓商會看見之前看不見的東西**。**這比把錢拿到手還重要**。」

陸瀚行禮。

---

那晚陸瀚寫《記事手冊》第十章末尾：

> **CRM 的數值分析的本質：**

> **從「我們發生了什麼」推到「為什麼發生」**。

> **不是「給更多數字」，是「給更好的決策」**。

> 數字漂亮沒用 ── **能改變動作的數字才有用**。

下一章他要處理：**裴遠西郡分舵主能看全西郡的客戶資料嗎？北郡的呢？普通雜役只能看自己負責的？人錄裡有些客戶的「健康狀況」「家庭關係」這種敏感資訊，誰能看**？

那是**護密**。

## 雜役筆記

*陸瀚《記事手冊》第十章 ──「算盤台」的關鍵指標。*

**▍CRM Analytics（數值分析 / 析數）**

從 CRM 累積的資料裡看出規律、看出問題、看出機會。不是「畫漂亮的儀表板」，是「**讓決策有依據**」。

**▍最常用的指標**

**漏斗 / 轉化率（Conversion Rate）**
每階段「進到下一階段」的比例。死在哪一步、改善哪一步。

**勝率 / 成交率（Win Rate）**
所有結案 deal 裡，多少筆是「贏」（完結）：
```
Win Rate = Closed Won / (Closed Won + Closed Lost)
```

**銷售週期（Sales Cycle）**
平均從第一次接觸到完結要多少天。**縮短銷售週期 = sales velocity 提高**。

**客戶終身價值（LTV，Lifetime Value）**
一個客戶從第一次成交到「不再回頭」期間，總共為公司賺多少：
```
LTV = 平均每筆 deal 金額 × 每年成交次數 × 客戶留存年數
```

**客戶獲取成本（CAC，Customer Acquisition Cost）**
獲得一個新客戶花了多少錢（行銷費、業務員時間、demo 成本）：
```
CAC = (行銷支出 + 業務支出) / 新客戶數
```

**LTV / CAC 比**
SaaS 黃金指標。**LTV / CAC ≥ 3 表示健康**、≥ 5 表示優秀。

**▍流失分析（Churn Analysis）**

陸瀚的第四題。

對 B2B 是「**客戶今年不續約了**」。對 B2C 是「**客戶不再回購了**」。

要看：
- *Churn Rate*：每月/每年流失比例
- *Churn Reason*：為什麼流失（價格、產品不夠好、服務差、競品搶）
- *At-risk Score*：哪些客戶接下來可能流失（活躍度降、客訴增、付款延遲）

**▍Cohort Analysis（同期群分析）**

把客戶按「**第一次成交月份**」分組，看每組接下來的行為。

例：
```
2026 年 1 月新成交 100 個客戶 → 6 個月後還活著 85 個
2026 年 2 月新成交 120 個客戶 → 6 個月後還活著 102 個
2026 年 3 月新成交 95 個客戶  → 6 個月後還活著 75 個
```

3 月那群明顯比較差 → 為什麼？產品變化？市場變化？

**Cohort 是 SaaS 必看**。

**▍RFM Analysis（最近性、頻率、金額）**

客戶分層的經典方法：

- **R**ecency：最後一次成交距今多久
- **F**requency：過去一段時間成交幾次
- **M**onetary：累計花了多少

```
高 R / 高 F / 高 M = 鐵粉 VIP
低 R / 高 F / 高 M = 流失預警的高價值客戶
高 R / 低 F / 低 M = 新客，需要培養
```

陸瀚分析「鄭三郎」用的就是類似邏輯。

**▍Lead Scoring（線索打分）**

新進線索（lead）「**值得多少跟進力氣**」的分數。

常用維度：
- 公司規模、產業
- 職稱（決策者 +5、執行者 +1）
- 來源（介紹 +10、官網 +3、廣告 +1）
- 互動行為（讀過 demo +5、回過信 +3、open email +1）

分數高的優先跟進、分數低的丟自動化培養（nurture）。

**▍Reporting Tool（報表工具）**

- *內建*：HubSpot、Salesforce、Pipedrive 都有 dashboard
- *BI 工具*：Tableau、Looker、PowerBI、Metabase（開源）
- *Reverse ETL*：Hightouch、Census ── 把 CRM 資料推到 BI / data warehouse
- *SQL on warehouse*：Snowflake / BigQuery + dbt

**核心原則**：先想清楚要看哪些「**能改變動作的指標**」，再選工具。**先有問題，才有工具**。

**▍最常見的反面教材**

> 「**我們公司導入了高大上的 BI dashboard，**有 47 個指標**」。

47 個指標 → 沒人看 → dashboard 上線兩週變成裝飾。

**3-5 個指標**，每天/每週看，連動到具體決策，才是有效的 analytics。陸瀚給屠東家的就是四題，不是 47 個。

## 這一章你只要記得這三件事

1. **CRM analytics 的本質：給「能改變動作的決策」依據。** 不是給更多數字。
2. **黃金指標：Conversion Rate（漏斗）、Win Rate、Sales Cycle、LTV、CAC、Churn Rate。** 其他都是輔助。
3. **3-5 個指標每週看一次 >> 47 個指標放著生灰。** 太多指標等於沒指標。
