# 第 5 章　重判

第二十一天。

鄭子衿那句「前三片看起來都對，但只有第三片真的回答我」，林知行記了一週。

他試了三種辦法。

第一種：把 Top-K 從 10 降到 3，希望前 3 名直接命中。結果：前 3 名常常不是真答案。萬卷盤的「氣味相近」抓出來的前 3，跟弟子想要的答案，永遠差一截。

第二種：要求弟子問得更精準。結果：弟子問得精準了，林知行自己也精準了，但小毛頭和新入門的弟子根本不會用「築基初期、火屬性、起手式」這種精準語言。

第三種，是他真正想要的。

把萬卷盤撈出來的 50 片，**全部跟弟子的問題擺在一起，重新看一遍**，重新排序。

問題是 ── 林知行一個人做不來。每天弟子三十多個問題，每個問題重排 50 片，他得讀一千五百片。一天根本不夠用。

他需要找一個人。

---

藏經閣後門有個老頭。

每天蹲在後門曬太陽，沒人理他。林知行每天進出，遠遠看他一眼。聽說他叫**胡判**，年輕時候是門派的「閱卷使」，三十年前因為一件案子退下來，後來就一直曬太陽。

第二十二天，林知行端了一碗湯給胡判。

胡判抬眼。眼睛很濁，看人的時候卻像在看一張寫滿字的紙。

「你想問什麼？」

林知行愣了一下，沒料到對方這麼直接。

「我把問題和答案各五十條擺一起，您能不能告訴我，哪一條真的回答這個問題？」

胡判看他。

「擺一起？」

「對。」林知行掏出他事先準備的紙條，「問題寫上面，下面五十條候選答案。您只要圈出真的答中的那幾條。」

胡判接過。看了一眼，又抬眼看林知行。

「你萬卷盤抓的？」

「對。」

「萬卷盤只能告訴你『氣味近』。」胡判說，「氣味近的，不一定中。」

「⋯⋯所以我來找您。」

胡判沉默了很久。

「一張紙條一個銅板。」他說，「我這把年紀，不接太多。一天最多五十張。」

林知行差點當場下跪。

---

第二十三天，林知行的工作流變成這樣。

弟子來問問題 → 他到萬卷盤抓 Top-50 → 把問題和 50 片寫在一張紙條上 → 跑到後門給胡判 → 胡判圈出真正命中的 3 片 → 林知行回藏經閣，把那 3 片給弟子。

效率沒慢。萬卷盤抓 50 片只要一刻鐘，胡判判一張紙條只要半刻鐘。比林知行自己讀 50 片快五倍。

更重要的是 ── **判得準**。

鄭子衿第二次來，問了類似的問題。林知行報氣味抓 50，胡判圈出 3 片。鄭子衿讀完，這次沒挑出毛病。

第三天，弟子們開始排隊。

---

第二十五天，沈青問了一個問題：

「胡判跟萬卷盤，到底差別在哪？」

林知行那天晚上回家想了很久。

第二天，他寫了一張紙條，貼在意位圖旁邊：

> 萬卷盤一次只看一片書，看它「跟問題像不像」。
>
> 胡判把「問題」和「答案」擺在一起看，判斷「答案有沒有真的回答這個問題」。

兩個都是判「相關」。但角度不一樣。

萬卷盤看的是**氣味**。它把每片書都翻譯成一組座標，問題也翻成座標，比距離。每片書只需要算一次氣味，永遠不會變。所以快，所以能在百萬片裡瞬間撈出 50 片。

胡判看的是**意思的對接**。他不算座標，他直接把問題和答案放在一起，看這個答案能不能回應這個問題。所以慢，所以一天只能判 50 張。

兩個合起來，**先萬卷盤撈 50 片（粗篩），再胡判排前 3（細排）**，速度跟準度都顧到。

林知行管胡判這個動作叫 ── **重判**。

---

第二十七天，胡判破天荒地多說了一句話。

「你給我的這些紙條，」胡判說，「一半都不是好問題。」

「⋯⋯什麼意思？」

「弟子寫的問題太短，太散。」胡判說，「就比如剛剛這張：『我想學火』。誰知道他要學起手式、想學招式、還是想學煉丹？我不是不能判，我是判得多餘。」

林知行愣住。

他知道胡判說的是什麼。

問題本身需要先處理。

如果弟子的問題太模糊，後面再多的 retrieval 和重判都救不了。

但這已經是下一章的事了。

---

第二十八天，胡判圈出的 3 片，弟子滿意走人。

林知行坐回桌前，把這一週的工作畫成圖。

```
弟子問題
   │
   ▼
萬卷盤（氣味查找） → 50 片
   │
   ▼
胡判（問題＋答案擺一起判）→ 3 片
   │
   ▼
弟子讀
```

兩階段。先粗、再細。

他想起前世第一次學 reranker 的那天。教他的工程師說了一句話：

> Embedding 永遠在算「一邊一邊」，cross-encoder 在算「兩邊放一起」。

當時他不懂。

他現在懂了。

---

那晚，老閣主又出現。

「弟子滿意了。」老人說。

「胡判幫的忙。」

「胡判判得好。」老人點頭，「但你帶他來的。」

林知行沒接話。

老人看了他一會。

「明天，」老人說，「會有一個複雜的問題進來。我不告訴你是什麼。你照常做。」

說完走了。

林知行知道，這是老人在測試。

他抬頭看意位圖、看萬卷盤、看胡判每天圈紙條的後門 ── 這三個東西連在一起，已經能處理八成的問題。

剩下兩成的問題，他現在還救不了。

不是 retrieval 的問題。

是問題本身的問題。

## 雜役筆記

*林知行貼在後門牆上的第六張紙條。*

**▍Reranker（重排序器）**

把向量資料庫撈出來的 Top-K 結果，重新打分排序的模型。它讀的是「問題 + 一份候選文件」，輸出「這份文件回答這個問題的相關度」。比 embedding 慢，但**判得準**。

**▍Bi-encoder vs Cross-encoder**

- *Bi-encoder（萬卷盤）*：問題和文件分別算 embedding，比距離。
  - 文件的 embedding 可以**提前算好存著**，查詢時超快。
  - 用於**檢索（retrieval）**。
- *Cross-encoder（胡判）*：問題和文件**拼在一起**送進模型，輸出一個分數。
  - 每次查詢都要重算，慢。
  - 用於**重排序（reranking）**。

**▍兩階段檢索（Two-stage Retrieval）**

幾乎所有正式上線的 RAG 系統都用這套：

```
Query
  │
  ▼
Bi-encoder + Vector DB → Top-50（粗篩，快）
  │
  ▼
Cross-encoder Reranker → Top-3（細排，準）
  │
  ▼
LLM Generation
```

**▍實務上常用的 reranker**

- *Cohere Rerank*：API、好用、多語言。
- *bge-reranker-large*：開源、中文友善。
- *jina-reranker-v2*：輕量、速度快。

**▍為什麼不直接用 reranker 跑整個資料庫？**

因為太慢。Reranker 對百萬片書要算百萬次，一個查詢得跑十分鐘。Bi-encoder 撈 50 片，reranker 只算 50 次，整體還是毫秒級。

## 這一章你只要記得這三件事

1. **氣味近 ≠ 答案對。** 向量檢索抓的是相近的一批，「真正回答這個問題」要再判一次。
2. **兩階段檢索：先粗篩、再細排。** Bi-encoder 撈 50 片（快），Cross-encoder reranker 排前 3（準）。
3. **Reranker 不會用來查整個資料庫。** 太慢。它只判 retrieval 撈出來的那幾十片。

下一章：弟子問「跟雷屬性連用的火屬性築基期引氣訣」，氣味抓不到、字面也抓不到。要兩個一起用。
