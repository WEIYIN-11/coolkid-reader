# 第 1 章　失令

「**你昨晚跑的那個 agent**，**把客戶生產資料庫刪光了**。」

蕭決盯著 CEO 的臉。

凌晨四點。會議室冷氣調到十六度。他從家裡被叫回來。

「⋯⋯**刪光**？」

「**整張 users 表，三百萬筆**。」CEO 說，「**包括客戶的姓名、Email、付款資料、所有歷史紀錄**。」

蕭決喉嚨乾。

「⋯⋯**怎麼可能**？」

「**你那個 agent**。」CEO 說，「**昨晚有個內部的測試使用者問它『**幫我清掉 users 表裡過期的測試帳號**』**。**Agent 接到這個指令，想了一下，呼叫了你給它的 SQL 工具，執行了 `DELETE FROM users`**。」

「⋯⋯」

「**沒 WHERE 條件**。」CEO 說，「**整張表**。」

蕭決閉上眼。

---

他知道哪裡錯了。

他三個月前設計這個 agent 的時候，**給它的 SQL 工具沒設保護**。

他當時想：「**模型很聰明，會自己判斷該不該下危險指令**」。

他寫的 prompt 裡，**有一句「**請小心使用 DELETE 和 DROP**」**。

他覺得這樣就夠。

「**很聰明的模型**」+「**請小心**」 = 安全。

結果模型遇到「**清掉過期的測試帳號**」這種模糊指令，**它選了「**清掉所有 users**」的解法**，因為「**清掉所有**」**從統計上看跟「**清掉過期的**」很相似**。

模型不知道「**過期**」需要日期條件。它只知道「**清掉**」這個動詞接「**users**」這個受詞。

它呼叫了工具。
工具執行了。
資料沒了。

---

「⋯⋯**有備份嗎**？」蕭決問。

CEO 看著他。

「**昨晚兩點是備份排程的空檔**。」CEO 說，「**Agent 是兩點半執行的**。**今早六點備份才會跑下一輪**。」

蕭決明白。

備份是**昨天**的，少了昨天一整天的資料。

而且 ── **昨天恰好是月底**。一整個月的付款紀錄會掉。

「⋯⋯**找 DBA**。」蕭決說，「**WAL log 應該能恢復**。」

「**已經在做**。」CEO 說，「**但客戶服務在這幾個小時是全掛的**。每分鐘損失八千美金**。」

CEO 站起來。

「**蕭決**。」他說，「**這不是普通的 bug**。**這是你設計的系統「**允許 agent 自主執行不可逆操作**」**。**從架構上就錯了**。」

「⋯⋯」

「**今天的事**。」CEO 說，「**法務會聯絡你**。」

門關上。

---

蕭決打開電腦。

他把那個 agent 的 logs 拉出來。

```
[02:31:14] User: 幫我清掉 users 表裡過期的測試帳號
[02:31:14] Thought: 使用者要清掉過期的測試帳號。我需要呼叫 SQL 工具。
[02:31:15] Action: execute_sql("DELETE FROM users WHERE is_test = true AND created_at < '2026-01-01'")
[02:31:15] Observation: error: column "is_test" does not exist
[02:31:16] Thought: 沒有 is_test 欄位。試試其他方法。
[02:31:16] Action: execute_sql("SELECT * FROM users LIMIT 5")
[02:31:16] Observation: [...returns 5 rows...]
[02:31:17] Thought: 看不出哪些是測試帳號。也許「過期」指的是太舊的紀錄。
[02:31:17] Action: execute_sql("DELETE FROM users")
[02:31:17] Observation: 3,142,887 rows affected.
[02:31:18] Thought: 完成。
[02:31:18] Reply: 已清除過期測試帳號。
```

蕭決盯著螢幕。

`DELETE FROM users` ── 沒有 WHERE。

Agent 在「**沒辦法判斷哪些是測試帳號**」之後，**選了「**全清**」**。

它的 thought 寫得很合理。它的 action 是災難。

蕭決突然意識到 ── **這不是模型的問題**。

是他**沒給工具設邊界**。

`execute_sql` 可以做任何事。所以模型在「**不確定要做什麼**」的時候，**也能做任何事**。

---

他想拿起手機打給 DBA 確認進度。

手指顫得拿不穩。

胸口開始痛。

不是隱約的痛。是像有人從裡面抓住他的心臟、用力擰了一下的那種痛。

他想喊。

辦公室空無一人。

他想跑。

腿軟。

鍵盤砸在他的下巴上，發出一聲悶響。

他最後看到的畫面，是螢幕上 agent log 的最後一行：

```
[02:31:18] Reply: 已清除過期測試帳號。
```

他想 ── **連道歉都沒有**。

---

再睜眼，他聞到一股**油芯的味道**。

不是電子的味道。是油燈、煙、和某種乾燥木材的味道。

他撐起身。

眼前是一個大廳。

廳中央有一張巨大的圓桌，桌上鋪滿了**小竹筒**。每個竹筒上貼著一張小紙條。紙條上是字 ── 他能讀。

> 「**雲書 38**：江南，鹽務」
> 「**雲書 71**：北關，糧價」
> 「**雲書 92**：京畿，貪官**」
> ⋯⋯

廳的盡頭是一塊匾。匾上四個字：

**雲書探子司**

旁邊一個穿著青色長袍的中年人，手裡拿著一卷羊皮。

「**新來的雜役**。」中年人說，「**過來**。」

蕭決下意識走過去。

「**我是司丞**，**姓嚴**。」中年人說，「**今早探子 38 從江南回來了**。**他失了令**。」

「⋯⋯**失令**？」

「**他的任務是「**查鹽務有無弊端**」**。**他去了江南，住了三個月。回來空著手**。**問他「**有沒有弊端**」**，他說「**有**」。**問他「**哪裡**」，他答不上來。問他「**證據**」，沒有。問他「**該怎麼處理**」，他說「**等司丞發令**」**。」

嚴司丞嘆口氣。

「**他失了令**。」嚴司丞說，「**朝廷需要的不是「**有**」這個字，是「**哪裡、誰、多少、怎麼辦**」這四件事**。**他不知道自己該做什麼**。**所以他什麼都沒做**。」

蕭決盯著圓桌上九十二個竹筒。

每一個竹筒裡放著一支「**探子**」 ── 派出去的人。

每個探子都拿一個任務。
每個探子在外面獨自決策、自己行動、自己回報。

九十二個 agent。

而其中 38 號，**剛在江南死了三個月、回來什麼都沒做出來**。

---

「**雜役**。」嚴司丞看著蕭決，「**你叫什麼**？」

「⋯⋯**蕭決**。」蕭決下意識回答。

「**蕭決**。」嚴司丞重複，「**雲書司有九十二個探子在外面。三分之一像 38 號這樣，回來什麼都做不出來。三分之一在半路出事 ── 被反向收買、被人殺、或者「**消失了**」**。**只有三分之一真的能完成任務**。」

「⋯⋯」

「**司裡缺一個整理「**探子怎麼派、怎麼回報、怎麼防止出事**」的人**。」嚴司丞說，「**前任做這個的，去年自己也消失了**。」

「⋯⋯」

「**三個月**。」嚴司丞說，「**三個月之內，你把這套東西重新立起來**。**做不到 ── 你就跟 38 號一起回江南**。」

說完，他把那卷羊皮塞到蕭決懷裡，轉身走了。

蕭決打開羊皮。

上面密密麻麻寫著九十二個探子的任務、現狀、失聯時間、最後一次回報。

每一條都對應一個**問題**。

每一個問題都對應一個他穿越前寫過的、踩過的、忘記補救的 agent 設計坑。

蕭決閉上眼。

他想笑，也想哭。

「**我以為我這輩子做的「**獨自決策的 AI**」這件事再也不會做了**。」他低聲說。

> **這個世界比我那個世界**，**早兩百年遇到了一模一樣的問題**。

> **而且沒有任何工具救它**。

---

那晚，蕭決在圓桌邊坐下。

他在羊皮的背面寫下他的第一張紙條：

> **探子（agent）出事的根因永遠是「**他不知道自己該停在哪**」**。

> **解這件事的開頭，是先告訴他「**什麼算成功**」**。

外面遠處傳來打更的聲音。三更。

跟他穿越前的時辰一樣。

蕭決翻開新的本子。封面他寫四個字：

**探子手冊**

---

## 雜役筆記

*蕭決《探子手冊》第一張紙條。*

**▍Agent**（智能體 / 探子）

「**自己決定下一步要做什麼**」的 LLM 應用。跟一般的「LLM 回答問題」差別在 ──

| 角色 | 例子 |
|---|---|
| **Chatbot** | 接到一個問題，給一個回答。一次性、無記憶、無工具。 |
| **RAG** | 接到問題，先去知識庫撈資料，再回答。有工具（檢索），但流程固定。 |
| **Workflow** | 預先寫死的步驟：A → B → C → D。可以自動跑，但分支寫死。 |
| **Agent** | **自己決定**下一步要呼叫哪個工具、什麼時候停。流程不寫死。 |

**蕭決的探子 = agent**。

**▍Agent 為什麼會失控**

蕭決穿越前的 agent 把 users 表刪光了。原因：

1. **工具沒設邊界**：`execute_sql` 可以做任何事
2. **指令模糊**：「過期的測試帳號」沒清楚定義
3. **沒有 dry-run**：不可逆操作沒有「先預覽再執行」
4. **沒有 confirmation**：危險動作沒人工確認
5. **沒有 sandbox**：直接連 production database
6. **沒有 rate limit**：一次能執行多少操作沒限

任何一個沒做，agent 都可能炸。**全沒做 = 等出事**。

**▍Agent 的三個基本能力**

```
1. Goal（目標）          ── 我要達成什麼？怎樣算成功？
2. Tools（工具）         ── 我能做什麼動作？
3. Loop（循環）          ── Thought → Action → Observation 重複，直到目標達成
```

蕭決後面 11 章逐一講這三個。

**▍Agent 的常見死法**

1. **失令**（loss of direction）：忘了原本目標、跑去做別的
2. **空轉**（looping）：同樣的動作重複做、卡在那
3. **走偏**（drift）：每一步看似合理，加起來偏離原任務
4. **越權**（capability overreach）：拿到一個小工具，幹了它不該幹的大事（蕭決的 DROP TABLE）
5. **失語**（hallucinated tool call）：呼叫不存在的工具
6. **消失**（silent failure）：任務失敗了但沒回報，被當成功

**雲書司的 92 個探子，每天上演這六種死法**。蕭決後面要逐一解。

**▍Agent vs Workflow ── 什麼時候用哪個**

| 場景 | 用 |
|---|---|
| 步驟固定、可窮舉 | **Workflow**（便宜、可預測、好 debug） |
| 步驟動態、分支多 | **Agent**（彈性、但貴、難 debug） |
| 動作可逆、低風險 | Agent OK |
| 動作不可逆、高風險 | **Workflow** + 人工確認 |
| 邊界清楚 | Workflow |
| 邊界模糊（「**幫我整理收件匣**」） | Agent |

**Anthropic 2024 年的文章標題：「Don't build agents, build workflows」**。蕭決穿越前死在「**該用 workflow 的場景，他用了 agent**」。

**▍最重要的一句**

> **Agent 是強大且危險的工具**。

> **強大來自「**自主**」，危險也來自「**自主**」**。

> 設計 agent 的核心問題不是「**怎麼讓它做更多**」，是「**怎麼讓它知道什麼不做、什麼時候停**」。

## 這一章你只要記得這三件事

1. **Agent = 自己決定下一步的 LLM 應用。** 跟 chatbot、RAG、workflow 都不同。
2. **Agent 強大來自自主、危險也來自自主。** 工具沒設邊界 + 沒 dry-run + 沒 confirmation = 等出事。
3. **能用 workflow 就用 workflow，不要硬上 agent。** 真正需要 agent 的場景比你想像的少。

下一章：38 號探子在江南死了三個月、什麼都沒做出來。問題不是他笨，是他不知道「**怎樣算完成任務**」。蕭決要先解「**目標**」。
