# 第 1 章　失令

> *練氣後期・第一重「失令」*

> *尹知行從商會往北，走了二十一天，過秦關，入雲書司。*
>
> *嚴司丞接他進門那天，只說了一句話：*
>
> ***「藏經閣讓你會找，商會讓你會記。我們這裡，讓你會做。」***
>
> *尹知行那時候不懂。*
>
> *他想：我會找答案、會識人記事、會寫規則、會設計工作流 ── 還要學什麼？*
>
> *入司第三個月，他出了第一次大事。*

---

尹知行抵達雲書司那一天，朔風正烈。

他從江流商會往北走了二十一天，過秦關、入塞外。雲書司在塞外一座叫做「**北望城**」的小城裡。

嚴司丞 ── 一個穿著青色長袍的中年人，腰牌上刻著「**雲書探子司**」── 在大門口接他。

「藏經閣？商會？」嚴司丞看了一眼舉薦信，「**我們這裡不查書、不識人、不記事**。**我們派的是「**令**」，**做的是「**動**」**。**你那兩套**，**在這裡只是底子**。」

尹知行收下舉薦信。

他在藏經閣是首席檢索官，在商會是首席記事使。雲書司嚴司丞說「**只是底子**」── 他懂這話的意思。

「從雜役做起。」嚴司丞說，「**三個月做不出名堂，回商會**。」

「⋯⋯是。」

---

嚴司丞把他帶進雲書司正廳。

廳中央一張巨大的圓桌，桌上鋪滿了**小竹筒**。每個竹筒上貼著一張小紙條。紙條上是字 ── 他能讀。

> 「**雲書 38**：江南，鹽務」
> 「**雲書 71**：北關，糧價」
> 「**雲書 92**：京畿，貪官**」
> ⋯⋯

廳的盡頭是一塊匾。匾上四個字：

**雲書探子司**

嚴司丞從袖中抽出一卷羊皮。

「**過來**。」嚴司丞說。

尹知行走過去。

「**今早探子 38 從江南回來了**。」嚴司丞說，「**他失了令**。」

「⋯⋯**失令**？」

「**他的任務是「**查鹽務有無弊端**」**。**他去了江南，住了三個月。回來空著手**。**問他「**有沒有弊端**」**，他說「**有**」。**問他「**哪裡**」，他答不上來。問他「**證據**」，沒有。問他「**該怎麼處理**」，他說「**等司丞發令**」**。」

嚴司丞嘆口氣。

「**他失了令**。」嚴司丞說，「**朝廷需要的不是「**有**」這個字，是「**哪裡、誰、多少、怎麼辦**」這四件事**。**他不知道自己該做什麼**。**所以他什麼都沒做**。」

尹知行盯著圓桌上九十二個竹筒。

每一個竹筒裡放著一支「**探子**」 ── 派出去的人。

每個探子都拿一個任務。
每個探子在外面獨自決策、自己行動、自己回報。

九十二個 探子。

而其中 38 號，**剛在江南死了三個月、回來什麼都沒做出來**。

---

「**雜役**。」嚴司丞看著尹知行，「**你叫什麼**？」

「⋯⋯**尹知行**。」尹知行下意識回答。

「**尹知行**。」嚴司丞重複，「**雲書司有九十二個探子在外面。三分之一像 38 號這樣，回來什麼都做不出來。三分之一在半路出事 ── 被反向收買、被人殺、或者「**消失了**」**。**只有三分之一真的能完成任務**。」

「⋯⋯」

「**司裡缺一個整理「**探子怎麼派、怎麼回報、怎麼防止出事**」的人**。」嚴司丞說，「**前任做這個的，去年自己也消失了**。」

「⋯⋯」

「**三個月**。」嚴司丞說，「**三個月之內，你把這套東西重新立起來**。**做不到 ── 你就跟 38 號一起回江南**。」

說完，他把那卷羊皮塞到尹知行懷裡，轉身走了。

尹知行打開羊皮。

上面密密麻麻寫著九十二個探子的任務、現狀、失聯時間、最後一次回報。

每一條都對應一個**問題**。

每一個問題都對應一個他穿越前寫過的、踩過的、忘記補救的 探子 設計坑。

尹知行閉上眼。

他想笑，也想哭。

「**我以為我這輩子做的「**獨自決策的 AI**」這件事再也不會做了**。」他低聲說。

> **這個世界比我那個世界**，**早兩百年遇到了一模一樣的問題**。

> **而且沒有任何工具救它**。

---

那晚，尹知行在圓桌邊坐下。

他在羊皮的背面寫下他的第一張紙條：

> **agent出事的根因永遠是「**他不知道自己該停在哪**」**。

> **解這件事的開頭，是先告訴他「**什麼算成功**」**。

外面遠處傳來打更的聲音。三更。

跟他穿越前的時辰一樣。

尹知行翻開新的本子。封面他寫四個字：

**探子手冊**



---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **練氣後期・第一重「失令」**。

## 雜役筆記

*尹知行《探子手冊》第一張紙條。*

**▍Agent**（智能體 / 探子）

「**自己決定下一步要做什麼**」的 LLM 應用。跟一般的「LLM 回答問題」差別在 ──

| 角色 | 例子 |
|---|---|
| **Chatbot** | 接到一個問題，給一個回答。一次性、無記憶、無工具。 |
| **RAG** | 接到問題，先去知識庫撈資料，再回答。有工具（檢索），但流程固定。 |
| **Workflow** | 預先寫死的步驟：A → B → C → D。可以自動跑，但分支寫死。 |
| **Agent** | **自己決定**下一步要呼叫哪個工具、什麼時候停。流程不寫死。 |

**尹知行的探子 = agent**。

**▍Agent 為什麼會失控**

尹知行穿越前的 agent 把 users 表刪光了。原因：

1. **工具沒設邊界**：`execute_sql` 可以做任何事
2. **指令模糊**：「過期的測試帳號」沒清楚定義
3. **沒有 dry-run**：不可逆操作沒有「先預覽再執行」
4. **沒有 confirmation**：危險動作沒人工確認
5. **沒有 sandbox**：直接連 production database
6. **沒有 rate limit**：一次能執行多少操作沒限

任何一個沒做，agent 都可能炸。**全沒做 = 等出事**。

**▍Agent 的三個基本能力**

```
1. Goal（目標）          ── 我要達成什麼？怎樣算成功？
2. Tools（工具）         ── 我能做什麼動作？
3. Loop（循環）          ── Thought → Action → Observation 重複，直到目標達成
```

尹知行後面 11 章逐一講這三個。

**▍Agent 的常見死法**

1. **失令**（loss of direction）：忘了原本目標、跑去做別的
2. **空轉**（looping）：同樣的動作重複做、卡在那
3. **走偏**（drift）：每一步看似合理，加起來偏離原任務
4. **越權**（capability overreach）：拿到一個小工具，幹了它不該幹的大事（尹知行的 DROP TABLE）
5. **失語**（hallucinated tool call）：呼叫不存在的工具
6. **消失**（silent failure）：任務失敗了但沒回報，被當成功

**雲書司的 92 個探子，每天上演這六種死法**。尹知行後面要逐一解。

**▍Agent vs Workflow ── 什麼時候用哪個**

| 場景 | 用 |
|---|---|
| 步驟固定、可窮舉 | **Workflow**（便宜、可預測、好 debug） |
| 步驟動態、分支多 | **Agent**（彈性、但貴、難 debug） |
| 動作可逆、低風險 | Agent OK |
| 動作不可逆、高風險 | **Workflow** + 人工確認 |
| 邊界清楚 | Workflow |
| 邊界模糊（「**幫我整理收件匣**」） | Agent |

**Anthropic 2024 年的文章標題：「Don't build agents, build workflows」**。尹知行穿越前死在「**該用 workflow 的場景，他用了 agent**」。

**▍最重要的一句**

> **Agent 是強大且危險的工具**。

> **強大來自「**自主**」，危險也來自「**自主**」**。

> 設計 agent 的核心問題不是「**怎麼讓它做更多**」，是「**怎麼讓它知道什麼不做、什麼時候停**」。

## 這一章你只要記得這三件事

1. **Agent = 自己決定下一步的 LLM 應用。** 跟 chatbot、RAG、workflow 都不同。
2. **Agent 強大來自自主、危險也來自自主。** 工具沒設邊界 + 沒 dry-run + 沒 confirmation = 等出事。
3. **能用 workflow 就用 workflow，不要硬上 agent。** 真正需要 agent 的場景比你想像的少。

下一章：38 號探子在江南死了三個月、什麼都沒做出來。問題不是他笨，是他不知道「**怎樣算完成任務**」。尹知行要先解「**目標**」。
