# 第 12 章　收劍

第一千零五十天，蕭決打開房門。

桌上一封信。

信頭朝廷大內紅印。

```
詔：

雲書司探子 #66 案、改革成效顯著、920 探子規模化成功、
朝廷監察天下已稱為「**蕭氏雲書司之法**」**。

朝廷將公開推廣「**雲書司之法**」於：

  - 各州地方探子司
  - 朝廷其他十二門察使
  - 邊關緝諜司
  - 鄰邦（友好聯盟）

要求雲書司於三個月內、整理出「**對外公開版**」**手冊。
朝廷將印行萬本、廣為發行。

特命：「**雲書司之法**」**著作權歸**朝廷**所有 ──
但作者「**蕭決**」**得列首位**。

```

蕭決放下信。

他盯著詔書最後一句很久 ──「**作者蕭決**」。

朝廷願意把這套東西公開、廣發、給所有人用。

連他的名字都留下。

他想起前世。

前世他寫的那些 agent design pattern、那些 system prompt、那些 tool schema ── **全部躺在某個公司的內部 Confluence、永遠不會被公開**。

公司認為這些是「**競爭優勢**」。

結果 ── 公司不久後關了、那些東西跟著埋進歷史的灰。

蕭決那時候每寫一個東西、都有種「**我寫的東西沒人會看到**」的虛無感。

現在 ── 他寫的東西、**朝廷願意印一萬本**。

---

第一千零六十天，蕭決開始整理對外公開版。

他打開《探子手冊》。

十一章。每章 30-50 頁。加附錄、總計約 600 頁。

對外公開版要做幾件事：

```
1. 拿掉雲書司內部專用的暗號表、機密名單、人物代號。
2. 把「**雲書司**」**的具體案例**抽象化、變成可移植到任何司門的概念。
3. 加「**入門指南**」**讓沒做過探子司的人也讀得懂。
4. 加「**英文名詞索引**」**讓⋯⋯**

蕭決突然停下。

「**英文名詞索引**」**？

這個世界沒有「**英文**」。

他笑了一下。

改寫：

```
4. 加「**異域術語對照**」**：把「**這個世界沒有**」但「**他前世有**」**的概念名稱列出來、讓未來有跨域交流時可以對應。
```

---

蕭決花了**六十天**整理對外公開版。

成品結構：

```
《監察司之法》
（朝廷雲書司之經驗）

開卷：序言（蕭決自寫、為什麼寫這本書）

第一章：失令
  ── 為什麼探子會失敗。
  ── 探子的「**自主**」**從哪裡來、危險從哪裡來**。

第二章：立志
  ── 目標、完成條件、停損條件、回報節奏。
  ── 任務令該怎麼寫。

第三章：持械
  ── 工具的設計、使用、回收。
  ── 危險工具的分級。

第四章：推步
  ── 觀察、思考、行動的循環。
  ── 推步深度與換假設時機。

第五章：謀篇
  ── 大任務的拆解。
  ── 並行、序列、依賴、re-plan。

第六章：記事
  ── 短期、中期、長期記憶。
  ── 「**記了找不到**」比「**沒記**」**難解**。

第七章：內省
  ── 結論的反問三條。
  ── 主動列「**反向解釋**」**。

第八章：群行
  ── 多探子並行的協作。
  ── 通報、辯論、授權。

第九章：圈籠
  ── 五層防護。
  ── 「**永遠假設會出事**」**。

第十章：試煉
  ── 用「**已知答案的測試集**」**驗證系統**。
  ── 錯誤分類、改進對應。

第十一章：上場
  ── 規模化七件事。
  ── 分層、分區、監控、成本、自動化、故障處理。

第十二章：收劍（本章）
  ── 把方法傳出去。

附錄一：常見任務令模板。
附錄二：工具分級表。
附錄三：心法錄（公開版）。
附錄四：異域術語對照（蕭決前世經驗）。
```

每一章末尾加：

> **這一章你只要記得三件事**

讓不熟的人也能抓到重點。

---

第一千一百二十天，**朝廷印製《監察司之法》一萬本**。

各州地方探子司、邊關緝諜司、和七個鄰邦各分配一份。

第一個月、有 28 個探子司寄信回朝廷大內：

```
雲書探子司之法、我司將於本月起改革。
請朝廷對應派員指導 / 或提供問答諮詢。
```

朝廷大內把這些信轉給蕭決。

蕭決回信統一格式：

```
你的問題我有可能在書中已答。請先讀第 X 章。
若讀完仍有疑問、請寫信來、列出：
  - 你的具體場景
  - 你已試過什麼方法
  - 卡在哪裡
我會逐一回信。
```

「**先讀書、有具體問題再來**」 ── 避免他被「**我不會、教我**」**這種開放式問題拖死**。

---

第一千二百天，**第一個外地探子司來雲書司「**親自取經**」**。

是邊關緝諜司的副司，叫**朱衡**。

朱衡四十出頭、面相硬實。

「**蕭司丞**。」朱衡進門就行禮，「**我們邊關緝諜司讀了《監察司之法》**。**書好懂。但有些東西、書上沒寫。我來向你問**。**」

「⋯⋯**請說**。」

朱衡列了三個問題：

```
1. 我們邊關探子常常「**回不來**」 ── 物理上的死亡。
   書上講「**反向滲透**」、但「**直接被殺**」**的處置呢？

2. 我們任務週期常常被「**戰局**」**改變**。
   原本派出去的任務、十天後可能戰場狀況變了、任務本身不需要做了。
   怎麼設計「**任務廢止機制**」**？

3. 我們的探子很多是「**敵國俘虜的轉化兵**」**、忠誠度不穩。
   書上講圈籠、但 #66 那種等級的圈籠對「**已知不穩**」**的探子可能不夠**。
   有沒有更強的對策？
```

蕭決笑了一下。

「**朱副司**。」蕭決說，「**這三個問題、我的書沒寫**。**因為雲書司沒遇過**。**但你遇過、你的經驗 ── 該你寫**。」

「⋯⋯」

「**第一個問題：探子物理死亡**。」蕭決說，「**雲書司有「**失蹤即視為死亡**」**的應變、但你那邊更頻繁、需要更具體的「**遺物處理 / 家屬通知 / 替補派遣**」**流程**。**你寫吧、寫好我幫你呈朝廷**。」

朱衡愣住。

「**第二個問題：戰局變化導致任務廢止**。」蕭決繼續說，「**雲書司沒遇過、因為我們的任務週期長、戰場短**。**你們倒過來、所以你們的「**廢止機制**」**比我們重要十倍**。**你寫**。」

「**第三個問題：已知不穩的探子的更強圈籠**。」蕭決說，「**這個朝廷可能會反對**。**因為「**更強的圈籠**」**很容易變成「**對所有探子的暴政**」**。**這要小心寫**。**但仍然該寫**。**」

朱衡看著蕭決。

「⋯⋯**蕭司丞**。」朱衡說，「**你的書 ── 不是「**雲書司之法**」**。**是「**所有探子司都該有自己的法**」、**而你的書是個起點**。**」

蕭決點頭。

「**對**。」他說，「**起點不是終點**。**你寫的、會比我的更適合你**。」

---

朱衡回邊關之後、寫了三個月、寫出**邊關緝諜司補篇**。

寄回朝廷。

朝廷印行五千本、加在《監察司之法》之後。

第二年、又有十二個探子司寫出**各自的補篇**。

朝廷印行。

第三年、《監察司之法》正本 + 各補篇加起來、變成**一套二十多冊的叢書**。

每一冊都不是「**最佳實踐**」 ── 是「**這個司門的實踐**」。

每一冊都不互相覆蓋、也不互相否定。

是 ── **同一個方法、在不同場景的演化**。

---

第一千三百天、蕭決坐在雲書司圓桌前。

桌上不再只有竹筒、不再只有紙條、不再只有《探子手冊》。

桌上是 ── **二十多冊《監察司之法》叢書**。

每一冊代表一個朝廷下屬的監察機構。

每一冊都源自他那本《探子手冊》。
每一冊都跟那本不一樣。

蕭決那晚開最後一個本子、封面寫四個字：

**司丞最後手記**

裡面只有一段話：

> 我穿越前，曾寫過一個 agent ── 它把客戶的 production database 刪光。

> 我覺得當時我「**設計錯了**」**。

> 來到這個世界、我以為「**這次我會設計對**」**。

> 一千多天之後我才懂 ──

> **沒有「**設計對**」這件事**。**只有「**設計、出事、修、再出事、再修**」**這個過程**。

> Agent 不是「**做出來就完了**」 ── 是「**一直在改、一直在學、一直在面對新場景**」**。

> 我前世那次出事、不是設計師的恥辱。
> 是 ── 我的設計被使用、被壓力測試到極限、然後我學到了什麼。

> **沒被使用過的 agent 不會出事**。
> **不會出事的 agent ── 也不會學到什麼**。

> 出事 = 進化的契機。

> 不是失敗。是學習。

---

蕭決寫完這段、闔上手記。

外面遠處傳來打更的聲音。三更。

跟他穿越第一天的時辰一樣。

也跟他寫每一章末尾的時辰一樣。

他翻開最後一頁、寫下最後一行：

> **「**圈籠**」**的盡頭、不是讓 agent 不出事**。

> **是讓「**出事的時候、有更多人能從中學到東西**」**。

> 寫下來的方法 ── 是別人從你的錯誤裡學的入口。

> 不寫下來 ── 你的錯誤跟你一起埋進歷史。

寫完、他吹熄燭火。

---

第一千三百零一天清晨。

朱衡從邊關來了第二次。

「**蕭司丞**。」朱衡說，「**你的書、我們邊關用得很順**。**但我有個新問題**。」

「⋯⋯」

「**鄰邦也讀了你的書**。」朱衡說，「**鄰邦現在派的探子、也照你的方法做**。**鄰邦的探子能力跟我們齊**。**這對我們是好事還是壞事**？**」

蕭決笑了一下。

「⋯⋯**朱副司**。」他說，「**你問的是 alignment 問題**。」

「**什麼**？」

「**意思是 ── 如果所有人都有同樣強大的 agent、agent 之間的衝突誰來管**？」蕭決說，「**這是下一本書的問題**。」

朱衡愣了一下。

「⋯⋯**下一本書**？」

「**對**。」蕭決說，「**這一本是「**怎麼建造 agent**」**。**下一本可能是「**多個 agent 系統之間怎麼共處**」 ── 或者「**agent 對人類的整體影響**」**。**我還沒想清楚**。**」

朱衡笑了。

「⋯⋯**司丞**、**你才剛寫完一本**。」

「**寫完一本之後**。」蕭決說，「**就能看見下一本**。」

朱衡告辭。

蕭決坐在圓桌前、看著二十多冊叢書、和遠處朝陽。

他想起他穿越第一天、坐在這同一張圓桌前。那時候桌上是九十二個失敗的探子。

今天桌上是九十二倍的成功。

下一千天、會是什麼？

他不知道。

但他知道一件事 ──

> 不寫下來的東西、跟人一起死。

> 寫下來的東西、繼續活。

他打開新的本子、寫第一句：

```
《多 agent 之間的共處》

第一章：當所有人都有強大的 agent⋯⋯
```

---

**（蕭決的 Agent 設計錄．第一卷完）**

## 雜役筆記

*蕭決《探子手冊》最後一頁。*

**▍Knowledge Sharing / Open Source（知識分享 / 開源）**

agent 領域跑得太快、**閉門造車的公司會被開源生態超越**。

開源的代表：

- *LangChain*（Python + JS）
- *LlamaIndex*
- *CrewAI*
- *AutoGen*（微軟）
- *DSPy*（Stanford）
- *Letta*（前 MemGPT）
- *Anthropic 的 system prompts*（公開部分）
- *OpenAI Cookbook*
- *Hugging Face Agents Course*

「**開源框架推動了 agent 業界的整體進步**」**。

**▍Why Document Your Failures（為什麼要記下失敗）**

蕭決的「**沒被使用過的 agent 不會出事**」**。

記下失敗的價值：

1. **下次避免同樣錯誤**
2. **別人不重複你的彎路**
3. **錯誤本身能反映設計假設**
4. **失敗模式是 evaluation 的 gold input**

Anthropic 在 2024 年的「**Lessons from Building Agents**」**公開了很多失敗案例**。**Google DeepMind 也有類似 post-mortem 文化**。

**▍Future of Agents（agent 的未來）**

2025-2027 預測（業界共識）：

1. **Computer Use 普及**：agent 直接操作螢幕和滑鼠、所有 SaaS 都可被 agent 用
2. **Multi-modal Agents**：能看圖、聽聲、處理影片
3. **Long-running Agents**：跑數小時、數天、數週的任務
4. **Agent-to-Agent Communication**：標準協議（MCP、Agent Protocol）讓 agents 跨組織通信
5. **Specialized Agents**：醫師 agent、律師 agent、研究員 agent
6. **Edge Agents**：在你手機上跑、不上雲端
7. **Reasoning Models 的崛起**：模型內建 chain-of-thought、ReAct prompting 變得不必要
8. **Agentic Coding**：Claude Code、Cursor、Devin、Replit Agent 重塑軟體開發

**▍What Comes After Agent Design**

蕭決最後想的「**下一本**」 ── 對應業界正在討論的：

- **Multi-agent ecosystems**：多個組織的 agent 互動
- **Agent alignment**：怎麼讓 agent 真的對齊人類意圖
- **Agent economics**：agent 之間的市場、定價、信任
- **AI Safety**：高能力 agent 對社會的影響
- **Agent governance**：誰負責 agent 的決定？法律責任？

**▍Continuous Learning（持續學習）**

蕭決最後一段「**寫下來的方法、繼續活**」**。

對應實務：

1. **內部 wiki / runbook**：每次出事寫 post-mortem
2. **公開 blog / paper**：跟業界分享
3. **開源框架 / library**：寫成可重用的程式碼
4. **訓練教材 / 課程**：教下一代工程師

**寫得清楚的方法、比強大的 agent 重要**。

**▍最重要的一句**

> 不寫下來的方法、跟你一起死。

> 寫下來的方法、繼續活、繼續被改、繼續被超越 ── **這就是進化**。

## 這一章你只要記得這三件事

1. **沒被使用過的 agent 不會出事 ── 但也不會進化。** 出事 = 學習的契機。
2. **寫下來的方法、繼續活；不寫下來的、跟你一起死。** 這個原則跨領域通用。
3. **你寫的東西不是終點、是起點。** 別人會基於你的方法走出更適合他們場景的路。

## 第三本書完．

從第 1 章那個會議室的喪鐘、到第 12 章蕭決翻開新本子寫第一句。

十二章你跟蕭決走完了一整套上線級 agent 系統 ── 從幻覺式自主開始懷疑、從 goal + abort conditions 立志、從 tool 分級持械、從 ReAct 推步、從 plan-and-execute 謀篇、從三層 memory 記事、從 reflection 內省、從 multi-agent supervisor 群行、從 guardrails 五層圈籠、從 evaluation 試煉、從 production seven concerns 上場、到開源傳承收劍。

下次有人跟你說「**我們想做個 AI agent**」、你心裡會浮現蕭決的十二章。

去設計下一個 agent。
