# 第 3 章　持械

> *練氣後期・第三重「持械」*

第四十二天，雲書司有六個探子同時派出去。

尹知行寫好六張任務令、講完了完成條件、約定了七日簡報。

第七天，六份簡報回來。

尹知行抽**第 12 號**（派去查中州米價的）看：

```
[週 1 簡報]
本週進度：
  - 已抵達中州。
  
未進展：
  - 我不知道該怎麼查米價。
  - 米鋪我去問了三家，每家報的價不一樣。我不確定該信哪家。
  - 我想去衙門查米倉檔案，但衙門不讓我看。
  - 我想偽裝成米商，但我沒有米商的偽裝。

我想知道：司丞是否可以教我「**該怎麼查米價**」？
```

尹知行閉上眼。

問題不在 12 號笨。

問題在 ── **他根本沒有「**查米價**」的工具**。

「**去問米鋪**」── 只是「**問**」。問三家報三個價，他不知道哪個對。
「**去衙門看檔案**」── 沒人讓他看。他沒有偽裝、沒有腰牌、沒有引線。
「**偽裝成米商**」── 沒服裝、沒名字、沒身分證明。

12 號只**有兩個「能力」**：「**走到那邊**」、「**回來**」。

中間所有「**查**」的動作，他**沒有工具**。

---

尹知行翻過去派出去的探子紀錄。

凡是成功完成任務的，**90% 是「**雜役有自己的人脈或隱藏技能**」**。

凡是失敗的，**90% 是「**雜役想不到該怎麼做**」**。

雲書司**從來沒給探子配齊工具**。

派出去就靠他們自己想辦法。

那不行。

---

第四十六天，尹知行在圓桌邊空出第三面牆。

他開始列「**探子可能用到的工具**」：

```
查資料類：
  - 查衙門檔案（需要偽造或借用的腰牌）
  - 查商號帳本（需要假身分證明）
  - 查私人信件（需要⋯⋯算了，這個違法）
  - 查市場現價（需要可信的線人）

接觸人類：
  - 偽裝為外地商人（需要服裝、名片、店號）
  - 偽裝為朝廷小吏（需要官服、文書、印章）
  - 偽裝為旅人（需要⋯⋯沒什麼，但價值低）
  - 派人「下注」測試對方（需要銀錢）

驗證類：
  - 比對筆跡（需要原樣筆跡庫）
  - 對照公文（需要可信的副本）
  - 證人交叉確認（需要至少三個獨立來源）

通訊類：
  - 飛鴿傳信回司（需要飛鴿和密碼）
  - 緊急急遞（需要驛站憑信）
  - 安全會面（需要密語對暗）
```

四大類、十幾種工具。

每一種工具都有：

```
- 名字
- 怎麼用（呼叫格式）
- 什麼時候用（適用情境）
- 不該用（禁忌情境）
- 副作用（用了會發生什麼）
```

---

尹知行把這些工具列成「**械器名錄**」。

每個探子出發前，**從械器名錄選自己這次任務需要的工具**。

不是「全部帶」── 全部帶有兩個壞處：

```
1. 累、難管
2. 工具太多 → 探子在現場時不知道該用哪個 → 卡住或亂用
```

也不是「**司丞替探子選**」── 派任務的人不一定清楚現場狀況。

尹知行的做法：

```
任務令裡列「**建議工具**」：5-8 個探子主要會用的。
探子可以「**再請領**」其他工具：但要回報「**為什麼需要、用來做什麼**」。
回司之後，械器名錄裡的工具該繳的繳、該銷的銷。
```

---

第五十天，12 號從中州送回第二份簡報：

```
[週 2 簡報]
本週進度：
  - 收到司寄來的「**外地米商**」偽裝包：店號「永豐米行」、名片三十張、外地口音書信範本五份。
  - 偽裝為永豐米行掌櫃接觸中州三家大米商，已開始議價試探。
  - 議價過程中發現「**官價米**」與「**私價米**」差距 22%。

進展：
  - 中州米價我已能掌握。
  - 仍未進入衙門。需要「**朝廷小吏腰牌**」這個工具，請司寄來。

下週計畫：
  - 拿到腰牌後查衙門糧倉檔案
  - 比對「**官報量**」與「**實際量**」
```

尹知行看完，**派飛鴿寄一塊「**朝廷小吏腰牌**」過去**。

附信：

```
腰牌用完後封存交還，不可帶回中州當紀念。
腰牌編號 #X-731，朝廷有底冊。借用 30 天，逾期需上報。
```

「**工具有副作用、要回收、用了要報**」 ── 這跟尹知行前世做 探子（agent） 的「**tool log + audit + return**」一模一樣。

---

第五十五天，12 號回信：

```
[週 3 簡報]
本週進度：
  - 用腰牌進入衙門糧倉。比對「**官報量**」與「**實際量**」共 17 筆。
  - 其中 5 筆顯著不符：差距超過 8%。
  - 5 筆全部由同一名糧倉副使「**鄭翔**」簽核。

證據已蒐集。下週回司覆命。

附：腰牌 #X-731 將隨身帶回封存交還。
```

完美。

尹知行把這份簡報跟 12 號帶回的證據對照、整理。**結論清晰、責任歸屬明確、工具回收乾淨**。

---

第五十八天，另一個探子 ── **17 號** ── 出事了。

17 號被派去南港查貨運舞弊。

第二週他偽裝為外地貨商接觸南港貨運所，但**他多選了一個工具**：「**派線人下注測對方**」。

他帶了 50 兩銀錢去南港。

第三週，他**沒有簡報**。

尹知行很警覺。

第二十二天他派了**驛站急遞**確認。

回信：「**17 號在南港被人發現是外地朝廷探子。50 兩銀錢被搶。本人下落不明**。」

尹知行把這封信釘到牆上。

---

「**為什麼 17 號出事**？」尹知行召集嚴司丞和兩個老司丞討論。

老司丞之一說：「**他選錯工具**。**「**下注測試**」這個工具有副作用 ── 銀錢會引人注意。**南港這種地方，**揮一筆 50 兩，**等於告訴所有人「**我這個人有問題**」**。**」

尹知行點頭。

「**所以「**選工具**」**這件事，**比「**有什麼工具**」更重要**。」尹知行說，「**每個工具該寫清楚「**什麼情境用、什麼情境不用、副作用是什麼**」**。」

嚴司丞同意。

「**還有一件事**。」嚴司丞說，「**17 號選了「**下注**」這個工具 ── 司沒攔他。**他在派出去之前的工具清單裡，下注是「**建議工具**」。**這是我們的錯**。**南港這種敏感地點，下注該是禁用工具，不該列在建議裡**。**」

尹知行抓起《探子手冊》第三章。

封面三個字：

**持械**

---

第六十天，尹知行完成《械器名錄》第一版。

每一個工具都按這個模板：

```
工具名：朝廷小吏腰牌
類別：身分偽裝
描述：可用於進入衙門、糧倉、官倉等朝廷管轄場所
使用方式：佩戴於腰間，遇朝廷官員可亮示
適用情境：
  - 任務涉及進入官方場所
  - 不必查詢真實朝廷紀錄（因會留痕）
禁用情境：
  - 任務有可能與真實朝廷小吏遭遇（會被識破）
  - 高風險地區（如南港、邊關）── 易被檢舉
副作用：
  - 朝廷有底冊，用了會在小吏記錄上留痕
  - 借用期限 30 天
  - 逾期不繳，下次申請會被拒
失效條件：
  - 真朝廷小吏出現
  - 被人勒令出示「**朝廷副本**」
  - 30 天到期
```

七十四個工具，每個都這樣寫。

尹知行花了**九天**才寫完。

「**寫一次。用十年**。」嚴司丞看了之後說，「**前任司丞做這事三年沒做完**。**你九天**。」

尹知行笑了一下。

「**因為我有壓力**。」尹知行說，「**而且我前世已經寫過類似的東西**。」

嚴司丞沒問「**前世**」是什麼意思。

只是點頭，把《械器名錄》收進司裡的鐵櫃。

---

第七十天，新派出去的探子拿到更完整的工具配備。

12 號出去查河運。任務令上列：

```
建議工具：
  - 外地商人偽裝（衣物、口音、名片）
  - 朝廷小吏腰牌（30 天授權）
  - 飛鴿傳信（密碼版）
  - 「**比對筆跡**」工具包（含原樣筆跡庫副本）
  - 緊急急遞憑信

禁用工具：
  - 下注測試（河運區風險評等：高）
  - 假冒武將（你無武功，易被識破）
```

12 號接過任務令，**比之前更穩**。

「**司丞**。」12 號說，「**這次的「**禁用工具**」**是新的吧**？**」

「**對**。」尹知行說，「**17 號的教訓**。」

12 號點頭。

「**還有一個問題**。」12 號問，「**任務中我發現需要新工具 ── 怎麼辦**？」

「**飛鴿回司**。」尹知行說，「**請領的時候寫「**為什麼、用來做什麼、副作用評估**」**。**我核准就寄給你**。**否則你自己想辦法 ── 但「**自己想辦法**」**的解法**也要回報**。」

12 號點頭走了。

---

那晚尹知行在《探子手冊》第三章末尾寫：

> **工具是探子的「**能力邊界**」**。

> 沒工具 = 探子只能走和看。
> 有工具但沒邊界 = 探子可能用了不該用的（17 號）。
> 有工具有邊界 = 探子能做事、做得安全。

> **每個工具寫「**怎麼用、什麼時候用、什麼時候不用、副作用**」**。
> **這四件事缺一個，工具就會出事**。

下一章他要處理：探子有了任務、有了工具。**但他在現場一步一步該怎麼走、什麼時候用哪個工具、看到回應之後該怎麼往下** ── 那是「**推步**」。



---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **練氣後期・第三重「持械」**。

## 雜役筆記

*尹知行《械器名錄》工具模板。*

**▍Tool / Function Calling**（工具呼叫 / 函式呼叫）

讓 LLM 不只生文字、還能**呼叫外部動作**。尹知行的「**械器**」就是這個。

**▍Tool 的標準定義**

每個 tool 都該有：

```python
{
  "name": "search_archive",
  "description": "查詢衙門檔案。回傳符合條件的紀錄。",
  "parameters": {
    "query": "string, 必填, 查詢關鍵字",
    "year_range": "string, 選填, 格式 YYYY-YYYY",
    "max_results": "int, 選填, 預設 10"
  },
  "when_to_use": "需要從歷史檔案中找特定紀錄時",
  "when_not_to_use": "若資料是即時的、用 query_realtime；若資料是私人的、不可用此工具",
  "side_effects": "查詢會留下衙門日誌；高頻使用會被注意",
  "rate_limit": "每天最多 50 次"
}
```

**▍OpenAI / Anthropic Function Calling**

主流 LLM 都支援。模型在生成時可以「**輸出一個工具呼叫**」而非單純文字：

```json
{
  "tool_calls": [{
    "name": "search_archive",
    "arguments": { "query": "鹽務 2024", "max_results": 20 }
  }]
}
```

你的程式接到這個就執行對應函式、把結果回傳給模型、模型繼續推理。

**▍Tool Design 的鐵則**

1. **單一職責**：每個工具只做一件事
2. **清楚描述**：description 直接決定模型能不能正確選用它
3. **參數明確**：每個參數都該有 type、必填/選填、預設值
4. **錯誤明確**：失敗時回 structured error，讓模型能 debug
5. **副作用明示**：不可逆動作要明確標示

**▍Tool 數量的痛點**

工具太少 → agent 做不到事
工具太多 → agent 選錯、混淆、context 變大、慢、貴

**業界共識：**單一 agent 一次別給超過 20 個工具****。

超過 → 用「**工具選擇器**」（先讓一個輕量模型挑該用哪幾個、再給主 agent）。

**▍工具的危險度分級**

尹知行的「**禁用工具**」概念。

```
Level 1（讀）：search_archive、read_file、http_get
  → 通常安全、可不需確認

Level 2（局部寫）：create_record、send_email_draft、save_note
  → 可逆、影響範圍小

Level 3（重要寫）：execute_sql、send_email_real、delete_record
  → 不可逆或影響大、需要 dry-run + confirmation

Level 4（危險）：drop_table、rm_-rf、執行任意 shell
  → 預設關閉、需要明確人工授權才能呼叫
```

**尹知行穿越前死在 Level 4 工具沒設保護**。

**▍Tool Use 的常見錯誤**

1. **Hallucinated Tool Call**：呼叫不存在的工具（模型編了一個名字）
2. **Wrong Parameters**：參數類型/格式錯
3. **Infinite Loop**：同樣的工具一直呼叫
4. **Tool Selection Confusion**：兩個工具描述太像、模型分不清
5. **Cascading Failure**：一個工具錯了、後面全錯（沒中止）

對策：
- Schema validation（呼叫前先驗證參數）
- Tool result validation（呼叫後驗證結果合理）
- Rate limiting（同樣工具一段時間呼叫 N 次以上中止）
- Idempotency（同樣參數呼叫，回同樣結果）

**▍MCP**（Model Context Protocol，模型上下文協議）

Anthropic 2024 年提的開放協議。**讓 tool 跟 agent 之間有標準介面**，工具可以被任何 agent 用、不綁定特定模型/框架。

「**寫一次 tool、所有 agent 都能用**」。生態逐漸成形。

**▍Computer Use（讓 agent 操作電腦）**

Anthropic 2024 年發布。Agent 可以看螢幕、移動滑鼠、打字。**Tool 的最強形式**：「**任何電腦能做的事 agent 都能做**」。

風險也最大：等於把整台電腦交給 agent。**必須 sandbox**。

**▍實作框架**

- *LangChain Tools*：最廣用、生態大
- *LlamaIndex Tools*：跟 LlamaIndex 整合
- *CrewAI Tools*：適合 multi-agent
- *Anthropic Tool Use API*：原生、無框架
- *MCP servers*：跨平台、跨模型

## 這一章你只要記得這三件事

1. **Tool 是 agent 的能力邊界。** 沒工具的 agent 只會聊天。
2. **每個 tool 要寫：什麼時候用、什麼時候不用、副作用、失效條件。** 四件事缺一個就會踩坑。
3. **危險工具要分級保護。** Level 4（不可逆、高破壞）預設關閉，明確授權才能呼叫。尹知行前世死在這。

下一章：探子有了任務和工具。但他在現場「**看到一個情況 → 該用哪個工具 → 看到結果 → 下一步該往哪走**」── 這個循環怎麼跑？ReAct 登場。
