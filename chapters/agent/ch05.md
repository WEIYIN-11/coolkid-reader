# 第 5 章　謀篇

第八十天，雲書司收到一份**特殊任務令**。

不是從各分舵來的常規案件。是**朝廷大內**直接下的：

```
任務：查清「**東陲三州**」近一年來「**糧、鹽、布、馬**」四項朝廷專營的全部弊端。
期限：八個月。
要求：完整證據鏈、責任歸屬、處置建議。
```

蕭決把任務令攤在圓桌上。

**東陲三州** ── **冀州、青州、徐州**。三個州、四項商品、一年資料、八個月期限。

**單純用 ReAct 跑 ── 一個探子根本完不成**。

光是「**冀州 + 糧**」一個小目標，就要兩個月。三州 × 四項 = 12 個小目標。一個探子做完是 24 個月。

但任務令給的是 **八個月**。

蕭決必須**先規劃整個任務的結構**，再派人。

---

蕭決把任務拆開。

```
東陲三州弊端調查

第一層：拆「**地點**」
  - 冀州、青州、徐州

第二層：拆「**項目**」
  - 糧、鹽、布、馬

第三層：每個 (地點 × 項目) = 一個子任務
  - 冀州糧、冀州鹽、冀州布、冀州馬
  - 青州糧、青州鹽、青州布、青州馬
  - 徐州糧、徐州鹽、徐州布、徐州馬

共 12 個子任務。
```

但 ── **12 個子任務不是互相獨立**。

蕭決想了一下。

**「**馬**」這項，只有冀州和青州有大規模馬政**。徐州沒馬。
**「**鹽**」這項，三州都有**。
**「**糧**」這項，冀州糧倉大、青州中、徐州小**。
**「**布**」這項，徐州最盛、青冀略遜**。

按「**規模重要性**」優先：

```
高優先（規模大、易出弊端）：
  - 冀州糧
  - 青州馬
  - 徐州布
  - 三州鹽（同時）

中優先：
  - 冀州馬
  - 青州糧
  - 徐州糧

低優先：
  - 冀州布
  - 青州布
  - 徐州馬（無）
```

蕭決算：
- 高優先 4 個 → 各派一個探子，並行 → 兩個月
- 中優先 3 個 → 接著派 → 又兩個月
- 低優先 → 同時開始，可以慢
- 8 個月內，**11 個有意義的子任務都能完成**

剩下時間做「**整合報告**」── 把 11 份子報告合成一份呈交大內。

---

蕭決寫了**主任務令**：

```
主任務（蕭決自己跑）
  目標：統籌東陲三州調查，最終提交完整報告。
  子任務數量：11
  並行：高優先 4 個
  序列：高 → 中 → 低
  期限：8 個月
  
  每兩週評估各子任務進度。
  發現重大線索 → 重新平衡資源（必要時抽中優先探子去支援高優先）。
```

然後寫**子任務令**：每個子任務一份，**個別目標、完成條件、停損條件、工具配給**全寫清楚。

---

第八十二天，蕭決派出**四個探子同時出發**。

冀州糧 → 探子 #12（過去查過糧倉、有經驗）
青州馬 → 探子 #34（過去查過茶葉走私、推步能力強）
徐州布 → 探子 #21（新秀、推步紮實）
三州鹽 → 探子 #38（江南鹽務案的老手）

四人同時出發。

蕭決自己留在雲書司，**每日早上集中看四份簡報**。

---

第九十天，四份第一週簡報同時回到圓桌：

```
#12 冀州糧：初步調查完成，疑似「**漕運私售**」訊號。
#34 青州馬：偽裝為馬商接觸馬政司、進展正常。
#21 徐州布：徐州布商市場了解，無明顯訊號（需要更深入查）。
#38 三州鹽：冀州鹽初步無弊端，下週轉青州鹽。
```

四份簡報擺在一起，蕭決看到了**單探子看不到的東西**：

```
#12 提到「**漕運私售**」 ── 涉及運鹽船。
#38 「**冀州鹽初步無弊端**」── 但他是看「**鹽量**」沒看「**運輸**」。
```

#12 和 #38 **看到同一批船的不同面**。

蕭決寫信給兩個探子：

```
#12，下週繼續查冀州糧。但注意：你看到的「**漕運私售船**」可能也載鹽。
記下船號和船主，傳給 #38。

#38，#12 那邊有冀州漕運船的資訊。
你別自己再從頭查冀州鹽運輸，**直接用 #12 的線索**。
```

兩個探子的工作之間**用蕭決當中介**。

#12 給 #38 資訊（船號清單），#38 比對自己的鹽運紀錄 ── 比 #38 自己從頭跑快五倍。

---

第一百天，**第二輪整合**。

蕭決收到四份新簡報，做了整理：

```
東陲三州統計表（截至本週）

冀州：
  糧 #12 → 三筆漕運私售證據（已蒐集）
  鹽 #38 → 冀州無弊端（已確認）
  布 → 待派
  馬 → 待派

青州：
  馬 #34 → 兩筆馬政「**虛報壯馬實際弱馬**」證據（已蒐集）
  糧 → 待派
  鹽 #38 → 下週開始
  布 → 待派

徐州：
  布 #21 → 仍在初查，下週需轉換方向
  糧 → 待派
  馬 → 無 (跳過)
  鹽 #38 → 第三週開始
```

蕭決計畫：

```
第二批派出（第十週開始）：
  冀州馬 → 探子 #5（馬政經驗）
  青州糧 → 探子 #17（曾被搶、現已重訓）
  徐州糧 → 探子 #41
  冀州布 → 探子 #29
  青州布 → 探子 #45（同時跑徐州布的協助）
```

並行 + 序列 + 動態調整。

蕭決把整個東陲調查當作**一張大圖**，每個探子是大圖的一片。**他必須隨時看見哪一片完成、哪一片落後、哪一片可以重分配**。

---

第二百天，東陲三州調查**七成完成**。

剩下的：徐州布、徐州糧、和 #21 換方向後的徐州布。

那天嚴司丞下到圓桌：

「⋯⋯**蕭決**。」嚴司丞說，「**過去十年雲書司沒辦法接朝廷大內這種「**大任務**」**。**每次接了都做不完**。」

「⋯⋯」

「**做不完不是探子不行**。」嚴司丞說，「**是沒有人把「**整個任務分給每個探子**」做得好**。**每個探子跑 ReAct 不夠**。**主事者要規劃**。」

蕭決點頭。

「⋯⋯**這就是「**謀篇**」**。」蕭決說，「**單個探子用「**推步**」 ── 一步走一步**。**任務本身大到單個探子做不完 ── 主事者用「**謀篇**」 ── 把任務拆成可並行的子任務**。**」

嚴司丞看著他。

「⋯⋯**蕭決**。」嚴司丞說，「**你前世做的東西，這個世界以前真的沒做過嗎**？」

蕭決笑了一下。

「**做過**。」他說，「**只是沒寫下來**。」

---

第二百四十天，東陲三州調查**完成**。

蕭決把 11 份子報告整合成一份**主報告**呈給朝廷大內。

報告含：

```
- 11 條重大弊端（責任人 + 證據 + 金額）
- 12 條次要問題
- 跨州模式分析（馮崇式串供模式在三州中發現 4 次）
- 處置建議（哪些當下處理、哪些深查、哪些立法）
```

朝廷大內讀完之後 ── **賞了蕭決和雲書司白銀千兩、御賜「**輿圖鏡心**」匾額**。

匾額掛在圓桌正上方。

---

那晚蕭決在《探子手冊》第五章末尾寫：

> **謀篇 = 把「**單一探子做不完的大任務**」**，**拆成「**多個小任務**」**。

> 拆完之後**並行能並行的**、**序列必須序列的**、**動態調整**。

> 一個大任務 = 一個 plan。
> Plan 上的每個節點 = 一個小 agent 跑 ReAct。
> 主事者（meta-agent / orchestrator）負責拆任務、分配資源、整合結果。

> **大任務絕對不要交給一個探子做 ReAct**。

> 18 輪推步可以、180 輪推步必崩。

下一章他要處理：**東陲三州調查 240 天**。蕭決自己是 meta-agent ── **他怎麼記得每個探子做到哪、過去 240 天哪個探子說過什麼**？

那是 **記事**。

## 雜役筆記

*蕭決《探子手冊》第五章 ──「謀篇」。*

**▍Planning（規劃）**

把「**單一 ReAct loop 做不完的大任務**」拆成小任務的能力。

**▍Task Decomposition（任務拆解）**

拆任務的常見方法：

1. **By Dimension**：按地點、時間、客戶、產品⋯⋯分維度
2. **By Phase**：按時間階段（先 → 中 → 後）
3. **By Sub-goal**：拆出邏輯上的子目標
4. **By Skill**：按需要的能力（research + writing + verification）

蕭決對東陲調查用的是 **By Dimension**（地點 × 項目）。

**▍Plan-and-Execute Pattern**

兩階段：

```
Phase 1：Planning
  LLM 看完任務後輸出一份「**計畫**」（任務樹）。
  人類審查、確認。

Phase 2：Execution
  按計畫的每個節點分別執行（可能用 ReAct）。
  整合各節點結果。
```

對比 ReAct：

| 模式 | 特色 |
|---|---|
| ReAct | 邊想邊做、彈性、適合不確定 |
| Plan-and-Execute | 先規劃整個 plan、適合步驟可預測、可審查 |
| ReWOO | Plan 之後執行時不再呼叫 LLM 規劃，節省成本 |

**▍ReWOO**（Reasoning WithOut Observation）

論文：Xu et al., 2023。

ReAct 的優化版。預先生成整個 plan（一系列 actions），執行時不再回到 LLM 推理 ── 直接照 plan 跑、最後一次性綜合。

優點：**便宜**（LLM 呼叫從 N 次降到 2 次）、**快**（並行執行）。
缺點：plan 一旦錯了沒辦法中途修。

**▍Hierarchical Agent（分層 Agent）**

蕭決自己 = top-level orchestrator。
每個探子 = sub-agent。

```
Orchestrator Agent（高層）
  ├── Sub-agent A（負責任務 1）
  ├── Sub-agent B（負責任務 2）
  ├── Sub-agent C（負責任務 3）
  └── Coordinator function（整合結果）
```

每個 sub-agent 都跑自己的 ReAct loop。Orchestrator 負責**分配、監控、整合**。

**▍實務的 Plan 應該包含什麼**

```yaml
plan:
  goal: "完成東陲三州調查"
  deadline: "8 個月"
  
  tasks:
    - id: T1
      goal: "查冀州糧"
      assigned_to: agent_12
      depends_on: []
      timeout: 60 days
      output: "證據清單"
      
    - id: T2
      goal: "查冀州鹽"
      assigned_to: agent_38
      depends_on: [T1.船號清單]   # T1 完成後拿到船號清單給 T2
      timeout: 45 days
      
    ...
  
  integration:
    after: [T1, T2, ..., T11]
    by: shaq_jue
    output: "主報告"
```

**▍Common Planning Failure Modes**

1. **Over-decomposition**：拆太細、N 個小任務、整合成本爆。
2. **Under-decomposition**：拆太粗、子任務還是太大、單一 agent 完不成。
3. **Wrong Dependencies**：拆出來的任務之間依賴關係沒設清楚、互相卡。
4. **No Re-planning**：計畫一定、堅持到底、即使現場發現完全不對也不改。
5. **Plan Drift**：每個小任務都「**稍微偏一點**」、加起來偏離原目標。

**▍Re-planning（重新規劃）**

蕭決第 100 天「重新平衡資源」就是 re-planning。

agent 應該**定期審視「**現在的計畫還對嗎**」**：

- 中途獲得新資訊？
- 某個子任務失敗了？
- 期限快到了但進度慢？
- 發現原計畫缺一條重要的路？

→ **修改 plan**。不要硬撐原計畫。

**▍實作框架**

- **LangGraph**：把 plan 畫成 DAG，每個節點是一個 sub-agent
- **LlamaIndex Workflow**：類似但偏 RAG 場景
- **CrewAI**：multi-agent 的 plan-and-execute
- **AutoGen**：微軟 multi-agent 框架
- **Anthropic Subagents (Claude Code)**：spawn 子 agent 跑子任務、結果整合回主 agent

**▍最重要的一句**

> 一個 agent 跑 ReAct 處理「**單一目標、< 20 步**」**的任務**。

> 多 agent + 規劃處理「**複合目標、跨領域、需要協作**」的任務**。

> 不要硬把後者塞進前者裡。

## 這一章你只要記得這三件事

1. **大任務絕對不要單一 agent 跑 ReAct 解。** 18 輪可以、180 輪必崩。
2. **拆任務的四個維度：dimension / phase / sub-goal / skill。** 拆完並行能並行的、序列必須序列的。
3. **Plan 要能 re-plan。** 中途發現原計畫錯了、改它，不要硬撐。
