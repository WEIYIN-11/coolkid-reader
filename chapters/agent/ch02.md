# 第 2 章　立志

> *練氣後期・第二重「立志」*

第七天。

尹知行把 38 號探子從江南帶回的所有紀錄翻了三遍。

紀錄不多。竹簡裡只有兩條：

```
[第 1 個月] 抵達江南。已落腳。
[第 3 個月] 鹽務有問題。回司覆命。
```

兩條。三個月。

尹知行派人把 38 號叫到圓桌前。

38 號是個三十多歲的瘦男人。眼神還算清明。

「**38 號**。」尹知行說，「**你的任務當時是什麼**？」

「⋯⋯**查鹽務有無弊端**。」

「**有沒有弊端，怎樣才算「有」**？」

38 號愣了一下。

「⋯⋯**就⋯⋯**有人作弊？**」

「**多少人才算「有」**？**一個人作弊算，還是十個人才算**？」

「⋯⋯」

「**「弊端」是什麼**？**價格作弊算，還是只有「**官員收賄**」算**？」

「⋯⋯**我覺得都算**。」

「**那為什麼回來只說「有」**？**江南鹽務「有」**作弊的人 ── 你查到誰？多少人？金額？」**

38 號沉默。

「⋯⋯**因為一進江南，到處都「**有**」**。」38 號終於說，「**我不知道該從哪一條開始查、查到什麼程度算夠。所以查了一個月，我就不知道該不該繼續、該不該回來、該不該寫些什麼**。」

尹知行閉上眼。

「**所以你三個月，全部時間在「**等**」**。」尹知行說，「**等我們發下一張令告訴你「**該查什麼**」**。**沒等到，就只好回來**。」

「⋯⋯**是**。」

---

尹知行那晚翻過去十年雲書司派出去的所有「**任務令**」。

九成的任務令長這樣：

```
任務令 #38：
  地點：江南
  事項：查鹽務有無弊端
  期限：三個月
```

只有「**地點、事項、期限**」。

沒有「**怎樣算成功**」。
沒有「**最小該帶什麼回來**」。
沒有「**遇到什麼情況可以停**」。

每個探子接到這種令，**自己解讀**。**解得對的成功、解得錯的失敗、解得模糊的像 38 號 ── 三個月等令**。

---

尹知行那天在圓桌邊的牆上貼第二張紙條：

> **「立志」是探子的命**。

> **不寫清楚成功條件 = 不寫清楚任務**。

下面三條子規則：

```
一、任務令要寫「目標」（goal）：要達成什麼結果。
二、任務令要寫「完成條件」（done definition）：怎樣算完成。
三、任務令要寫「停損條件」（abort conditions）：遇到什麼情況可以中止。
```

---

第十天，尹知行開始重寫任務令。

他先改 38 號的舊任務令當範本：

```
任務令 #38（v2）

目標：查清江南鹽務的弊端，回司提供具體證據和處置建議。

完成條件（任一達成即可回司覆命）：
  A. 拿回三條以上「**官員收賄**」的具體證據（姓名 + 金額 + 時間）
  B. 拿回五條以上「**鹽商作弊**」的具體紀錄（商號 + 手法 + 影響範圍）
  C. 若兩者皆無，回司報告「江南鹽務經查無明顯弊端」並列出查證過程。

停損條件（遇到立刻回司）：
  - 任務被人識破，可能危及人身
  - 兩個月內無任何頭緒
  - 江南有重大變故（朝廷已知曉的事件，無需再查）
  - 收到上級重新指令

每七日寫一份簡報回司：本週做了什麼、查到什麼、卡在哪、下一步打算做什麼。
```

四段。

「目標」、「完成條件」、「停損條件」、「定期回報」。

---

第十一天，尹知行把 38 號重新派出去。

這次他帶的是 v2 版任務令。

「**38 號**。」尹知行說，「**這次你照這張令做**。**每七日寫一份簡報。我這邊回信給你下一步指示**。」

「⋯⋯**司丞**。**萬一我兩個月內查不到任何證據呢**？」

「**停損條件第二條**。」尹知行說，「**回司報告「**兩個月查證過程**」**。**這也算完成**。」

「⋯⋯**所以「**查不到**」也算成功**？」

「**對**。」尹知行說，「**「**查不到並交回查證過程**」 ≠ 「**什麼都沒帶回來**」**。**前者是完成任務、後者是失職**。」

38 號點頭。

走的時候，他比上次走的時候，**腳步重一點**。但**頭抬高一點**。

尹知行知道差別在哪 ── **他這次知道自己「**能成功**」**。

---

第十五天，38 號的第一份簡報回來：

```
[週 1 簡報]
本週進度：
  - 已抵達江南、落腳鹽商街
  - 接觸三家中型鹽商、初步了解市場價格
  - 觀察到「**官鹽價**」與「**私鹽價**」差距約 30%（正常範圍）

未進展：
  - 未接觸官員（風險高，需更多偽裝）

下週計畫：
  - 偽裝為外地鹽商，接觸鹽運使衙門書吏
  - 從「**運鹽公文**」中尋找異常數量
```

尹知行看完，回信：

```
方向對。第二週繼續。
注意：偽裝為外地鹽商需要假身分證件。司裡為你準備。
另：「**運鹽公文**」找異常數量是好方法，但別只看數字。看「**異常的合法掩護**」。
```

第二十二天，第二份簡報：

```
[週 2 簡報]
本週進度：
  - 假身分通過、進入運鹽使衙門
  - 翻閱過去六個月的運鹽公文
  - 發現「**北港運出 → 南港抵達**」之間，三個月內共有七筆「**運量不符**」

具體：
  - #142 公文：北港運出 8 千石、南港抵達 6 千石（差 2 千石）
  - #156 公文：北港運出 5 千石、南港抵達 3 千石
  - ⋯⋯ 共七筆

下週計畫：
  - 追查「**消失的鹽**」去向
  - 確認是運輸損耗（合法）還是中途私售（弊端）
```

尹知行回信：

```
七筆異常 = 高訊號。
追查「去向」之前，先查「**這七筆公文簽核者是誰**」、「**運鹽船主是誰**」。
通常弊端不是運輸過程出事，是「**簽核**」和「**起運**」兩端內外勾結。
```

---

第二十九天，第三份簡報：

```
[週 3 簡報]
本週進度：
  - 確認七筆異常公文，**全部由同一人簽核**：運鹽副使「**趙懷古**」
  - 起運鹽船主有四人，其中三人都是「**德泰運鹽行**」名下
  - 德泰運鹽行掌櫃「**孫永福**」與趙懷古有姻親關係

證據：
  - 公文簽核筆跡比對：七筆全為趙懷古親筆
  - 公文簽核日期都是月底（避開週中嚴查）
  - 德泰運鹽行帳本上有「**入孫府宴客**」每月一筆，金額遠超合理範圍

完成條件 A 進度：3 條（達標）

下週計畫：回司覆命。
```

尹知行看完，笑了一下。

第二十九天，**完成條件 A 達標**。

如果按舊任務令，38 號可能還在江南東張西望、不知道該不該回。

按 v2 任務令，**他自己知道「**夠了，可以回**」**。

---

第三十一天，38 號回到雲書司。

帶回完整證據卷。

尹知行把卷宗呈給嚴司丞。

嚴司丞翻了大概兩個時辰。

「⋯⋯**這份卷宗**。」嚴司丞說，「**比過去三年的同類任務加起來都完整**。」

「⋯⋯」

「**38 號當初我打了。**」嚴司丞說，「**我以為他笨。**現在看，**不是他笨，是我們沒告訴他「**怎樣算完成**」**。**」

尹知行點頭。

「⋯⋯**還有件事**。」嚴司丞說，「**朝廷昨天送來一張新任務 ── 西關的軍糧運送有問題，要派人去查**。**這次任務令，**你寫**。**」

尹知行接過。

他翻開《探子手冊》第二章。

封面寫下兩個字：

**立志**

---

第三十五天，尹知行寫的西關任務令長這樣：

```
任務令 #93

目標：查清西關軍糧運送過程中「**運量不符**」的真實原因，提供具體責任歸屬。

完成條件（任一即可）：
  A. 拿回三條以上「**虛報運量**」的具體證據（簽核者 + 涉及糧倉 + 金額）
  B. 拿回證據顯示「**運量不符**」純屬「**運輸損耗**」（並能解釋為何近期損耗異常）
  C. 兩個月內無頭緒 → 回司報告查證過程

停損條件：
  - 任務被識破，風險升高
  - 西關有戰事爆發 → 立刻撤離
  - 朝廷重新指示

每七日簡報。
```

四段。跟 38 號 v2 版同樣結構。

派出去的探子叫 #93。他接過任務令的那天，**問了一個問題**：

「**司丞**。**完成條件 A 提到「**虛報運量**」**。**這個「**虛報**」**有沒有具體定義 ── 比方說，差幾石以上算虛報？**」

尹知行愣了一下。

「⋯⋯**好問題**。」他說，「**差 5% 以上算虛報。差 5% 以下視為合理損耗**。」

尹知行在任務令上加了一行。

#93 點頭走了。

尹知行坐回桌前，貼第三張紙條：

> **任務寫得越具體，探子問的問題越多**。

> **這是好事**。**問題在「**接令時**」問出來、總比在「**已經走到一半**」才發現好**。

---

第四十天，嚴司丞下到圓桌。

「**尹知行**。」嚴司丞說，「**我每週看你給探子寫的任務令**。」

「⋯⋯」

「**你寫的每張任務令最後一段都是「**每七日簡報**」**。**你想看每個探子每週的進度**？**」

「**是**。」

「**為什麼**？」

尹知行想了一下。

「**因為「**派出去看不到**」是雲書司過去十年最大的問題**。」尹知行說，「**探子在外面跑，回來才知道結果 ── 三個月後**。**三個月可以發生很多事。**他可能走偏了、可能被收買了、可能在三十天前就遇到瓶頸但沒回報**。**每週簡報 = 我每週能介入、能修正方向、能補資源**。**」

「⋯⋯」

「**朝廷對外不也是這樣**？」尹知行說，「**戰場上將軍每月送奏摺**。**月內若有大事，急報**。**雲書司沒道理不這樣**。」

嚴司丞點頭。

「**從下個月起**。」嚴司丞說，「**所有探子每七日簡報。我自己每月看一次。**這套規矩你定**。**」

尹知行行禮。

---

那晚尹知行在《探子手冊》第二章末尾寫：

> **任務令的本質：**

> **告訴探子「**我要什麼**」**、**「**怎樣算夠**」**、**「**什麼時候可以停**」**、**「**多久要回報**」**。

> 模糊任務 = 探子瞎走。
> 沒回報節奏 = 走偏了沒人知道。

> 寫得對的任務令，**比派最厲害的探子重要**。

下一章他要解決：**探子有了好的任務令，但他在江南要查鹽商、要看公文、要假身分、要訪人**。**這些「**做什麼**」的能力，需要被準備好**。**這是「**持械**」**。



---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **練氣後期・第二重「立志」**。

## 雜役筆記

*尹知行《探子手冊》第二章前三張紙條。*

**▍System Prompt（系統提示）**

Agent 的「**身分、任務、規則**」的固定指令。每次對話自動帶上、模型優先遵守。

尹知行寫給探子的「**任務令**」就是 system prompt。

**▍System Prompt 的四件套**

```
1. Role / Identity（你是誰）
2. Goal / Objective（你要達成什麼）
3. Constraints / Rules（什麼不能做、什麼必須做）
4. Output Format（怎麼回應、多久回報一次）
```

**▍Goal Specificity（目標明確性）**

尹知行踩過的坑：「**查鹽務有無弊端**」太模糊。

模糊目標 → agent 自行解讀 → 解讀對的成功、解讀錯的失敗 → **不可預測**。

明確目標的標準（SMART 改寫版）：

- **S**pecific：具體說要做什麼，不要抽象動詞
- **M**easurable：可量化（5% 以上算虛報）
- **A**chievable：可達成
- **R**elevant：跟總目標相關
- **T**ime-bound：有時限

**▍Definition of Done（完成條件 / DoD）**

尹知行的「**完成條件**」。

**「**Agent 必須有明確的「**怎樣算完成**」標準**」，否則：

- 太鬆 → 半成品也回報「完成」
- 太嚴 → 永遠跑不完

尹知行的設計：**多個 OR 條件**（A / B / C 任一達成即可）。**讓 agent 有出路**。

```
完成條件範例：
  A. 拿到三條以上具體證據 → 完成
  B. 拿到五條以上 lighter signal → 完成
  C. 兩個月確認無 signal → 完成（並報告過程）
```

**▍Abort Conditions（停損條件）**

尹知行的「**停損**」。

什麼情況 agent 應該**主動中止任務**：

- 風險超出可承受範圍
- 環境條件變了（戰事爆發）
- 上級重新指令
- 預算 / 時間用盡
- 達到 max iteration

「**沒有停損 = 永遠不會停**」。Agent 失控的常見原因。

**▍Progress Reporting（進度回報）**

尹知行的「**每七日簡報**」。

長時間任務的 agent 必須**定期主動回報**：

- 已做的事
- 已得到的結果
- 卡在哪
- 下一步打算

好處：
- 監督者能即時介入
- Agent 跑偏時能拉回來
- 失敗時能 debug
- 用量可控

實作上：
- **Checkpointing**：每跑 N 步存一次狀態
- **Streaming**：邊跑邊輸出 thought 給人看
- **Heartbeat**：定期回「我還活著」

**▍Output Format（輸出格式）**

尹知行的簡報格式（本週進度、未進展、下週計畫）。

讓 agent 用**固定格式回應**：

```json
{
  "summary": "本週進度摘要",
  "completed": ["..."],
  "blocked": ["..."],
  "next_actions": ["..."],
  "confidence": 0.75
}
```

好處：
- 下游程式好處理
- 一致性、可比較
- 結構化錯誤訊息

**▍Constitutional AI / Principles（憲法 / 原則）**

Anthropic 對 Claude 的訓練方式。給模型一套「**永遠遵守的原則**」，模型自己用這套原則檢查自己。

尹知行的「**停損條件**」就是憲法的一種：「**遇到 X 一律中止**」。

**▍實務工具**

寫 system prompt 的工具：

- *Anthropic Workbench*
- *OpenAI Playground*
- *Promptfoo*：版本控制 + A/B test prompt
- *Langfuse Prompt Management*

**永遠版本控制你的 system prompt**。改了哪一句、效果怎麼變、什麼時候 rollback ── 全部要追蹤。

## 這一章你只要記得這三件事

1. **System prompt 四件套：身分、目標、規則、輸出格式。** 缺一個 agent 就亂。
2. **目標要具體 + 完成條件要明確 + 停損條件要列出。** 「查有無弊端」這種模糊指令 = 等出事。
3. **長時間任務必須有定期回報。** Streaming、checkpointing、heartbeat 三選一以上。
