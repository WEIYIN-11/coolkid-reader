# 第 4 章　推步

第七十五天。

新派出去的探子 **#21** 帶著任務令和工具包出發。

他的任務：查清北州糧倉是否有「**虛報入庫**」。

第七天簡報回來：

```
[週 1 簡報]
本週進度：
  - 抵達北州。偽裝為外地糧商。
  - 接觸三家糧倉，初步詢問。
  
未進展：
  - 我不知道下一步該做什麼。

詳述：
  - 三家糧倉態度都很正常。
  - 都報的入庫量比我預期的高。
  - 我不知道「高」是真的有問題，還是我預期太低。
  - 我想用「**朝廷小吏腰牌**」進倉查實際量。
  - 但我擔心一進去就被發現是探子。
  - 我也想找線人。但我不知道哪個線人可信。

我卡住了。請司丞指示。
```

蕭決翻過去 #21 出來之前的訓練紀錄。

#21 是新探子。第一次出任務。

他的問題不是「**不夠聰明**」。

是 ── **他不知道「**遇到狀況該怎麼決定下一步**」**。

---

蕭決回覆 #21 的信很長：

```
#21，你卡住的原因是你沒有「**推步**」的方法。

我教你三段論：

第一段：觀察（看到什麼）
  寫下你現在「**看到的事實**」：
    - 三家糧倉報的入庫量比我預期高 30%
    - 三家糧倉態度都很正常
    - 我有腰牌但沒用、有線人線索但沒接

第二段：思考（這代表什麼 + 接下來該做什麼）
  從事實推論：
    - 入庫量比我預期高 ── 可能我預期偏低（無弊端）、可能他們真的虛報（有弊端）
    - 三家態度都正常 ── 兩個解釋：真的乾淨、或他們互相串供
    - 我需要驗證「我的預期是不是準的」、和「三家是不是互相串供」
  下一步動作（在工具裡選）：
    - 用「**朝廷小吏腰牌**」進其中一家糧倉、實地量取入庫量
    - 用「**比對筆跡**」工具看三家報表的書寫筆跡是否同源（如果同源 = 串供強訊號）

第三段：行動（做完看結果，回到第一段）
  做完之後寫下「**看到的新事實**」，重新跑一輪。

每一步都把「**看到 → 想了什麼 → 做什麼**」寫進你的小冊子。
下一步就會清楚。
```

蕭決飛鴿寄出。

---

第十四天，#21 第二份簡報：

```
[週 2 簡報]

第 8 天
  觀察：三家糧倉報表筆跡相比對。發現家 A 和家 C 的「**入庫量**」欄位筆跡相似，
        但「**簽核者**」筆跡不同。
  思考：A 和 C 入庫量可能由同一人代填，但簽核者各自簽。
        這是「**幕後同人代填**」的訊號。
  行動：去家 A 衙門索取「**入庫公文存底**」副本（用朝廷小吏腰牌）。

第 10 天
  觀察：家 A 存底中，入庫公文的「**草本**」有刪改痕跡。
        「**入庫量**」一格原本寫 8000 石，被劃掉、改成 12000 石。
  思考：「**改大**」入庫量 = 虛報的標準手法。
        劃掉的筆跡跟原寫的「8000」筆跡相同 → 同一人改的。
  行動：找改筆者是誰。看家 A 「**過手糧倉公文**」的吏目。

第 12 天
  觀察：家 A 過手糧倉公文的吏目叫「**馮崇**」。
        馮崇同時也是家 C 的「**糧倉副使**」（兼差）。
  思考：馮崇橫跨家 A 和家 C。兩家筆跡相似的「**入庫量**」欄位，可能都是他代填。
  行動：暗中蒐集馮崇近兩個月的進出帳，看他有沒有「**異常收入**」。

第 14 天
  觀察：馮崇近兩個月新置宅院、購馬車一輛。總值 280 兩。
        他的官俸是月薪 4 兩。
  思考：馮崇有「**超出俸祿範圍**」的支出。配合家 A、家 C 虛報行為，是收賄訊號。
  行動：繼續蒐集物證（買宅契約、賣方供詞）作為證據。

下週計畫：完成證據鏈、回司覆命。
```

蕭決看完，笑了一下。

#21 用了一週，把整套「**觀察 → 思考 → 行動 → 觀察新事實**」跑了四遍。

每一遍都比上一遍**更靠近答案**。

最後他**不需要司丞指示下一步**。他自己會推。

---

蕭決把這個方法叫「**推步**」。

第一步：**觀察**（observation）── 寫下「**看到了什麼事實**」
第二步：**思考**（thought）── 寫下「**這代表什麼 + 下一步該做什麼**」
第三步：**行動**（action）── 從工具裡選一個動作做
第四步：回到第一步（看新事實）

四步循環。直到任務完成。

---

第二十一天，#21 回到雲書司。

帶回完整證據鏈。

馮崇的供詞、宅院契約、糧倉副使收賄手法、家 A 家 C 的串供模式 ── 全部齊。

嚴司丞看了一個時辰。

「⋯⋯**這跟 38 號當初江南的案子一樣完整**。」嚴司丞說，「**但 #21 是新探子**。**第一次出任務**。」

「⋯⋯」

「**為什麼**？」嚴司丞問。

「**因為他學了「**推步**」**。」蕭決說，「**他不是「**等司丞發指示**」**。**他自己會「**從看到的事實推下一步**」**。**」

嚴司丞點頭。

「⋯⋯**這個方法**。」嚴司丞說，「**寫進手冊**。**所有探子訓練時必學**。**」

---

第二十六天，蕭決在《探子手冊》第四章開頭寫：

```
推步三段論

寫下：「我看到什麼 ── 這代表什麼 ── 我下一步做什麼。」
然後做。做完繼續寫下：「我看到什麼新事實⋯⋯」

重複直到任務完成。
```

但他也在第二章末加一條警告：

```
推步的陷阱

陷阱一：思考完了不行動 ── 永遠在「想」、無進展。
陷阱二：行動完了不觀察 ── 看不到結果、下一步亂猜。
陷阱三：觀察完了不思考 ── 直接做下一動作，沒推理連續性。

三個陷阱破任一就停滯。
```

---

第三十天，新派出去的探子 **#34** 卡了。

#34 派去查中州茶葉走私。

第二週簡報：

```
觀察：三家茶莊正常進貨、無異常。
思考：可能不是這三家。
行動：再查另外三家。
觀察：那三家也正常。
思考：可能不是茶莊端，是運輸端。
行動：查運輸隊。
觀察：運輸隊正常。
思考：可能不是運輸端，是港口端。
行動：查港口⋯⋯

連續八天，每天「**換一個方向查**」，沒拿到任何證據。我不知道下一步該往哪。
```

蕭決皺眉。

#34 用了**推步**，但**他每一步都在換方向**。

每次「**思考**」都跳到一個新假設，**沒有真正深入任何一條線**。

蕭決回信：

```
#34，你的推步有個問題：你跳得太快。

每換一個假設、你只試了一天就放棄。
但「**沒看到弊端**」≠「**沒有弊端**」。
可能是你查的方法不對。

修正：
  - 對任何一條假設，至少給它三輪「**觀察 → 思考 → 行動**」。
  - 如果三輪都沒進展，再換假設。
  - 換假設之前，明確寫「**為什麼我認定這條假設不對**」。

不要每天換方向。每個方向給它足夠的深度。
```

#34 改了方法。

下一週他**集中在「**運輸端**」**，跑了五輪推步。

最後抓到「**茶葉運輸隊中，三車一綑出貨記成兩車**」的舞弊。

---

第四十天，蕭決在第四章補一條：

```
推步的深度

每個假設、至少跑三輪「**觀察 → 思考 → 行動**」**才換。
換假設前明確寫「為什麼這條死了」。

「**亂跳**」是探子最常見的死法 ── 看似在做事，其實沒進展。
```

---

第四十五天，嚴司丞下到圓桌。

「**蕭決**。」嚴司丞說，「**最近七個探子，五個用推步順利完成任務。兩個還在路上**。」

「⋯⋯」

「**完成率從過去的 30% 到 70%**。」嚴司丞說，「**這是雲書司十年來最好的數字**。」

蕭決點頭。

「**但有件事**。」嚴司丞說，「**過去七個探子，平均回司之前**，**簡報裡的「**推步紀錄**」**有 18 輪**。」

「⋯⋯」

「**18 輪 = 18 個「**觀察 → 思考 → 行動**」**。**這在你的設計裡 ── 每個探子腦袋裡要記得「**前 17 輪做過什麼**」**才能繼續推**。**」

嚴司丞看著蕭決。

「**這是「**記事**」的問題**。」嚴司丞說，「**探子在現場走了一個月，他記得住自己過去 30 天每一步嗎**？」

蕭決閉上眼。

「⋯⋯**記不住**。」蕭決說，「**他需要寫下來**。**而且每一輪都得能查回前面**。**這就是下一章**。**」

「**什麼下一章**？」

「**記事**。」蕭決說，「**Memory**。」

「⋯⋯**Memory 是什麼意思**？」

「**我的世界的話**。」蕭決說，「**意思是：**探子腦袋以外、需要留存的所有東西**。**」

---

那晚，蕭決在《探子手冊》第四章末尾寫：

> **推步是 agent 的「**走法**」**。

> **觀察 → 思考 → 行動 → 看新觀察**。

> 每一輪寫下這三件事。
> 走偏了能拉回、停滯了能換假設、完成了能交代。

> **不能寫的探子，走不了 18 輪**。
> **能寫的探子，走 100 輪也不亂**。

下一章要解決：**寫在哪、寫多少、什麼留下、什麼忘掉**。

## 雜役筆記

*蕭決《探子手冊》第四章的核心三段論。*

**▍ReAct**（Reasoning + Acting，思辨 + 行動）

蕭決的「**推步**」。Agent 設計最經典的循環模式。

論文：Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models"（2022）。

```
Thought（想）：我現在知道什麼？需要什麼？下一步該做什麼？
Action（做）：呼叫一個工具
Observation（看）：拿到工具回傳的結果
↓ 回到 Thought
```

無限循環，直到 Thought 變成「**我已經有答案了**」。

**▍為什麼 ReAct 強**

對比兩個替代方案：

- **直接生成答案**（沒 ReAct）：模型只能用「**訓練時的知識**」，無法觸及最新資訊。
- **只工具呼叫沒推理**：模型瞎呼叫工具，看到結果不知道怎麼接。

ReAct 把「**想**」和「**做**」交織 ── 想完做、做完看、看完再想。**每一步推進都被記下來、模型能看著前面繼續推**。

**▍ReAct 的標準輸出格式**

```
Thought: 我需要查 X 的歷史資料。

Action: search_archive(query="X 過去三年", max_results=20)

Observation: [回傳 20 筆紀錄]

Thought: 從這 20 筆裡，第 3、第 7、第 12 筆涉及 X 與 Y 的關係。
        但我需要更明確的時間區段。

Action: search_archive(query="X 與 Y 2025-2026", max_results=10)

Observation: [回傳 10 筆]

Thought: 找到了。Y 在 2025 年 11 月接手 X，這就是我要的。
        準備生成最終答案。

FinalAnswer: ⋯⋯
```

**▍ReAct 的常見問題**

1. **Thought 不更新**：模型每輪重複同樣的想法。
2. **Action 重複**：同樣的工具呼叫一直發。
3. **Observation 不消化**：模型沒「**讀懂**」結果。
4. **沒有 Final Answer**：永遠跑不完。
5. **太快下結論**：第二輪就 FinalAnswer，結果是錯的。

**▍對策**

```
- Max iterations（最大循環數，常設 5-15）
- Early stopping（如果連續兩輪 thought 一樣 → 中止）
- Cycle detection（同樣 action 重複 3 次 → 中止）
- Self-consistency（同個任務跑 3 次、結果不同 → 不確定）
```

**▍ReAct vs Plan-and-Execute**

兩種主流 agent 模式：

| 模式 | 描述 | 適合 |
|---|---|---|
| **ReAct** | 邊想邊做、每一步動態決定 | 探索性、不確定性高 |
| **Plan-and-Execute** | 先規劃整個 plan、再執行每步 | 步驟可預測、步數多 |

蕭決的 #21 用 ReAct。下一章 #34 跳太快、改成「**先想好幾條假設、深入查一條**」── 帶有 Plan-and-Execute 的味道。

**▍Reasoning Models（推理模型）**

OpenAI o1、o3、DeepSeek R1、Claude with extended thinking。

特色：**模型自己會「**長時間思考**」**，不需要你寫 ReAct prompt。

```
傳統 LLM：
  Q: 1234 × 5678 = ?
  A: 7,006,652（猜）

Reasoning Model：
  Q: 1234 × 5678 = ?
  [Internal thinking: 1234 × 5000 = 6,170,000；1234 × 600 = 740,400；1234 × 78 = 96,252；加總 = 7,006,652]
  A: 7,006,652
```

**Reasoning models 取代 ReAct 嗎**？──**部分**。對單次推理是的。對「**需要呼叫多個工具**」**仍需要 agent 框架包**。

**▍實務工具**

- *LangChain AgentExecutor*：包好的 ReAct loop
- *LlamaIndex Agent*：類似但更精煉
- *Anthropic Tool Use API*：原生 tool calling
- *DSPy ReAct*：可優化版

**▍最重要的一句**

> **Agent 不只是「**會想**」**，**是「**想了會做、做了會看、看了再想**」**。

> 缺任何一段都不是 agent 是 chatbot。

## 這一章你只要記得這三件事

1. **ReAct 三段論：Observation → Thought → Action → 回到 Observation。** 每一輪都把這三段寫下來。
2. **不要亂跳假設。** 每條假設至少跑 3 輪推步、不行再換、換之前明確記「為什麼這條死了」。
3. **設 max iterations、cycle detection、early stopping。** 沒這三個 agent 會無限跑。

下一章：探子推 18 輪、跨 30 天、現場記不住前面做過什麼。Memory 登場。
