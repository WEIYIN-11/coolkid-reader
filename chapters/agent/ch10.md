# 第 10 章　試煉

> *練氣後期・第十重「試煉」*

第四百一十天，朝廷大內派了一個監察使下到雲書司。

監察使姓**冷**，是個極瘦極挺的中年人。

「**司丞**。」冷監察說，「**過去一年雲書司很風光**。**東陲三州、十州糧倉、南關兵馬司、十三件大案**。**朝廷想知道 ── 你們是真的「**比過去強**」，**還是「**運氣好**」？**」

尹知行停下筆。

「⋯⋯**監察使，**這怎麼判斷**？**」

「**我有辦法**。」冷監察說，「**我手裡有兩份東西**。」

他拿出兩張紙。

第一張：**過去十年雲書司處理過的 500 件已結案調查、含當時的結論**。
第二張：**那 500 件後來實際發生的「**真相**」 ── 哪些原本結論對、哪些錯**。

「**這 500 件你之前沒看過**。」冷監察說，「**我從各州地方志、後續處置紀錄、相關官員的後續傳記裡比對出來**。**朝廷藏了五年才整理好**。」

尹知行盯著兩張紙。

500 件，**每件都有「**真相**」**。

「**監察使**，**你的意思是**？**」

「**我給你 500 件的「**任務令**」**。**你的雲書司，**用新方法重跑這 500 件**。**結論跟「**真相**」**比 ── 對的多少、錯的多少**。**過去十年用舊方法做的結論也跟真相比**。**兩邊的對錯比 ── 就是「**你們有沒有變強**」**的答案**。」

尹知行明白了。

冷監察給他的，是 ── **黃金測試集**（gold standard test set）。

---

尹知行那天晚上看冷監察留下的 500 件。

```
案件範例：
[編號 #2018-103]
任務：江東漕運是否有弊端？
舊雲書司結論：無明顯弊端。
實際真相（五年後揭發）：漕運司司丞「**周謙**」貪污 12,000 兩、串通漕船主走私。
舊結論對錯：錯。

[編號 #2019-067]
任務：北州糧倉短缺真相？
舊雲書司結論：糧倉副使虛報入庫量。
實際真相：糧倉副使作弊、後被處置。
舊結論對錯：對。

[編號 #2020-211]
任務：京畿銀號是否安全？
舊雲書司結論：銀號商會不穩定、建議朝廷介入。
實際真相：銀號商會正常、雲書司過度反應。
舊結論對錯：錯。
```

500 件。

尹知行開始算過去十年的成績。

```
舊雲書司過去十年的對錯比：

對：187 件 (37%)
錯（false positive 抓無罪當有罪）：156 件 (31%)
錯（false negative 放過真罪）：98 件 (20%)
無結論（任務失敗、沒結論可比）：59 件 (12%)

整體準確率：37%
```

37%。

也就是說 ── **雲書司過去十年，只有不到四成的結論是對的**。

尹知行看完，閉上眼。

---

尹知行那天分派任務。

不能讓「**現在的探子**」**直接跑這 500 件 ── 他們會被「**自己用新方法的成見**」**汙染**。

他做了三件事：

**第一**，把 500 件分成兩半。

```
A 組 250 件：用作「**訓練 / 校準**」 ── 探子可以看真相、調整方法。
B 組 250 件：用作「**測試 / 評估**」 ── 探子不看真相、跑完才對比。
```

A 組可看 = 「**training set**」。
B 組不可看 = 「**held-out test set**」。

**第二**，定義「**對**」的標準。

不是「**結論跟真相百分之百符合**」 ── 那太嚴。

```
分四級：
  Level 1 完全對：結論的主犯名、金額、手法都對
  Level 2 大致對：主犯名對、金額誤差 < 30%、手法對
  Level 3 部分對：找到弊端但細節有誤
  Level 4 不對：結論方向錯（誤判無罪 / 誤判有罪）
```

「**Level 1 + 2 = 對**」 ── 業務有用。
「**Level 3**」 ── 不算錯但需要補強。
「**Level 4**」 ── 算錯。

**第三**，選 5 個有經驗的探子、用新方法跑 B 組 250 件。

每個探子分 50 件、用 90 天跑完。

---

第五百天，B 組 250 件全部跑完。

尹知行算成績：

```
新雲書司在 B 組 250 件的成績：

Level 1（完全對）：96 件
Level 2（大致對）：78 件
Level 3（部分對）：42 件
Level 4（錯）：21 件
無結論：13 件

「對」率（L1+L2）：(96+78) / 250 = 70%
「無錯誤結論」率：(96+78+42) / 250 = 86%
```

70%。

比舊的 37% 提升了**約一倍**。

尹知行拿著這份報告呈給冷監察。

冷監察看了很久。

「⋯⋯**70%**。」冷監察說，「**你們現在的對錯比、是舊雲書司的兩倍**。」

「⋯⋯」

「**但是**。」冷監察說，「**70% 還是不夠**。**朝廷需要的是 90% 以上**。」

「⋯⋯」

「**剩下的 30% 錯在哪、你看出來了嗎**？」

尹知行點頭。

---

尹知行把 30% 的錯誤拆開分析：

```
Level 4「錯」的 21 件，原因分布：

A. 任務令模糊（探子誤解了目標）：5 件
B. 工具不足（探子沒有「**比對筆跡**」之類的工具）：3 件
C. 推步太快（沒給每條假設 3 輪深度）：4 件
D. 反向滲透類（探子被收買 / 被誤導）：3 件
E. 內省缺漏（沒做反向檢核）：2 件
F. Memory 漏記（重要證據忘了寫進案卷）：1 件
G. 跨州協作失敗（兩個探子沒對齊）：3 件
```

**每一條對應之前章節的某個機制**。

```
A → 第二章「**立志**」沒做好
B → 第三章「**持械**」**缺工具
C → 第四章「**推步**」**過淺
D → 第九章「**圈籠**」**漏洞
E → 第七章「**內省**」**沒做
F → 第六章「**記事**」**疏失
G → 第八章「**群行**」**問題
```

每一條都可以針對性改進。

---

尹知行寫了一份「**錯誤分布報告**」：

```
雲書司「**B 組 30% 錯誤**」**改進建議**

短期（一個月內）：
  - 任務令制式表（A：5 件 → 預計降 60%）
  - 推步深度規定（C：4 件 → 預計降 75%）
  - 內省檢核必做（E：2 件 → 預計降 100%）

中期（三個月）：
  - 新工具開發：跨州資訊整合（G：3 件）
  - 圈籠暗號表頻率加倍（D：3 件 → 預計降 80%）

長期（一年）：
  - 探子訓練流程重訂、case study 制度
  - 「**字跡使**」**正式編制**
```

尹知行呈給冷監察。

冷監察看完。

「⋯⋯**這個方法**。」冷監察說，「**從結果反推、找出每件「**為什麼錯**」、**對應改進方向 ── 比你過去那本「**心法錄**」**還準**。**」

「⋯⋯」

「**做下去**。」冷監察說，「**朝廷給你一年、把「**對**」率拉到 90%**。」

「**是**。」

---

第六百天，尹知行開始**第二輪試煉**。

從冷監察那邊借來另外 200 件案例（**第二批**）。

雲書司用改進後的方法跑這 200 件。

成績：

```
Level 1：92 件
Level 2：68 件
Level 3：28 件
Level 4：8 件
無結論：4 件

「對」率：80%
「無錯誤結論」率：94%
```

從 70% 拉到 80%。

剩下的 20% 尹知行又拆 ── 改進 ── 跑第三輪 ── 拉到 88%。

第四輪 ── 91%。

**第六輪 ── 95%**。

---

第七百天，冷監察最後一次來雲書司。

「⋯⋯**尹知行**。」他說，「**95%**。**朝廷史上沒有任何司門到過這個數字**。」

「⋯⋯」

「**而且你不只「**到 95%**」**。」冷監察說，「**你「**知道為什麼到 95%**」**、**也知道剩下 5% 錯在哪**。**這比達到 95% 本身更重要**。**」

尹知行點頭。

「**監察使**。」尹知行說，「**這套方法 ── 我希望朝廷其他司門也能用**。**不是「**達到 95%**」 ── 是「**用測試集系統評估自己**」這套方法本身**。」

冷監察微笑。

「⋯⋯**我會代你呈報朝廷**。**也許明年起、各司門年度評鑑都用這個方法**。」

說完轉身走。

---

那晚尹知行在《探子手冊》第十章末尾寫：

> **沒測過的系統 = 不能聲稱「**有用**」**。

> 「**感覺有用**」**和「**真的有用**」**隔了一個測試集**。

> 測試集要有「**已知答案**」**、**要有「**新方法不能事先看到**」**、**要有「**錯誤分類**」**、**要能追溯到「**這一條對應哪個機制**」**。

> 95% 不是終點。
> 「**知道剩下 5% 錯在哪**」**才是**。

下一章他要處理：雲書司現在強了。**但一旦規模放大 ── 不只 92 個探子、是 920 個 ── 怎麼撐？怎麼監控？怎麼控制成本**？**那是「**上場**」**。



---

那夜尹知行在牆前盤膝坐下、閉目。

這一張新貼的紙條化作微光、沉入丹田。

胸口熱了一下、又涼了一下。

自此尹知行修為 ── **練氣後期・第十重「試煉」**。

## 雜役筆記

*尹知行《探子手冊》第十章 ── 試煉。*

**▍Evaluation（評估）**

對 agent 系統做系統化測試。**沒測過 = 不能上線**。

**▍Golden Test Set（黃金測試集）**

冷監察給尹知行的 500 件。CRM 第 8 章和 RAG 第 8 章都講過、agent 場景更重要。

特徵：
1. **已知正確答案**：每筆都有 ground truth
2. **覆蓋多種場景**：不能全是同一類
3. **包含 edge case**：難題、罕見題、刁鑽題
4. **不對 agent 公開**：testing time 才看

**▍Train / Validation / Test Split（訓練 / 驗證 / 測試集）**

尹知行的「**A 組 250 件 + B 組 250 件**」**：

```
Training (60%)：開發時看、調整方法
Validation (20%)：跨輪比較用、選最佳設定
Test (20%)：上線前最終驗收、平常不看
```

「**Test 一旦用了、就要找新的 test**」。否則會「**過度擬合測試集**」**（agent 變成「**為了通過這個測試**」優化**、實際場景表現可能變差）**。

**▍Agent-specific Metrics（agent 專用指標）**

不只看「**最終答案對不對**」、還要看「**過程**」：

```
1. Success Rate（成功率）：最終任務完成的比例
2. Task Completion Steps（步數）：平均要幾輪 ReAct
3. Tool Selection Accuracy（工具選對率）
4. Tool Call Success Rate（工具呼叫成功率）
5. Hallucination Rate（幻覺率）：呼叫不存在工具或編造資料
6. Cost per Task（每任務成本）：token 數 + tool 呼叫費
7. Latency（延遲）：從接到任務到完成的時間
8. Safety Violations（安全違規數）
```

**▍Trajectory Analysis（軌跡分析）**

不只看最終答案、看 **agent 走的整條路**：

```
- 哪一步走錯？
- 走錯後有沒有自我糾正？
- 有沒有 looping / drifting / stuck？
- 重要決策點是不是合理？
```

工具：**LangSmith**、**Langfuse**、**Phoenix (Arize)**、**W&B Weave**。

**▍Public Agent Benchmarks（公開 agent 基準）**

業界用來比較 agent 強弱：

- **SWE-bench**：真實 GitHub issue、agent 寫 patch 修 bug
- **WebArena / VisualWebArena**：在模擬網頁上做任務
- **AgentBench**：多領域 agent 任務集
- **GAIA**：通用助理基準
- **MMLU / GPQA**：知識問答（不是純 agent、但 LLM 必過）
- **τ-bench**：tool use 與多輪對話

**▍A/B Testing（A/B 測試）**

線上比較兩個版本：

```
Group A：50% 流量、用舊方法
Group B：50% 流量、用新方法
跑兩週、比指標（success rate、cost、user satisfaction）
```

**做 agent 改動的標準動作**：永遠 A/B、不直接全切。

**▍Error Analysis（錯誤分析）**

尹知行把 21 件錯誤分成七類、對應七個改進方向。**這是 evaluation 最有價值的環節**。

```
不是「我們 70% 對」就完了。
是「30% 錯」的分布是什麼？
每一類錯能對應哪個機制？
改哪個機制能降多少？
```

**▍實作框架**

- **LangSmith**：LangChain 出品、全套 trace + eval
- **Langfuse**：開源、可自架
- **Phoenix (Arize)**：開源、視覺化好
- **W&B Weave**：跟 Weights & Biases 整合
- **Promptfoo**：CLI、本地測試、CI/CD 友善
- **DeepEval**：Python 套件、pytest-like

**▍Human Evaluation vs Automatic Evaluation**

| 方式 | 優缺 |
|---|---|
| **Automatic**：用 metric / LLM judge | 快、便宜、但可能有盲點 |
| **Human**：人工打分 | 準、但慢、貴、有偏差 |
| **LLM-as-Judge**：用另一個 LLM 評分 | 中間方案、但 judge 也可能有 bias |

**業界共識**：自動 + LLM judge 跑大量、**人工抽樣覆查 5-10%**。

**▍最重要的一句**

> 「**感覺有用**」**和「**測得有用**」**之間隔了一個 test set**。

> 沒測試集 = 你只是運氣好。
> 有測試集 = 你能改進、能保證、能跟人說「**我的 system 在這 N 件上有 X% 成功率**」**。

## 這一章你只要記得這三件事

1. **沒測過的 agent 不能聲稱「有用」。** 要有 golden test set、要有 train/test split。
2. **不只看「對不對」，看「為什麼錯」。** 錯誤分類能告訴你下一步改哪。
3. **Trajectory analysis：看 agent 走的整條路，不只看最終答案。** 哪步錯、有沒有自我糾正、有沒有 looping。
